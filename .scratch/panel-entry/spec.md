# 可配置的面板入口位置（顶部导航栏 / 底部魔法棒）

Status: ready-for-agent

## Problem Statement

插件入口目前固定在天花板顶部工具栏按钮（#top-settings-holder，spec 决策 11「顶部按钮 + 自绘浮层」的既有契约）。但两种表面各有真实取舍：顶部导航栏是现状契约、桌面鼠标顺手，但移动端远离拇指区，且在 TauriTavern 等宿主里顶部安全区（env() 恒 0）可能压住按钮——底部安全区已有「面板安全区」设置补偿，顶部无人处理；底部魔法棒菜单（#extensionsMenu，左下角魔法棒按钮呼出）贴近拇指区，但它是 ST 的「Extras 工具」语义，插件的入口塞进去属于 gallery 先例式的非常规通道，且魔法棒按钮本身的显隐由 ST 按可见子项数动态决定。用户要的是「可以调整」本身——把入口位置做成可配置能力，而不是替所有用户二选一。

## Solution

新增插件全局设置项「面板入口」：入口位置三选一（顶部导航栏 / 底部魔法棒 / 两者都显示），默认顶部导航栏（老用户升级零感知）。选择魔法棒或两者时，在 ST 魔法棒菜单里挂载一个「记忆面板」行条目（镜像内置工具行结构，随 ST 菜单原生样式）；魔法棒菜单未就绪时等待其挂载，始终不可用则回退顶部并如实显示实际位置。设置分组折叠态摘要显示当前选择，切换即时生效，无需重启。

## User Stories

1. 作为用户，我想在设置里选择面板入口位置（顶部导航栏 / 底部魔法棒 / 两者都显示），以便按设备习惯定制入口
2. 作为用户，我想默认入口保持在顶部导航栏，以便升级后行为与现状完全一致
3. 作为用户，我想选择魔法棒后，底部魔法棒菜单里出现「记忆面板」入口行，以便在拇指区一键呼出面板
4. 作为用户，我想「两者都显示」时顶部与魔法棒两个入口并存且状态同步（面板开合、高亮一致），以便双端都顺手
5. 作为用户，我想入口在面板展开时高亮（aria-pressed），以便随时知晓面板开合状态
6. 作为用户，我想切换入口位置后立即生效，以便无需重启
7. 作为用户，我想「面板入口」设置分组折叠态看到当前选择的摘要，以便不展开即可确认
8. 作为用户，我想魔法棒菜单不可用（ST 未挂载菜单容器等极端情况）时入口自动回退顶部导航栏，以便入口永不消失
9. 作为用户，我想回退发生时设置分组里显示「实际位置：顶部导航栏（魔法棒不可用）」，以便知晓真实生效位置
10. 作为用户，我想选择魔法棒或两者时魔法棒按钮正常亮出（即使本实例未连 Extras），以便入口可达

## Implementation Decisions

- **范围**：只改 apps/st-extension。不动 core/apps、不动 ST 本体。
- **设置项**：`PluginSettings` 新增 `entryPlacement: "top" | "wand" | "both"`，默认 `"top"`。演进走既有 mergeSettings 前向兼容（旧数据自动补默认值，无需迁移，见 plugin-settings.ts 头注释）。
- **存储**：插件全局设置（extension_settings.steMemory，随 ST settings.json 持久化）。注意与「面板几何」「面板安全区」不同——那两个是本机偏好（localStorage），入口位置是全局设置（本次 grill 决策 Q6 用户明确选择）。
- **选项集**：只有 顶部 / 魔法棒 / 两者 三项，不提供「隐藏入口」——隐藏后面板只能关不能开，纯陷阱。
- **入口语义**：单一面板开关，与现有 ToolbarButton 完全同语义（toggle PanelModel，aria-pressed 高亮），不增加直达 Tab 等菜单树。
- **魔法棒项形态**：镜像 ST 内置工具行结构 `div.list-group-item.flex-container.flexGap5` + `div.fa-solid.fa-* .extensionsMenuExtensionButton` + `span`「记忆面板」（先例：gallery 的 addGalleryWandButton）。挂在 `#extensionsMenu` 下（无专属 `*_wand_container` 的第三方先例即此）。布局样式随 ST 菜单原生走（list-group-item 零新布局样式）；仅按压/展开态与焦点高亮补少量 `--stm-*` 令牌规则（用户故事 5 的展开高亮需要，属状态样式非布局）。
- **挂载控制器**：在 mountPanel 基础上抽出入口挂载逻辑：按设置解析目标（top → 现状 #top-settings-holder 兜底 body；wand/both → 等待 `#extensionsMenu` 出现（MutationObserver/短轮询），追加魔法棒项）；「两者」= 两处同时挂。设置变更 → 重解析 + 重挂载（React 双 root 风格沿用 mountPanel，热切换即时生效）。
- **回退**：选 wand/both 但魔法棒容器始终未出现（ST 版本差异等极端情况）→ 回退顶部，标记 fallback，设置分组摘要显示「实际位置：顶部导航栏（魔法棒不可用）」。入口永不静默消失；回退后仅当设置变更重新解析时才重新探测魔法棒菜单（15s 等待窗口内菜单出现则立即升级，ST 的魔法棒菜单随启动 1~2s 内建好，窗口外的迟到场景不处理）。
- **副作用（接受）**：ST 的 showHideExtensionsMenu 每秒按菜单可见子项数显隐魔法棒按钮——我们的项是可见子项，选 wand/both 后魔法棒按钮必然常驻可见（哪怕本实例没连 Extras）。这是「选魔法棒入口就必须点亮魔法棒」的自洽代价，不处理。
- **设置分组**：设置 Tab 低频区新增可折叠分组「面板入口」（与「版本与运行状态」「面板安全区」相邻，遵循设置分组既有模式：折叠态摘要行显示当前选择；组内 = 三个选项 + 一行实际挂载位置提示）。
- **词汇表**：st-extension CONTEXT.md 新增「面板入口」词条（已随本 spec 发布）。
- **无 ADR**：不满足 ADR 三条标准（难逆转 / 无上下文费解 / 真取舍）——这是可配置项，随时可逆；魔法棒挂载机制与回退策略属于实现行为，本 spec 决策区即为其文档。

## Testing Decisions

- **好测试的标准**：只测外部行为、不测实现细节。
- **主 seam（纯逻辑）**：挂载决策模块（resolve mount target + fallback 判定）与设置模型（entryPlacement 默认值/merge 补齐）的 vitest 单测。先例：st-settings-store.test.ts、plugin-settings.test.ts。
- **ST DOM 不测（既有决策，沿用）**：魔法棒容器挂载、等待重试、ST 按钮显隐交互属 ST DOM 行为，不写自动化测试；人工验收（真机 ST 桌面 + 移动断点各过一遍三个选项与回退）。
- **渲染 seam（可选，小需求可不做）**：设置分组 UI 的 renderToString 冒烟测试（先例：ui/agent-connection-manager.test.tsx）。魔法棒项 DOM 结构简单且无新样式，可并入人工验收。
