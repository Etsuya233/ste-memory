# 重置记忆空间（清除记录 / 重置空间）

Status: ready-for-agent

## Problem Statement

我在 SillyTavern 插件面板里管理记忆空间，长时间对话后空间里积累了大量记忆记录，或者表格结构被自定义改动搞得不可收拾。目前面板没有任何方式批量清空或重置一个记忆空间的内容——想清只能逐条删记录（还要受引用校验限制），想恢复出厂只能删掉整个空间再重来，而全量删除会让当前对话失去绑定。我需要一个明确、有确认、分档的「重置」入口，让我能干净利落地清空当前对话的记忆内容。

## Solution

在 ST 插件面板「设置」Tab 新增「危险操作」区块，提供**两个独立的原生确认流程**：

- **清除空间记录**：原子删除当前记忆空间中全部记录派生数据（记忆记录、历史记录、字段证据与修订身份），**保留**表格定义、字段与显示策略；同时清除填表任务与楼层进度台账，通用日志保留。
- **重置空间**：原子删除当前记忆空间中**全部表格**（级联字段、记录、历史与证据），随后自动按系统表默认定义重新初始化（重装 8 张系统表）；自定义表随之消失、被修改过的系统表回到出厂定义；记忆空间身份、名称与对话绑定保留。

两者都不删除记忆空间本身（「删除记忆空间」是既有且语义不同的另一操作）。两个操作都作为普通数据变更参与现有传播机制：空单元按 LWW 覆盖 R2 云同步副本与对话文件镜像；执行后面板数据、记忆宏快照、问答面板历史随之刷新或清空。

## User Stories

**清除空间记录**

1. 作为用户，我想在设置页的「危险操作」区块看到「清除空间记录」按钮，以便清空当前对话记忆空间积累的全部记录
2. 作为用户，我想在点击后看到原生确认框，其文案说明将删除全部记录、历史与证据且表格结构保留，以便确认后果后再动手
3. 作为用户，我想确认后所有表格中的记忆记录被原子删除，以便空间内容归零
4. 作为用户，我想清除时历史记录、字段证据与修订身份一并删除，以便不留孤儿数据、不污染查询与展示
5. 作为用户，我想清除后表格定义、字段、显示策略与表格开关原样保留，以便不用重建表格结构
6. 作为用户，我想清除后记忆查询（含 Agent 查询工具、记忆宏展开、记录网格）返回空结果，以便看到的就是空空间
7. 作为用户，我想清除后填表任务与楼层进度台账一并清空，以便可以从头重新填表而不受旧的「已填楼层」标记干扰
8. 作为用户，我想清除后通用日志（填表日志等审计数据）保留，以便事后复盘本次清除前的历史
9. 作为用户，我想清除后记忆空间的名称、身份与对话绑定保持不变，以便继续使用同一个空间
10. 作为用户，我想清除后云同步把空单元推送到 R2、对话文件镜像被空单元写回，以便各副本与本地一致（接受云上副本随之清空）
11. 作为用户，我想清除后记忆宏快照重建、问答面板内存历史清空，以便注入与问答不再展示旧内容
12. 作为用户，我想清除前进行中的填表任务被自动取消（interrupted，未提交提案丢弃），以便不会有任务把数据写回已清空的空间
13. 作为用户，我想当前对话无有效空间（空间未加载、绑定无法识别或插件停用）时按钮置灰，以便不会对无效目标执行

**重置空间**

14. 作为用户，我想在设置页「危险操作」区块看到「重置空间」按钮，以便把当前记忆空间恢复到出厂状态
15. 作为用户，我想点击后看到原生确认框，其文案说明将删除全部表格、恢复系统默认表、自定义表与修改过的表定义将消失、且会传播到云与镜像，以便确认后果后再动手
16. 作为用户，我想确认后全部表格（连同字段、记录、历史与证据）被删除，以便表格层彻底归零
17. 作为用户，我想删除后自动重新安装 8 张系统表（人物、人际关系、地点、物品、剧情、伏笔、待办、世界状态），全部启用且使用出厂默认定义，以便无需手动初始化
18. 作为用户，我想自定义表在重置后不重装，以便重置语义明确为「回到系统默认」而非「保留我的自定义」
19. 作为用户，我想被修改过的系统表（新增字段、改过显示策略或提示词）回到出厂定义，以便真正恢复默认
20. 作为用户，我想重置后表格 Key 保持稳定（重装生成新表 ID 但 Key 不变），以便依赖 Key 的记忆视图与宏展开不失效
21. 作为用户，我想重置后空间身份、名称与对话绑定保留，以便空间还是同一个空间
22. 作为用户，我想重置后填表任务与楼层进度台账清空，以便重新填表从头开始
23. 作为用户，我想重置后通用日志保留，以便保留审计痕迹
24. 作为用户，我想重置后云同步与对话文件镜像收到空单元（LWW），以便各副本一致
25. 作为用户，我想重置后面板表格列表与记录网格自动刷新、记忆宏快照重建、问答面板历史清空，以便界面立即反映新状态
26. 作为用户，我想重置前进行中的填表任务被自动取消，以便不会有任务把数据写回刚初始化的空间
27. 作为用户，我想当前对话无有效空间时重置按钮置灰，以便不会对无效目标执行

**通用**

28. 作为用户，我想两个操作各自独立的确认流程使用原生 `window.confirm`（与插件现有删除交互一致），以便交互可预期、无额外依赖
29. 作为用户，我想操作成功后有明确的成功提示（含清空/重置后的空间名），以便确认操作已生效
30. 作为用户，我想重置中若重装系统表失败，操作报错、空间保持无表状态且可重试，以便不会产生半初始化但假装成功的状态

## Implementation Decisions

- **领域层（core）**：`MemorySpaceService` 新增两个空间级操作，作为端口方法加在记忆空间仓库接口上（两个宿主实现同时被接口强制实现）：
  - `clearRecords(spaceId)`：单事务删除该空间的记忆记录、历史记录、字段证据与修订身份；表格定义、字段、显示策略、开关不动。这是新的批量通道，不经单记录删除校验——全空间一起消亡时不存在「仍被引用的目标」问题。
  - `deleteAllTables(spaceId)`：单事务删除该空间全部表格，级联其字段、记录、历史与证据（与既有的空间级联删除同语义，但不删除空间实体本身）。
- **宿主实现**：SQLite（参照实现）用按空间过滤的删除语句 + 外键级联；Dexie（镜像语义）在单事务内按 `memorySpaceId` 批量删除对应表（与既有空间删除的级联清单一致，去掉空间实体行本身）。两实现的语义与既有「空间级联删除」对齐，注释互引。
- **ST 宿主维护服务**：新增空间维护服务，编排两个操作：
  - 执行前取消该空间全部进行中的填表任务（复用现有 cancel → interrupted 语义，安全点停止、未提交提案丢弃）。
  - 清除：调 `clearRecords` + 清填表任务与楼层进度台账；通用日志保留。
  - 重置：调 `deleteAllTables` + 清填表任务与楼层进度台账 + 调系统表安装器重装 8 张系统表；通用日志保留。重装失败时报错并保持无表状态（可重试），不回滚已删表格（与首次创建安装失败即回收空间的策略不同——重置时空间绑定已存在，不能回收）。
- **UI（设置 Tab）**：新增「危险操作」区块，两个按钮各自触发 `window.confirm`，文案写明删除范围与「云同步与对话文件镜像中的副本也会被清空」；当前对话无有效空间（未加载 / 绑定无法识别 / 插件停用）时按钮置灰。执行成功后：面板数据版本刷新（表格列表、记录网格重取）、记忆宏快照立即重建、云同步与镜像 kick、问答面板内存历史清空。
- **传播语义**：清除/重置产生空的空间单元，按既有 LWW 机制防抖推送覆盖 R2 云副本、镜像文件被空单元写回；不做「本地独清空」的特殊通道。空间实体仍在，镜像的「本地缺失才恢复」语义不触发旧数据复活。
- **稳定性**：重置后重装生成新表 ID，但表格 Key 不变；依赖 Key 的插件配置（记忆视图、清洗规则选择）不受影响。
- **范围**：本轮只做 ST 插件（面板 UI + Dexie 宿主 + core 端口 + SQLite 参照实现保语义对齐）；不加 api 路由与 web UI。

## Testing Decisions

- **好测试的标准**：只断言外部可观察行为（数据删除/保留的结果、空间身份不变、任务被取消），不测实现细节（不测具体删除语句、不测 confirm 文案）。
- **接缝 1（主接缝，行为全量）**：ST 宿主空间维护服务。用内存 Dexie 测试库 + 真实系统表安装器 + 填表任务服务接线（现有 `createTestDatabase` / `createServices` 形态）。覆盖：清除后记录/历史/证据消失而表格结构保留；重置后表格归零并重装出 8 张出厂系统表、自定义表不重装、被修改的系统表回默认；填表任务/楼层台账被清而通用日志保留；空间身份与名称不变；进行中任务被取消；重装失败路径。
  - 先例：`system-tables-install.test.ts`（真实安装器）、`memory-space-repository.test.ts`（Dexie 空间仓库删除语义）、`fill-task-service.test.ts`（任务取消语义）。
- **接缝 2（语义对齐）**：api SQLite 参照实现的两个端口方法（记录层清空 / 表级联清空），服务层或仓库层测试，断言删除后各表的剩余行数与既有级联语义一致。
  - 先例：`memory-spaces.test.ts`（服务层测试形态）。
- **接缝 3（UI 薄层）**：设置 Tab 危险操作区渲染两个按钮、无有效空间时置灰；confirm 为原生对话框不测。
  - 先例：`panel-shell.test.tsx`。

## Out of Scope

- **删除记忆空间**（空间实体级联删除、绑定失效）：既有操作，不并入本按钮，UI 上也新增（面板当前无此入口，维持现状）。
- web（api/web）侧的清除/重置 UI 与 API 路由；本轮仅补 SQLite 参照实现保证语义对齐。
- 撤销/恢复、回收站、软删除。
- 清除/重置的「本地独清空、云上保留」特殊通道（明确不做，保持 LWW 一致性）。
- 通用日志（填表日志等审计数据）的清理。
- 备份导出格式变更：备份单元自然反映清空后状态，无需改动。

## Further Notes

- 三个空间级操作的术语与区别已写入 `core/CONTEXT.md`（清除空间记录 / 重置空间 / 删除记忆空间）。
- 未建 ADR：清除/重置传播到云这一权衡可逆，且术语已在 glossary 固化，不满足 ADR「难逆转」条件。
- 执行入口只作用于「当前对话」绑定的记忆空间；多空间批量操作不在本票范围。
- 后续若为 api/web 增加清除/重置路由：SQLite 侧 `memory_fill_tasks` 与楼层台账只挂 `memory_spaces` 外键（不随表格级联），路由实现必须像 ST 宿主维护服务一样显式清空该空间的填表任务与楼层台账（参照 `space-maintenance-service.ts` 的编排）。
