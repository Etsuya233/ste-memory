- [x] 取消与重试操作生效且状态正确（用户取消 = 块边界检查后停止，任务置 interrupted，与关 tab 同态，不自动重放）

## Answer

工作树提交（10 个修改文件；st-extension 432 例全绿，typecheck（src+scripts）/eslint/prettier（改动文件）/build 全绿）。

- **任务历史列表**（`ui/task-panel-model.ts` + `ui/tasks-tab.tsx`）：终态任务列表（状态徽章 / 楼层范围 / 创建时间 / 进度 / 失败原因），createdAt 倒序，上限 20 条；运行中任务不进历史（活动任务区展示，取消入口唯一）；时间展示复用 `formatSyncTime`（ISO → `YYYY-MM-DD HH:mm`，与设置面板同步时间同约定，等宽数字）。
- **重试**（`fill-tasks/fill-task-service.ts` `retry()`）：失败/中断任务按原楼层范围与原分块大小重新提交为新任务（`blockSize` 保留），原任务保持终态留在历史；重试 = 复用 `submit`——活动任务守卫天然拒绝运行中任务的重试（快速双击不产生双任务，冲突携带当前任务可读），对话切换/LLM 配置/范围校验同路径生效；重试已成功任务等同于手动重新触发同一范围（UI 不提供入口）。重试跑全量原范围（含已提交块）：与 ticket 13「已提交块保留、可再次提交任务重试」语义一致，证据同源唯一复用保证幂等（已提交块重跑只耗 token 不产生脏数据）。
- **逐消息覆盖视图**（`buildCoverageViewModel`）：类别 = 台账（processed/error，出错可重试、已提交保留语义不受活动任务影响）+ 活动任务范围内未台账楼层（任务中）+ 其余（未计划）；连续同类别区间（run）为渲染单元，楼层条每消息一格（键 = 楼层号，悬停显示楼层与类别）、图例带计数；陈旧台账楼层（超出当前对话长度）不参与（按 live 楼层渲染）。
- **测试**：模型 18 例（覆盖视图分类/run 合并/陈旧楼层/历史条目字段/retryable 过滤运行中任务）、服务 4 例新增（失败重试 error 覆盖 processed + 旧任务保持 failed、取消后重试完成 + 旧任务保持 interrupted、双击重试冲突、NotFound）。
- **遗留**：真机验收（任务 Tab 触发 → 覆盖条随进度变化 → 失败任务重试 → 历史列表展示）待用户在真实 ST 环境执行；重试全量范围的 token 成本是已接受的权衡（见上）；超长对话（>1k 消息）覆盖条 DOM 元素多，1s 轮询仅活动任务期间进行（React 按楼层键 diff，无状态变化不写 DOM）。
