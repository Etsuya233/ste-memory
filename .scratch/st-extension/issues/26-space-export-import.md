# 26 — 单空间导出/导入

**What to build:** 针对当前对话对应记忆空间的单空间粒度导出/导入功能：导出当前空间为独立 JSON 文件，导入文件到当前空间（匹配时整体替换、不匹配时 cloneSpace 并重建绑定、无绑定时创建新空间并绑定）。全库备份文件也可作为导入源（智能提取匹配单元）。

**设计决策（2026-08，grilling session 结论）：**

- 与 issue 07 的全库导出/导入互补：全库 = 整体替换所有空间；本功能 = 单空间粒度，面向「备份/恢复一个对话的记忆」或「跨分支迁移记忆」场景。
- spaceId 不匹配时走 cloneSpace 路径（而非 remap 写入）：保留原空间数据不动，创建新空间并重建绑定——最安全，语义是「抄了一份」而非「覆盖」。需要 ADR 记录 trade-off。
- 复用现有备份信封格式（`ste-memory-backup` format），data 部分只含一个空间单元。全库文件导入时从 `data.spaces[]` 中智能提取匹配单元。

**Blocked by:** 07 — 手动导出/导入（编解码、备份存储端口、restoreSpace、cloneSpace）

**Status:** ready-for-agent

## Problem Statement

issue 07 实现了全库导出/导入，行为是整体替换——导入时清空全部六张表再写入备份文件的所有空间。这对单对话用户够用，但多空间用户有两个痛点：

1. **备份粒度太粗**：我只想备份当前对话的记忆，不想把所有对话的数据都导出成一个文件；导入时也不希望其他空间的数据被覆盖。
2. **跨分支迁移无路径**：我从分支 A 导出全库，想在分支 B 导入时只恢复 A 对应的空间——但全库导入会把 B 的数据也清掉。

## Solution

在设置面板「数据备份」组增加「导出当前空间」和「导入到当前空间」两个按钮，提供单空间粒度的导出/导入：

- **导出当前空间**：把当前对话对应的记忆空间序列化为一个 JSON 文件下载。文件格式复用现有备份信封，data 部分只含当前空间的一个单元。
- **导入到当前空间**：选文件后校验、匹配空间、按情况处理：
  - spaceId 匹配 → 整体替换当前空间数据
  - spaceId 不匹配 → cloneSpace 创建新空间 + 重建绑定（原空间保留）
  - 无绑定 → cloneSpace 创建新空间 + 建立新绑定
  - 文件中无匹配空间 → 报错

## User Stories

**导出**

1. 作为用户，我想在设置面板点击「导出当前空间」按钮，把当前对话的记忆空间数据下载为 JSON 文件，以便手动备份单个对话的记忆
2. 作为用户，导出的文件只包含当前空间的数据（不包含其他空间），以便文件体积小、内容明确
3. 作为用户，导出的文件格式与全库备份兼容（同一信封格式），以便导入时不需要区分文件来源
4. 作为用户，导出的文件名包含日期信息（`ste-memory-space-export-<日期>.json`），以便区分不同时间的备份
5. 作为用户，导出时是否包含修订历史跟随「包含修订历史」设置项，以便与镜像写回行为一致
6. 作为用户，当前对话没有绑定记忆空间时，导出按钮灰显并提示「当前对话未绑定记忆空间」，以便知道前置条件不满足
7. 作为用户，导出完成后看到 Toast 提示「已导出记忆空间「<空间名>」」，以便确认操作成功

**导入**

8. 作为用户，我想在设置面板点击「导入到当前空间」按钮并选择 JSON 文件，把文件中的记忆数据导入到当前对话，以便从备份恢复或从其他对话迁移记忆
9. 作为用户，导入的文件可以是单空间导出文件，也可以是全库备份文件——系统自动提取匹配当前空间的单元，以便不需要关心文件是哪种格式
10. 作为用户，导入开始时看到 Toast 提示「正在导入…」，导入完成后看到 Toast 提示「已导入记忆空间「<空间名>」」，以便了解导入进度和结果
11. 作为用户，导入的文件格式不正确或版本不支持时，看到明确的错误提示（复用 issue 07 的校验错误信息），以便知道问题原因
12. 作为用户，导入的文件中不包含当前记忆空间的数据时，看到提示「文件中不包含当前记忆空间的数据」，以便知道无法导入

**导入 — spaceId 匹配**

13. 作为用户，导入文件中的 spaceId 与当前空间一致时，弹窗确认「将用文件中的数据替换当前记忆空间「<空间名>」的全部记录。此操作不可撤销。确认？」，以便在替换前知情
14. 作为用户，确认后当前空间的全部记录、修订历史、证据被文件内容整体替换，表格定义保留不动，以便数据恢复到导出时的状态
15. 作为用户，替换完成后面板自动刷新（表格列表 + 记录视图），宏快照重建，以便立即看到新数据且下次生成使用新记忆

**导入 — spaceId 不匹配**

16. 作为用户，导入文件中的 spaceId 与当前空间不一致时，弹窗详细说明「将创建新的记忆空间并绑定到当前对话，原空间数据保留。确认？」，以便知道会发生什么
17. 作为用户，确认后系统用 cloneSpace 从文件数据创建一个新空间（全新 ID，所有外键重映射），然后把当前对话的绑定指向新空间，以便在当前对话中看到导入的数据
18. 作为用户，原空间的数据不受影响（保留不动），以便不会丢失当前对话已有的记忆
19. 作为用户，cloneSpace 创建的新空间继承文件中的空间名，然后按当前对话的命名规则重命名，以便空间名与当前对话匹配

**导入 — 无绑定**

20. 作为用户，当前对话没有绑定记忆空间时也可以导入，系统创建新空间并建立绑定，以便从文件恢复一个对话的记忆（如新设备、镜像损坏场景）
21. 作为用户，无绑定时导入的确认弹窗与 spaceId 不匹配时相同（详细说明），以便知道会发生什么

**导入后副作用**

22. 作为用户，导入完成后（无论哪种路径）面板自动刷新，以便立即看到新数据
23. 作为用户，导入完成后宏快照自动重建，以便下次对话生成时注入的是导入后的记忆
24. 作为用户，导入完成后对话文件镜像尽快写回（kick 镜像同步），以便切走对话后镜像包含最新数据

## Implementation Decisions

1. **UI 位置**：设置面板「数据备份」组，在现有「导出全部数据」/「导入全部数据」按钮旁增加「导出当前空间」/「导入到当前空间」按钮。无绑定时导出按钮灰显（tooltip 提示），导入按钮永远可用。

2. **导入动作解析器（新 seam）**：纯函数 `resolveImportAction(file, currentBinding)` 返回导入动作判别联合：
   - `{ kind: "restore"; unit }` — spaceId 匹配，整体替换
   - `{ kind: "clone-and-rebind"; unit; currentSpaceId }` — spaceId 不匹配，cloneSpace + 重建绑定
   - `{ kind: "create-and-bind"; unit }` — 无绑定，cloneSpace + 建立新绑定
   - `{ kind: "no-match"; availableSpaceIds }` — 文件中无匹配空间

   该函数封装导入决策树，是唯一需要新增的逻辑 seam。UI 层根据返回的动作执行对应的 repository 调用。

3. **全库文件兼容**：导入时从 `file.data.spaces[]` 中按当前空间 ID `find` 匹配单元。找不到则返回 `no-match`（报错）。不需要区分单空间文件和全库文件。

4. **导出实现**：`loadSnapshot()` → 从 `snapshot.spaces` 中找当前空间单元 → 按 `includeHistory` 设置裁剪 history → `createBackupFile` 编码单单元快照 → `serializeBackupFile` → Blob 下载。

5. **导入确认弹窗**：匹配时简短确认（一行）；不匹配/无绑定时详细说明（cloneSpace 行为 + 原空间保留）。用浏览器原生 `confirm()`（与 issue 07 一致）。

6. **Toast 通知**：导入开始时显示「正在导入…」，完成后显示「已导入记忆空间「<空间名>」」（成功）或错误提示（失败）。用 ST 的 `toastr` API（与现有备份功能一致）。

7. **导入后刷新链**：面板 `dataVersion` 递增（触发表格列表 + 记录视图重渲染）→ 宏快照重建 → `mirrorSync.kick()` 镜像尽快写回。与 issue 07 导入后的刷新行为对齐。

8. **ADR**：记录 trade-off —— 为什么 spaceId 不匹配时走 cloneSpace（保留原空间）而非 remap 写入（覆盖原空间）；为什么复用备份信封而非新格式；为什么导入按钮永不禁用。

## Testing Decisions

- **测试外部行为，不测实现细节**：只测导入动作解析器的输入输出、导出快照过滤的正确性、UI 按钮状态。
- **导入动作解析器（核心新 seam）**：纯函数，用 fake `ChatBindingStoreRead` 测试四种路径（restore / clone-and-rebind / create-and-bind / no-match），覆盖：匹配、不匹配、无绑定、多空间文件提取、文件无匹配空间。
- **导出快照过滤**：验证 `loadSnapshot` 结果经过滤后只含当前空间单元，且 history 裁剪跟随设置项。
- **UI 按钮状态**：验证导出按钮在有/无绑定时的禁用状态，验证导入按钮始终可用（与现有备份按钮测试模式一致）。
- **先例**：issue 07 的 core 编解码测试（20 例）、Dexie 备份 repository 测试（6 例）、UI 冒烟测试（9 例）。本功能的解析器测试沿用同一风格（纯函数输入输出断言）。

## Out of Scope

- 多空间批量导出/导入（issue 07 的全库功能已覆盖）
- 导入时的合并策略（冲突 ID 处理、增量导入）
- 导出进度条（v1 先简化，后续有性能问题再加）
- 导出到剪贴板（JSON 文本复制）
- 导入后自动清理原空间（cloneSpace 路径保留原空间，用户手动管理）

## Further Notes

- 与 issue 07 的关系：互补而非替代。issue 07 是「全库备份/恢复」，本功能是「单空间备份/恢复 + 跨分支迁移」。两者共享信封格式和校验逻辑。
- cloneSpace 路径复用 `ChatSpaceManager.resolveBranch` 的已有模式（创建空间 → 重建绑定 → syncToCurrentChat 收敛），但导入场景的 ID 工厂和空间名重命名逻辑需要适配。
- 全库文件作为导入源是便利性设计：用户不需要关心文件是单空间还是全库导出的，系统自动提取。如果文件中有多个空间匹配当前 spaceId（理论上不可能，因为 spaceId 全局唯一），取第一个。
