# 27 — 清洗规则测试：弹窗预览当前列表整条流水线效果

**What to build:** 为 ticket 22 / ADR 0011 的清洗规则列表增加**测试能力**：设置 Tab「清洗规则」区块动作行新增「测试」按钮（无列表时禁用），点击打开一次性弹窗「清洗测试」——以**当前编辑列表**为对象，对弹窗内输入内容套用整条流水线（全部启用规则按数组顺序执行，上一条输出是下一条输入），展示**逐规则步骤 + 最终结果**，供保存/投入任务前确认规则行为正确。输入两种形态：默认「单条文本」（整框 = 一条消息的 content）；「从当前对话载入」切换为「消息列表」形态（最近 20 条，对齐填表任务默认块大小；每条显示名字 + 内容且可编辑；清洗与真实流程一致地**逐条只清 content**）。**未保存草稿参与测试**（弹窗标注「含未保存修改」；草稿无效则弹窗显示校验错误并中止，绝不静默回退已保存版本）。原文不动，结果区只读（含「复制结果」），改输入可重跑。

**Status:** ready-for-agent

## Problem Statement

清洗规则列表的规则行为只能在真实填表任务中观察：用户配置/导入规则后无从验证「这条正则到底会把消息变成什么」，只能跑一次任务看结果，错了再回来改、再跑——调试一个正则要反复消耗 LLM 请求。且规则是链式执行，改中间一条可能破坏后续规则的输入，最终结果不对时无法定位是哪条规则的问题。设置 Tab「清洗规则」区块目前没有任何预览/测试能力（apps/web 侧有「前 10 条消息原文→变换后对照」的实时预览，ST 插件侧缺失）。

## Solution

在设置 Tab「清洗规则」区块动作行（与新建/重命名/删除同行）增加「测试」按钮，无列表时禁用。点击打开**清洗测试**弹窗（overlay，一次性，非持续模式）：

- **输入区**：默认单条文本形态（一个文本框，整框视为一条消息的 content，可粘贴/输入）；「从当前对话载入」按钮切换为消息列表形态——载入当前对话最近 20 条消息（不足则全部；无消息提示不载入），每条显示发送者名 + 内容，内容可编辑；再次点击载入**替换**当前消息列表（不追加）。不提供增删消息行。
- **执行**：点「清洗」运行当前编辑列表的整条流水线（草稿参与见下）。原文不动。
- **结果区**（输入框下方，只读）：**最终结果 + 逐规则步骤**——从原文开始，每步显示该规则变换后的中间态；停用规则标注「跳过（已停用）」；清洗结果为空的条目显示「（空）」；列表无启用规则时提示「列表没有启用规则」且结果为原文。改输入后可再次点「清洗」重跑。「复制结果」按钮复制最终结果。
- **草稿参与**：测试运行时，编辑中的未保存草稿**覆盖**对应已保存规则参与测试，弹窗标注「含未保存修改」；测试涉及的草稿校验失败（如正则语法错误）→ 弹窗内显示校验错误并**中止执行**（与保存校验同口径）。

## User Stories

**入口与作用对象**

1. 作为用户，我想在设置 Tab「清洗规则」区块看到「测试」按钮并点击打开清洗测试弹窗，以便在保存规则前验证规则效果
2. 作为用户，当还没有任何清洗规则列表时「测试」按钮禁用，以便不会产生无意义的空测试
3. 作为用户，测试对象始终是当前编辑列表的整条流水线（全部启用规则按顺序执行），以便预览结果与填表任务输入语义一致

**输入**

4. 作为用户，我可以在弹窗文本框内粘贴/输入任意文本，整框视为单条消息的 content，以便快速验证一条正则对一段文本的效果
5. 作为用户，我可以点击「从当前对话载入」让弹窗切换为消息列表形态并载入当前对话最近 20 条消息（不足则全部），以便用真实数据检验规则
6. 作为用户，载入的消息逐条显示发送者名与内容，以便辨认每条消息的来源
7. 作为用户，我可以编辑载入的消息内容，以便调整输入后重测
8. 作为用户，再次点击「载入对话」会替换当前消息列表而不是追加，以便重新载入最新消息
9. 作为用户，当前对话没有任何消息时点击载入会看到提示且不载入，以便知道原因

**执行与结果**

10. 作为用户，点击「清洗」后输入原文保持不变、下方出现结果区，以便对照原文与变换结果
11. 作为用户，结果区同时展示最终结果与逐规则步骤（每步显示该规则变换后的中间态），以便定位是哪条规则造成的变化
12. 作为用户，停用规则在步骤中以「跳过（已停用）」标注，以便知道哪些规则没有参与本次变换
13. 作为用户，列表没有启用规则时看到「列表没有启用规则」提示且结果为原文，以便理解为什么没有变化
14. 作为用户，清洗结果为空的条目显示「（空）」，以便区分空结果与未清洗
15. 作为用户，我可以复制最终结果，以便拿去做进一步处理或对照
16. 作为用户，修改输入/规则后可以再次点击「清洗」重跑，以便迭代调试

**草稿与错误**

17. 作为用户，我在编辑规则但尚未保存时点测试，未保存的修改会自动参与测试且弹窗标注「含未保存修改」，以便保存前验证刚输入的正则
18. 作为用户，测试涉及的草稿校验失败（如正则语法错误）时弹窗显示校验错误并中止执行，以便知道问题所在而不是静默回退到已保存版本

**语义保真**

19. 作为用户，消息列表形态下清洗逐条只作用于消息内容（发送者名不参与清洗），以便与填表任务输入完全一致
20. 作为用户，单条文本形态下整框当一条消息处理，以便符合直觉地调试单条消息

## Implementation Decisions

（grilling 会话产出；术语「清洗测试」已入 `apps/st-extension/CONTEXT.md`，_Avoid_: 测试模式、调试面板、清洗预览；不写 ADR——UI 增量 + 既有弹窗先例，不满足 ADR 三条件。）

- **入口**：「测试」按钮位于「清洗规则」区块动作行（与新建/重命名/删除同行），`editList` 不存在时禁用。
- **弹窗形态**：overlay 弹窗（复用 `stm-modal-overlay` 骨架，`PreviewModal` children 形态先例），标题「清洗测试」；一次性打开，非持续模式；关闭即丢弃弹窗内状态。
- **唯一逻辑 seam：扩展 `cleaning-rules-manager-model.ts`**（现纯逻辑 seam）新增「测试运行」纯函数族，组件只做「模型 → DOM」投影与事件接线（同现有惯例）：
  - 输入：已保存规则（当前编辑列表）+ 未保存草稿覆盖（按规则 id）+ 消息载荷（单条文本形态 = 一条无名消息；消息列表形态 = 多条「名字 + content」消息）；
  - 执行顺序：先校验全部参与规则（草稿用 `validateRuleDraft` 同口径）——任一无效返回错误集合（含规则名），调用方中止；通过后复用 `applyCleaningRules`，逐消息收集每步中间态；
  - 输出：逐消息的 { 原文, 步骤[每步 = 规则名/模式/停用跳过标注/草稿覆盖标注/变换后内容], 最终结果 }；无启用规则时输出原文 + 空步骤（提示由 UI 按步骤是否全为停用判定，或由模型直接给出标志，实现时择一并在模型测试锁定）。
- **新端口 prop**：`CleaningRulesManager` 新增 `readRecentMessages(count: number): FillSourceMessage[]`（`FillSourceMessage {floor, content, name}` 形状，与填表任务同源）；宿主 `panel-shell.tsx` 注入，数据源与填表任务的楼层读取同源（当前对话 chat 数组）。组件拿到后原样展示，不做任何变换。「从当前对话载入」= `readRecentMessages(20)`；再次点击替换（不追加）；返回空 → 提示不载入。
- **弹窗内部状态**：当前形态（单条文本 / 消息列表）、输入内容（文本框或消息数组，均可编辑）、最近一次运行结果（<原文, 步骤, 最终> 序列，只读展示）；关闭/重新打开即重置。
- **显示细节**：空结果条目显示「（空）」（PreviewModal 先例）；「复制结果」复制最终结果（多消息形态复制全部消息结果，格式与展示一致）。
- 单条文本形态：整框为一个字符串、发送者名为空——与消息列表形态共用同一「逐条执行」模型（即单条消息列表），不另写路径。

## Testing Decisions

- **好测试标准**：只断言纯函数的输入 → 输出（步骤序列、最终结果、错误集合），不断言组件内部状态或 DOM 细节；组件测试只验证用户可见的渲染契约。
- **主 seam 测试**：`cleaning-rules-manager-model.test.ts` 扩展（现有 `rule()`/`list()` 工厂先例复用），覆盖：
  - 编排：规则按序执行、上一条输出是下一条输入（多规则用例）；
  - 草稿覆盖：草稿替换已保存规则参与测试、步骤标注覆盖来源；
  - 停用跳过：停用规则不执行且步骤标注「跳过（已停用）」；全部停用 = 原文 + 提示路径；
  - 无效草稿中止：返回错误集合（含规则名），不产生结果；
  - 语义保真：消息列表逐条只清 content（名字不改动）；单条文本形态 = 单条消息路径（与消息列表共用实现，分别断言）；
  - 边界：空输入、空消息列表、无启用规则、replace/keep/discard 三模式经流水线的中间态。
- **组件冒烟测试**：`cleaning-rules-manager.test.tsx`（renderToString，无 jsdom，现有惯例）验证渲染契约：测试按钮存在与禁用态（无列表）、弹窗开合、载入按钮、「清洗」后结果区出现、「复制结果」按钮、data-action / data-stm-field 键值。
- **不重复测试**：单条规则的模式语义（keep/discard/replace）已在 `cleaning-rule-lists.test.ts` 覆盖，本 feature 只测流水线编排与测试弹窗自身的逻辑。

## Out of Scope

- 单规则级测试按钮（grilling 确认 Q1 = 列表级整流水线；单规则调试可由「草稿参与测试」覆盖）。
- 持续模式/实时预览模式（grilling 确认 Q3 = 一次性弹窗；apps/web 侧已有实时预览，本插件不移植）。
- 弹窗内增删消息行、消息排序、载入数量可配置。
- 结果回写输入框、对结果再次点「清洗」（避免对已清洗文本二次清洗的误操作——原文不动、只读结果区）。
- 世界书扫描输入与证据内容的清洗（真实流程保持原文，测试范围只对齐消息内容）。
- api/web 侧清洗规则面板的任何改动（apps 侧已有实时预览，不受影响）。
- ADR（不写，见 Implementation Decisions）。
