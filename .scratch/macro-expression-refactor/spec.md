# 表达式宏重构需求与向量召回实现思路

状态：已实现并完成本轮验收，实际覆盖与宿主限制见实现记录。日期：2026-10-26。

主代理先与 Sol 6.1 Medium 质询，随后按用户反馈与 Astra Medium 复审。本稿取代同目录此前版本；原讨论作为决策历史保留。用户已经认可“向量提供相关度，Query／SQL 完整决定结果”的方向，并明确统一名称为“对话宏”、整块废弃 memoryRecall。具体字段形状、默认值及实现方案属于本次共同建议。

## 1. 目标与核心模型

用户要求宏默认使用表达式，支持现有 Query 与 SQL，融入向量，支持表格预设自带宏，并能够筛选宏中的记录。宏全部在运算时统一计算，取消后台预计算。

核心模型是：**宏保存完整查询；向量为查询提供相关度；表达式决定筛选、排序、最终条数和输出字段。** 宏执行结果再按输出格式和字符预算渲染，用户通过 `{{前缀::宏名}}` 把结果放入提示词。

不再区分“普通宏”和“召回宏”两套定义，不设置候选 SQL、外部 Top K、外部最低分或外部字段投影，也不引入召回块与多块编排。包含语义源的宏仍是一份完整查询。SQL 可以用 JOIN、UNION、CTE 和聚合组织多表结果；Query 继续承担直观的单表结构化查询。

宏定义包含稳定身份、名称、单一启用状态、一份 Query 或 SQL 表达式、输出格式及字符预算。默认新建 Query；未保存的编辑草稿不参与求值。保存时明确启用状态，含语义源的新建宏默认停用，启用处显示会产生 embedding 请求。输出格式只决定呈现，不改变查询的记录、排序、数量或字段。

本轮不扩展向量索引切片、近似最近邻、混合检索、LLM 改写或重排、跨空间读取、JavaScript 脚本、任意宏递归、人工勾选本次命中、自动修改 ST 预设或世界书。本稿中的筛选指表达式筛选记录。

## 2. 宏归属、预设与命名

### 2.1 统一称为对话宏

本次局部宏统一称为“对话宏”，表示当前对话绑定记忆空间中的宏，定义随该空间保存；不另设“空间宏”或“当前宏”分区。多个对话明确共享一个空间时，共享这份对话宏定义；各对话的上下文参数仍来自各自本次生成，执行结果不会共享。

同名优先级为 **对话宏 ＞ 全局宏 ＞ 内置宏**。同名覆盖整个定义，不合并字段。停用或错误的高优先级定义仍占据该名称，展开为空并显示原因；只有删除定义才重新选择较低层同名定义。停用对话宏时界面说明它仍遮蔽同名全局内容。

全局宏继续保存在插件设置中，按本次活动空间执行。全局语义宏启用后会在所有适用对话执行，界面明确作用范围。内置无参宏、`full` 和表 Key 宏保留调用与内容用途，同样改在本次求值时计算。Agent 的 `tablesDigest`、`systemDefaultPrompt` 等独立宏保持既有职责。

宏名沿用现有字符限制；身份在改名时保持，复制、新副本导入、克隆及预设实例化产生新身份。表与字段使用定义 Key；向量组增加表内稳定 Key，显示名称与实例 ID 不承担可移植引用职责。

### 2.2 表格预设携带宏

表格预设保存宏定义集合。创建空间或明确应用预设时，宏与表结构、共用填写规则、向量分组和初始化来源在同一次空间提交中生效。实例化后独立修改，后续预设更新不回写已有空间。

普通宏沿用预设保存的启用状态；含语义源的宏在复制、导入、克隆或显式恢复后默认停用，用户启用后才请求 embedding。不存在另一份对话向量启用名单。正常打开同一空间、从该对话已有镜像加载，不属于新副本或显式恢复，不重置已保存的启用状态。

另存或覆盖表格预设默认包含对话宏，全局宏需先显式复制到当前空间。预设导出不附加记录、来源空间身份、实体 ID 映射、向量数据、连接配置或密钥。表达式中的用户字面值原样保存，不搬运记录或自动重写常量；直接依赖某条记录身份的表达式可能无法跨空间命中，编辑器需说明这一限制。系统自带预设宏避免具体记录身份依赖。

预设校验覆盖宏名、表达式形状、表字段和向量组 Key。SQL 可在空结构与空评分源上由 SQLite 编译校验，但不能据此证明任意 SQL 字面值均可移植。修改表或字段 Key 时，结构化 Query 可以更新已知引用；SQL 不做字符串猜改，保存结构变更后标明受影响表达式并要求修正。

对话宏随空间备份、镜像和克隆保存。清除空间记录保留宏，应用预设替换宏，删除空间删除宏。原位恢复可保留宏身份，但含语义源宏按上述规则停用；新副本始终生成新身份。

剧情记忆预设至少提供“未总结纪要”和“相关纪要”两个宏示例：前者为普通 Query，后者为包含语义源的 Query。前者按预设启用，后者初始停用。跨表摘要可用 SQL 编写，不为预设增加专用查询块或剧情专用运行逻辑。

## 3. Query 表达式

Query 采用可保存的 JSON 形态，表字段使用 Key，条件算子和类型沿用现有记忆查询。执行时绑定空间内部身份，内部分页不改变用户表达式的结果范围。

普通查询示例：

```json
{
  "table": "episodes",
  "conditions": [{ "field": "plot_summary", "op": "equals", "value": null }],
  "fields": ["summary", "content"],
  "orderBy": { "field": "$created_at", "direction": "asc" },
  "limit": 15
}
```

包含相关度的拟议扩展示例：

```json
{
  "table": "episodes",
  "semantic": {
    "groups": ["event_memory"],
    "query": { "context": "last_user_message" }
  },
  "conditions": [
    { "field": "plot_summary", "op": "equals", "value": null },
    { "field": "$similarity", "op": "greater_than_or_equal", "value": 0.45 }
  ],
  "fields": ["summary", "content", "$similarity"],
  "orderBy": { "field": "$similarity", "direction": "desc" },
  "limit": 10
}
```

表和字段仅为说明示例，编辑器提供实际 Key 补全。`semantic` 声明本表使用的组及查询输入，为有有效索引的记录提供 `$similarity`。多个组命中同一记录取最高分，Query 每条记录只出现一次。未提供有效分数的记录不进入该 Query 的语义结果；需要保留无分数记录时使用 SQL LEFT JOIN。

条件数组保持 AND；开放现有相等、不等、集合、包含和有序比较能力及其字段类型限制。语义查询增加 `$similarity` 的数值比较、排序与投影，未声明 `semantic` 就使用该字段时报配置错误。OR、复杂关联、聚合及多表组合使用 SQL，首版不增加 Query 布尔树。

`fields` 决定最终字段，未填写时沿用记录显示文本；字段顺序按表达式保留，引用值以本批记录集合中的显示值呈现。`limit` 为最终结果条数，缺省表示不人为限制最终条数，仍受资源与输出预算约束；底层每页 100 条只属于读取实现。未配置排序时沿用 `$updated_at` 倒序，同值以记录身份稳定排序；语义查询编辑器模板显式写出相关度倒序，避免隐式改变排序含义。

## 4. SQL 表达式与命名语义源

### 4.1 完整 SQL 决定结果

SQL 接受单条只读 SQLite 查询，支持 SELECT、CTE、JOIN、子查询、UNION 和聚合，允许尾部分号。拒绝多条可执行语句、写入、DDL、PRAGMA、事务及内部记忆元数据表读取，使用 SQLite 的实际编译和授权能力判断。

用户的 SELECT、WHERE、ORDER BY、LIMIT、OFFSET 完整生效。输出字段按 SELECT 决定，不要求结果必须包含记录身份，统计及聚合也能直接渲染。结果保留列顺序，重复列名明确报错并要求使用别名，不能先转成对象而悄悄覆盖列值。

Query 和 SQL 可以显式切换，但不保证复杂 SQL 无损转换为 Query。SQL 表达式由可选的语义源声明、可绑定输入及 SQL 正文共同构成，均保存在同一个宏中，编辑页可连续维护；它们共同定义一次查询。

### 4.2 首版采用声明源加标准 SQL

此前讨论中的 `semantic_scores(...)` 是示意语法，当前 SQLite 层没有该表值函数。首版采用可落地的命名关系：表达式声明语义源，执行器准备其相关度数据，SQL 按名称 JOIN。无需新增 SQL 解析器或虚拟表扩展，也不通过正则识别和替换 SQL 中的函数调用。

SQL 表达式的保存形态为 `{ sources?: SemanticSource[], sql: string }`；普通 SQL 可省略 sources。以下为了阅读将源声明与 SQL 分开展示，后段全文保存于同一对象的 sql 字段，属于拟议配置格式，尚未实现：

```json
{
  "sources": [
    {
      "name": "episode_scores",
      "table": "episodes",
      "groups": ["event_memory"],
      "query": { "context": "last_user_message" }
    }
  ]
}
```

```sql
SELECT e."summary", e."content", s.score
FROM "episodes" AS e
JOIN episode_scores AS s
  ON s.record_id = e."$record_id"
WHERE e."plot_summary" IS NULL
  AND s.score >= 0.45
ORDER BY s.score DESC, e."$record_id" ASC
LIMIT 10;
```

语义源提供 `record_id`、`score`、`group_key` 三列，只属于该来源声明的表，所有记录身份均来自当前空间。每条有有效分数的记录一行，多组取最高分，`group_key` 表示最高分组；组分相同按组 Key 固定选取。`score` 使用现有余弦相似度，范围 [-1, 1]，不表示事实可信度。

源名称在表达式内唯一，不得与本空间业务表名或保留内部名称冲突；不同宏可复用相同源名称。名称校验使用 SQLite 标识符的大小写比较规则，实际标识符安全引用。所有声明源都是本表达式的计算依赖，即使 SQL 没有引用某个源，也会先准备它；首版不分析任意 SQL 的依赖或承诺 WHERE 恒假时免请求。

### 4.3 筛选、LIMIT 和空评分源

语义源本身没有 Top K、最低分、候选 LIMIT 或字段投影，提供所选组全部有效记录的分数。表达式的 WHERE 决定资格，ORDER BY 决定顺序，最外层 LIMIT 决定最终条数。

“从最新二十条未总结纪要中找最相关十条”可以由 SQL 显式表达两次选取：

```sql
WITH recent AS (
  SELECT * FROM "episodes"
  WHERE "plot_summary" IS NULL
  ORDER BY "$created_at" DESC, "$record_id" ASC
  LIMIT 20
)
SELECT r."summary", s.score
FROM recent AS r
JOIN episode_scores AS s ON s.record_id = r."$record_id"
ORDER BY s.score DESC, r."$record_id" ASC
LIMIT 10;
```

这里两个 LIMIT 都由作者写出，不增加表达式外的隐藏限制。首版可对全表有效索引评分再执行此 SQL；以后允许等价的条件下推，但不能改变关系查询语义。

没有有效向量的记录在评分源中没有行。普通 JOIN 排除它，LEFT JOIN 可保留该业务记录并得到 NULL 分数；作者可以用 WHERE、IS NULL 或 COALESCE 明确处理。评分源为空属于有效空关系，显示覆盖诊断，不让整个宏失败。SQL 聚合可以对空关系得到正常结果，不能因为没有索引跳过整条 SQL。

不存在的表或组、非法输入、实际 embedding 失败仍是错误。分数阈值排除全部记录属于正常空结果。不能把“没有可用索引”“查询返回零行”及“表达式执行失败”合并成一种状态。

## 5. 查询输入与请求共享

语义源输入首版支持 `{ "context": "last_user_message" }` 或 `{ "text": "固定查询文本" }`。上下文输入取本次操作开始时最后一条已保存用户消息，执行 trim；固定文本同样只执行 trim。二者都不展开 ST 宏，不执行 JavaScript，不引用其他宏结果，不调用 LLM 改写，也不应用填表清洗规则。

默认编辑器使用最后用户消息；显式测试可为该上下文参数提供测试文本。SQL 首版提供唯一的宿主输入参数 `:last_user_message`，使用绑定值供 SQL 正文引用；不增加任意自定义 bindings 配置，不把消息正文拼接成 SQL。此参数不改变语义源中明确选择的输入来源。没有已保存用户消息时，该参数绑定为 NULL；语义源要求非空文本，普通 SQL 可以自行用 IS NULL 或 COALESCE 处理。

先校验语义源表、组及输入，输入为空或超过本地 4000 字符上限时报错，不静默截断。本批表无目标记录，或本批目标记录与所选组范围内没有任何已保存向量时，可以直接形成空源，不要求 profile 或连接；孤立的旧记录向量不计入该范围。只要存在需要检查的已保存向量，先取得 profile 才能判断模型与指纹兼容；profile 缺失时报配置错误，不能把它解释成所有向量无效。取得 profile 后再校验其 maxInputChars，并检查向量有效性；有效数为零时返回空源，零 embedding，不探测远端认证或网络。实际需要查询向量时才发请求并接受其错误。

同一求值批次以“实际查询文本＋embedding profile”共享查询向量 Promise，相同输入只请求一次。不同组、不同表可以共用查询向量，但各自生成评分关系；完全相同源可复用本批评分数据。不同文本分别请求，不假定当前单输入 embedding 接口支持批量 API。每次新生成重新计算，不跨生成复用查询向量或评分关系。

只使用当前所选 profile 下与本批记录输入指纹匹配的有效索引；缺失、过期、异常和空输入分别统计。查询不等待、不触发索引补建，不自动重试。索引依然属于独立后台派生数据，这不等于宏文本预计算。

## 6. 统一求值时机与用户流程

### 6.1 设置到实际输出

用户先配置 embedding 连接并为表建立向量组和索引；预设可提供分组。创建宏时默认编辑 Query，可增加 semantic 或切换 SQL 声明语义源，在表达式中写筛选、相关度排序、字段及 limit，测试后启用，再把 `{{前缀::宏名}}` 放进角色卡、提示词预设或世界书内容。

实际生成时，插件计算当前生效且启用的宏与内置入口，准备所声明语义源，执行完整表达式并渲染，再放行提示词展开。用户只维护一个宏启用开关。启用含语义源的全局宏或对话宏，都会在每次适用的实际生成中计算，即使未放置宏或它只在未激活的 WI 中；界面说明成本，首版不扫描 ST 所有提示词来源推断调用集合。

### 6.2 不做后台宏计算

启动、刷新、切对话、保存设置或宏、编辑记录、导入备份及向量补建均不执行宏 Query、SQL 或查询 embedding。允许校验定义、标记最近结果已过期；校验不能顺带计算真实查询或发送 embedding。需要 SQLite 编译校验时只 prepare、不 step，查询输入和外部请求不运行。

每次实际生成新建求值批次。ST 同步宏回调仅返回该批次已计算文本，不能返回 Promise，也不能临时发异步请求。同次生成中重复出现的宏读取相同文本；本次结束后结果仅供界面查看，不参与下次求值。

| 操作                                         | 行为                                                             |
| -------------------------------------------- | ---------------------------------------------------------------- |
| 新用户消息正常发送                           | 保存正文后、主要提示词展开前计算                                 |
| 重生成、生成新 swipe、续写                   | 每次用户发起操作重新计算                                         |
| 群聊一个回复批次                             | 本批计算一次，成员共用；下批重新计算                             |
| 同次生成中的工具递归                         | 复用本批结果                                                     |
| 群聊正常自动回复                             | 按本批开始时最后用户消息计算；缺消息仅影响使用该参数的表达式     |
| 切换已有 swipe、查看历史、打开最近结果       | 不计算                                                           |
| 独立 dry run、quiet、impersonate、插件 Agent | 不触发该 ST 记忆宏求值，宏为空                                   |
| 显式测试／重新求值                           | 独立执行同一查询语义，标明可能请求 embedding，不替换真实生成结果 |

独立 token 预估可能低估记忆宏内容。ST 同步宏回调缺少完整调用归属，并发 dry run 或 quiet 可能读取真实生成当前结果。typed hooks 排除这些入口，无归属结束事件不得撤销尚在等待或尚未进入正常拦截器的批次；正常批次已经进入提示词构建后，宿主完成事件缺少类型及操作身份，无法保证任意并发交错的完全隔离。不得用最后调用类型或计数器猜测操作归属，也不能宣称这一宿主边界已经消除。

### 6.3 ST 接入与输入边界

正常发送可在可等待的 MESSAGE_SENT 阶段统一求值。重生成等没有新 MESSAGE_SENT，需在 GENERATION_AFTER_COMMANDS 等早于提示词展开的可等待阶段计算。GENERATION_STARTED 只建立批次并清除旧调用资格，避免消息尚未落定或命令取消时计算错输入。

ST 在 MESSAGE_SENT 前已展开本次新用户输入中的宏。本轮保障角色卡、提示词预设、世界书内容及其后提示词路径，不保障把宏直接输入本次新用户消息就能取到当次结果；该提前阶段为空，不回填上轮文本。普通生成拦截器晚于部分宏展开，不能仅靠它覆盖全部位置。

取消旧发送需要其进入本插件的生成门禁后退出。当前宿主按扩展加载顺序执行拦截器，提前中断会跳过后续插件，因此本插件以 `loading_order: -1000` 先执行；其他可能提前中断的扩展必须排在其后。宿主也会忽略生成中的角色选择，真实切换验收采用停止旧生成后、HTTP 响应尚在延迟期间切换对话，另以单元测试覆盖直接上下文变化的取消。

接入判断以代码和宿主源码为依据，必须分别验收 Chat Completion、Text Completion、群聊及取消流程，不能把旧自动召回验证当作新链路已经完成。当前真实 ST 验证范围与尚存宿主边界见 [实现与验收记录](./implementation.md)。

## 7. 结果一致性、输出与失败

### 7.1 本批固定输入

本批固定对话、空间、操作身份、宏定义、消息参数、已提交记忆记录、字段、向量组和 embedding 请求配置。记录以开始时的已提交快照为准；后续编辑只影响下次生成，最近结果可显示资料已更新，不自动重算或撤销本批文本。

SQLite 记忆与 IndexedDB 向量无法承诺跨库同瞬时事务。读取的向量必须用本批记录、字段、引用显示依赖、组和 profile 校验输入指纹；只保留匹配本批输入的向量，新正文生成的向量不能配旧记录输出。覆盖可能减少，仍不能混用版本。Query 引用显示与 SQL 显示文本均使用本批记录集合。

请求连接地址、模型、请求头及凭据应在内存捕获并沿用，密钥不进入结果或导出。若现适配器无法保持请求配置，则连接变更取消受影响工作，不能改用新连接却仍按旧 profile 解读结果。

所有宏先独立完成，全部结束或达到本批截止时间后统一发布结果，再展开提示词。一个宏错误只使该宏为空；其他成功宏保留。切对话、ST 停止或新操作替换旧操作会取消归属，旧响应不能发布或清除新结果，覆盖 A→B→A 和共享空间不同对话。

### 7.2 渲染和预算

Query 无 fields 时使用记录显示文本，有 fields 时按字段顺序输出；引用按本批显示值呈现。SQL 默认按 SELECT 返回列顺序渲染 Markdown 表格，不自动把任意引用 ID 改成其他字段；需要目标名称时由作者 JOIN。支持 JSON 格式时，结果必须是有效 JSON，不能截断序列化字符串。

宏独立字符上限未配置时继承全局上限，标题、表头和省略标记均计入。按查询顺序装入完整记录或结果行，下一条放不下时停止并标明省略，不拿短的低排名行替换。首条非空结果也放不下时报告预算不足；JSON 按完整行重新序列化并计算预算。旧宏迁移可保留兼容渲染以维持既有输出。

输出继续进行宏语法消毒，结果中的成对花括号不能再次执行。错误不拼入模型提示词，留在界面与日志。

### 7.3 资源、取消和诊断

首版建议本批总预算 10 秒，包含快照准备、索引检查、排队、embedding、评分、SQL 和渲染；单条 SQL VM 预算 1 秒。到期后未完成宏为空并显示超时，已完成且归属有效的结果统一发布，主生成继续。用户可跳过本次尚未完成的计算，ST 停止则终止主生成和求值。

单宏最终查询结果最多 10,000 行；探测到第 10,001 行时报错，不静默截前 10,000 条。该上限不作用于语义源评分行数，也不能代替完整评分；评分受总时间及实际内存约束。首版不承诺任意规模，性能验收应记录全源评分耗时和内存峰值，超时或资源失败明确报告。SQLite VM 预算只能约束 SQL，不能替代主线程评分的分片、实际事件循环让出和取消检查。

表达式错误、缺表缺组、非法输入、连接或远端错误使该宏为空，主生成继续。无索引返回空评分关系并报告覆盖；正常零行、错误、未执行、停用、执行中、成功、取消和过期分别展示。不复用上轮成功文本，不换同名低优先级定义，不忽略筛选扩大范围，不自动重试。

界面区分最近真实结果和显式测试结果，展示表达式、生效作用域、消息来源、输入时点、各语义源及组选区、索引覆盖、请求次数、查询返回行与输出行、分数、实际文本、字符预算及分阶段耗时。最近结果只在本页保留，切对话清除；打开结果不执行查询。测试与真实生成互不覆盖、互不取消。

## 8. 向量召回的大致实现思路

### 8.1 可复用能力与新增职责

当前项目已有 SQLite WASM Worker、参数绑定、只读授权和 VM 时间预算；向量侧已有 embedding 端口、记录向量仓库、指纹检查、余弦计算和同记录最高组分。当前检索服务还包含界面状态、最低分过滤与 Top K 截断，不能直接把其已截断结果当成完整语义源。

新增的核心职责是宏表达式模型、语义源准备、无截断评分、一次求值的只读数据会话，以及生命周期接线。功能层依旧经 memory 公开边界读取；具体 SQLite、IndexedDB 和 ST 适配由 runtime 装配，不让宏功能依赖基础设施内部实现。

### 8.2 一次求值的执行流程

```text
捕获本次宏、上下文与已提交记录输入
→ 建立隔离的只读求值会话
→ 收集表达式声明的语义源
→ 按本批输入指纹筛出有效记录向量
→ 按文本与 profile 共享异步 embedding
→ 分片计算完整相关度，每源按记录取最高组分
→ 物化表达式局部评分关系
→ 只读执行 Query 编译结果或用户 SQL
→ 渲染并统一发布本批宏文本
→ 清理临时关系、销毁求值会话
```

embedding 在 SQL 执行前由宿主异步完成，SQLite 只读取已准备的有限相关度关系；远端请求不占业务写事务，也不在 SQLite 回调里等待 Promise。

### 8.3 数据会话与 SQL 执行

建议在 SQLite Worker 增加宏求值会话，基于本次已提交记录及结构建立隔离的内存数据库。它不接受业务写入或手动控制台修改；Query 的字段映射、引用显示和 SQL 的业务表读取都基于该会话。首版复制输入快照的内存代价需要测量，后续可以优化复制范围，不能因此改变已承诺的本批输入语义。

语义源以 `record_id TEXT`、`score REAL`、`group_key TEXT` 的临时表或等价关系提供。标识符由可信代码正规引用，分数和身份用绑定插入，消息正文不拼入 SQL。每个宏的一次内部 RPC 完成“创建本宏临时源、插入数据、安装读权限、执行 SQL、finally 清理”，失败也清理，避免当前 Worker 串行队列中不同宏或测试相互污染。

用户 SQL 仍用只读授权和本次业务表／源的列白名单执行，内部物化通道与用户 SQL 权限分开；即使数据库隔离，也不能把用户 SQL 交给 host 权限。检查实际可执行语句数量，保留有序列元数据与行数组，重复列名在对象化前报错。当前 Agent SQL 封装限制返回 101 行，不能直接复用其截断结果；宏需可检测超限的独立读取入口，底层授权机制可以共用。

首版采用命名源避免 SQL AST 改写，不需引入解析器，也不注册自定义表值虚拟表。未来如增加 `semantic_scores(...)` 语法，应另行验证解析和编译方案，不作为本轮完成条件。

### 8.4 评分与共享

从现有检索实现提取或复用无界面状态的有效性检查与评分步骤，向宏求值器返回全部有效分数及覆盖；手动检索仍可在评分后执行其自己的 Top K。不能用极大的 Top K 假装无截断，也不能复用手动检索实例的取消状态。

首版按源声明的表与组读取全部可用向量，不对任意 SQL 的 WHERE 或 LIMIT 做推断。多组先按记录取 max，生成每源一行；不同源分别计算组聚合。最终阈值、排序、去重、聚合和条数完全交给 SQL，Query 按同一关系语义编译。

批次内共享查询向量 Promise，完全相同源可共享评分数据。评分按批处理并实际让出事件循环，检查 AbortSignal 和总时限；仅 await 已解决 Promise 无法保障及时接收停止操作。索引读取后必须对本批指纹核验，不能调用只按当前实时正文生成 targets 的路径后与旧快照拼接。

### 8.5 需要实施验证的技术点

实现前先在真实 WASM 路径验证隔离会话、临时评分关系、白名单、单语句检查、重复列名及有序结果；再验证 SQL LIMIT 不会提前截评分源。还需测量快照复制与全源评分成本，并完成正常发送、重生成、续写、群聊和停止的真实 ST 接入验证。以上是待实施技术验收，不声称当前已经具备完整接口。

## 9. 兼容与迁移

### 9.1 旧视图与对话宏存储迁移

旧全局视图留在全局，转换为普通 Query，保留名称、in 条件、更新时间倒序、字段及条数。旧 limit=null 实际仅取 100 条，迁移显式设为 100，并可携兼容渲染标记。原先存于聊天 metadata 的对话宏迁入所属记忆空间，用户可见名称仍为“对话宏”；原 metadata 在完成可恢复迁移前保留。

同一空间的不同旧对话可能有同名不同定义，合并后无法同时保持各自独立覆盖。本轮明确采用冲突处理：同名相同定义复用，未占名定义幂等导入，同名不同定义不自动覆盖或合并。保留全部旧定义及来源，只对发现冲突的对话名称设置迁移待处理状态，该名称暂时展开为空并展示冲突，不清空共享空间中已有宏，也不影响其他对话读取它。

用户可显式选择保留空间现有定义、覆盖为旧定义，或改名导入；覆盖会影响共享空间，改名后需要更新该对话的宏引用。非冲突名称可完成迁移并记录完成状态，重复打开不重复生成身份。该门禁只为迁移保留，处理完成后删除，不延续为第二套对话宏作用域。绑定到其他空间的旧对话首次打开时按其实际绑定迁移，不能根据名字猜目标空间。

旧格式中损坏定义和未知版本保留原始数据、明确报告，不能静默丢弃后露出低层同名宏。新空间协议、备份、镜像和预设分别显式升级，旧文件缺少对话宏视为旧版本空集合，不能把未知新版本当旧文件读入。

### 9.2 整块废弃 memoryRecall

移除旧 `{{memoryRecall}}` 专用宏注册、自动召回设置入口、独立聊天开关与配置读写、视图绑定、召回结果状态、服务及 runtime 接线。旧流程专用的生命周期处理、调试入口和测试随功能删除；新统一宏求值需要的通用 ST 等待与取消机制由新流程承接。既有手动向量检索、向量索引与 embedding 连接继续保留，新的 Query semantic／SQL 语义源承担提示词召回能力。

不保留旧宏别名、兼容求值器、条件动态关联或自动转为新宏的迁移器。升级后不读取、不执行旧自动召回配置，也不因旧 enabled 产生请求；设置保存与旧文件恢复时剔除可识别的旧召回配置键，不影响其他元数据、记忆数据或索引。备份和镜像的新格式不再携带旧配置，导入旧文件也不恢复这项功能。

旧提示词中的 `{{memoryRecall}}` 调用失效，升级说明要求用户自行创建表达式对话宏或全局宏并替换引用；插件不自动修改角色卡、提示词预设或世界书，也不注册一个返回空值的兼容占位宏。移除旧专用宏名占用和相应保留规则。

重生成、swipe 和续写按新流程每次统一计算，迁移说明提示相较旧流程请求次数可能增加。对话宏的定义和启用状态随当前空间保存与共享，整个新体系只有每个宏自身的启用开关。
