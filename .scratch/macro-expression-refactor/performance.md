# 宏表达式求值性能测量

2026-10-26，Windows，Node v24.18.0，真实 SQLite WASM，单次测量。使用求值器测试的同一记录结构，每条记录两个向量组，每个向量 1024 维；向量和查询向量由确定性公式在本地生成，无远端请求。SQL 最终 LIMIT 10，评分源保持全部记录。两种规模分别使用独立 Node 进程运行。

| 记录数 | 向量数 | 快照准备 | 源检查、完整评分及结果映射 | 评分关系物化与 SQL | 批次合计 |
| ------ | ------ | -------- | -------------------------- | ------------------ | -------- |
| 1,000  | 2,000  | 682 ms   | 449 ms                     | 49 ms              | 1,180 ms |
| 10,000 | 20,000 | 4,469 ms | 4,450 ms                   | 314 ms             | 9,233 ms |

两次均检查全部向量并获得 100% ready，分别生成 1,000 和 10,000 行评分关系。快照准备包含快照复制、读时显示计算与隔离 SQLite 数据库初始化；批次合计不含测试数据生成、WASM 模块冷启动、远端 embedding 等待和最终宏文本渲染。测量端口仅在外部记录阶段耗时，未加入生产 profiling。

| 记录数 | 数据就绪后的基线 heap / RSS | 观测最高 heap / RSS | 进程最高 RSS |
| ------ | --------------------------- | ------------------- | ------------ |
| 1,000  | 26.75 / 114.75 MiB          | 68.01 / 167.79 MiB  | 170.23 MiB   |
| 10,000 | 174.94 / 358.05 MiB         | 278.28 / 463.22 MiB | 465.50 MiB   |

heap 与 RSS 在实际事件循环让出点按 5 ms 间隔采样，并在快照和 SQL RPC 边界补充采样；同步片段中的瞬时 heap 峰值可能未被观测。进程最高 RSS 取 Node 的 `process.resourceUsage().maxRSS`。基线已经包含预置的完整记录和向量。Node heap、进程 RSS 与浏览器 Worker/WASM 的内存分布不同，这些数据不能充当浏览器内存峰值。

测量使用 60 秒截止时间，以便完整观察规模成本；生产仍使用 10 秒总预算。10,000 条记录在本机已接近该预算，加入网络等待、引用模板或其他工作后可能超时，本次测量不构成该规模必定在生产预算内完成的承诺。

在仓库根目录复现：

```powershell
node --expose-gc --experimental-strip-types .scratch/macro-expression-refactor/perf-evaluation.ts 1000
node --expose-gc --experimental-strip-types .scratch/macro-expression-refactor/perf-evaluation.ts 10000
```

脚本输出原始字节、阶段毫秒数、覆盖和进程最高 RSS；只引用仓库源码，没有本地外部资源或连接配置。
