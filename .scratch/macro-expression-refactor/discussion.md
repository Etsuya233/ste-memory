# 宏重构质询记录

日期：2026-10-26。参与者：主代理、GPT-6.1 Sol Medium、GPT-6 Astra Medium。使用 grill-with-docs、grilling 与 domain-modeling；依用户要求，质询在代理之间完成，用户未被要求逐项回答。前五轮为初稿历史，第六轮起按用户反馈复审；最新需求以 spec.md 为准，尚未实施。

## 第一轮：表达式、组合与持久化归属

主代理提出命名宏保存 Query/SQL、预设复制为对话宏、候选筛选后执行向量。Sol 同意命名入口和沿用 Query 算子，反对跨块隐式去重：人物摘要与详情即使是同一记录也可能提供不同信息。双方决定块内去重、跨块保留，召回块内多来源共享 Top K，各块依配置顺序输出。

核对代码后，主代理撤回预设直接复制对话宏的建议。当前预设应用先提交空间结构，再修改对话 metadata；共享空间的其他对话无法直接继承这份对话宏。双方选择新增空间宏，与结构一起提交，代价是增加一个作用域及扩展空间传输协议。Sol 指出局部覆盖仍然存在：应用预设不能删除其他对话的局部宏，必须保留并显示失效；当前对话继续沿用既有清理流程。

## 第二轮：候选与 SQL 身份

Sol 质询 SQL 聚合如何对应向量记录，提出每个 SQL 召回来源明确指定目标表并返回 `$record_id`。主代理接受；普通 SQL 聚合直接渲染，缺少合法身份的 SQL 召回整体报错。双方否决凭显示文本、表别名或行号猜记录，以及忽略坏行继续运行。

最初方案同时存在表达式分页、候选上限和最终 Top K，易造成多重隐含限制。双方将候选上限统一为 Query.limit 或 SQL 原文 LIMIT；缺省取全部候选，内部 100 条分页不影响业务范围。Top K 留在召回块，发生在排序后。Query 保留单排序字段及既有 AND 算子，不顺带加入新的查询语言。

Sol 指出同一记录由多个来源命中时可能有不同投影，双方决定来源只提供候选与组选区，输出投影由召回块按表统一管理。块内保留条件与组选区的配对，禁止先把记录和组分别合并再做笛卡尔组合。

## 第三轮：按用户补充取消预计算

用户补充“等到运算时再统一计算，不再预先计算”。双方据此取消后台轮询、变更后重建，以及跨生成复用；正常发送、重生成、swipe、续写均启动新批次。每批计算所有生效普通宏及显式启用的向量宏，宏同步回调只读取当次结果。同批相同查询文本与配置共享一次 embedding，跨批重新请求。

Sol 核对宿主源码，指出正常发送的 GENERATION_AFTER_COMMANDS 早于用户正文保存，生成拦截器又晚于部分宏展开。双方采用双入口方向：新用户消息在 MESSAGE_SENT 等待计算，重生成等在更早可等待阶段执行；STARTED 只建立操作归属。该接线属于源码推导，仍需真实 ST 验收。本次新用户输入中的宏在 MESSAGE_SENT 前已被宿主展开，明确不保障该提前位置取得当次结果，不能用旧结果填充。

用户没有要求扫描提示词按使用情况求值，宿主的世界书激活与同步宏接口也使这种判断复杂。双方选择统一计算有效普通宏，向量宏由每对话固定身份选择启用；即使未放宏也可能发生已启用查询，界面需要说明。较低层向量宏被同名高层遮蔽时挂起启用项，不把授权转给新定义。

## 第四轮：失败、预算与兼容

双方同意整宏原子发布、各宏独立完成。网络或配置失败使所属宏为空并可见，主生成继续，不保留上轮成功文本，不回落同名定义。部分索引可用允许检索并报告覆盖；零候选及阈值后零命中为正常空结果。总时限 10 秒、单 SQL 1 秒，候选超限报错，禁止静默只取前 100 条。

旧视图逐个迁成 Query 普通块，旧 limit=null 显式冻结为实际已有的 100 条。memoryRecall 继续保留原启用项与固定作用域绑定，兼容实现使用统一求值器并保留忽略展示 limit 的旧候选语义，避免悄悄把绑定改成不再更新的表达式副本。用户可以显式把兼容定义转换为自包含命名宏。生命周期按最新要求改成每次生成重新计算，文档明确费用和行为变化。

域词汇只增补本轮必要概念，不把尚未实施的提案写成既有事实。空间宏归属与生成时求值涉及真实取舍，记录为 proposed ADR；原 ADR 与用户已有未跟踪文件不覆盖。

## 第五轮：文档反例复审

Sol 复审初稿时指出，靠 SQL 编译检查证明表达式不含具体记录身份无法成立，记录身份可能经拼接或 JSON 运算构造。双方删去自动证明及字面值绝对禁令，统一保留用户表达式字面值并说明跨空间限制，系统生成的预设宏避免记录身份依赖。

Sol 同时指出各宏独立完成容易被理解为先完成先发布，与批次版本校验冲突。修订为先收集各宏状态、在全部完成或截止后统一复核并一次发布；普通宏错误只影响所属宏，版本变化则作废整批。原位显式恢复可以保留宏身份但撤销旧向量启用项，普通镜像加载保留已有选择；旧召回固定身份绑定在引用宏被改成多块或 SQL 后明确报错。10,000 行上限限定为主查询及候选返回行，显示引用补查仍受时间预算约束。

## 第六轮：用户质疑表达式与召回的分离

用户指出对话宏与空间宏承担同一用途，又质疑 Query／SQL 只筛选召回候选的方式。主代理与 Astra 重新回到原始需求，确认“SQL 只返回候选身份、外部 Top K 决定条数、外部投影决定输出”是代理引入的结构，不能当作已明确需求。

Astra 指出其具体问题：用户无法从自己写的 SELECT、ORDER BY 和 LIMIT 判断最终宏结果。把召回宏改名为普通宏选取方式仍未消除这种割裂。双方比较“候选表达式加外部召回”“向量搜索结果源”“相关度进入完整查询”，选择第三种。SQL 可以把完整评分关系作为 JOIN 的来源，Query 可扩展 semantic 和相关度字段；来源自身不提前取 Top K。

用户认可该方向，并要求继续核对其他方面、生成文档及补充实现思路。当前宏合并保存在空间中，作用域变为当前、全局、内置，不新增一层局部覆盖。

## 第七轮：函数示意与可实现的第一版接口

主代理与 Astra 比较了识别 semantic_scores 函数再改写 SQL、声明命名评分源再执行标准 SQL、自定义表值虚拟表三条路线。源码显示当前没有 SQL parser，SQLite 回调同步，Worker 串行所有 RPC；不能在 SQL UDF 中等待网络，也不能正则替换任意 SQL。

双方将首版确定为自包含的“sources＋sql”表达式。源只声明表、组、输入和关系名，最终字段、筛选、阈值、排序与数量全部留在 SQL。此前 semantic_scores(...) 示例暂不承诺实现，命名源路径不需要引入解析器或虚拟表。所有声明源都是执行依赖，未被 SQL 引用也可能产生请求，避免在没有依赖分析的前提下承诺短路优化。

评分源对每条有有效向量的记录提供最高组分与组 Key，不设 Top K。无有效索引形成空关系并报告覆盖，LEFT JOIN 因而可保留无分数业务记录；缺表缺组、非法输入和网络失败仍为错误。Query 使用单表、semantic 及 $similarity，跨表组合由 SQL JOIN／UNION 表达，不引入查询块。

## 第八轮：求值数据、请求与执行隔离

双方撤掉初稿“编辑记忆使整批作废”的要求，改为固定本批已提交记录输入，后续编辑留给下一批。Astra 指出 SQLite 与 IndexedDB 无跨库同瞬时快照，读到的新向量必须按本批记录及配置指纹校验，不能用实时 targets 配旧正文；显示引用也必须基于本批集合。embedding 请求配置要在内存固定，无法固定时连接修改取消受影响工作。

实现方向是独立 SQLite 只读求值会话，宿主异步取得 embedding 并分片评分，每宏通过单次内部 RPC 物化临时源、安装读权限、执行 SQL 并 finally 清理。现有检索服务已经截断 Top K，须复用或提取未截断评分步骤，不能用极大 K 代替。评分需实际让出事件循环，VM 时间预算不能代替主线程取消。

最终查询行数上限与评分源量分开，评分不受最终 10,000 行上限截断。批次内同文本和 profile 共享 embedding，跨批重新请求；普通宏和语义宏统一一个 enabled 开关。预设普通宏沿原状态，语义宏新副本默认关闭，停用仍占名以避免意外暴露全局内容。

## 第九轮：合并作用域、输出与迁移

Astra 发现多个旧对话共享空间且同名定义不同的真实迁移冲突，无法同时保留原局部覆盖语义。双方采用仅阻止所属对话冲突名称的迁移状态：保留旧数据，不覆盖空间现有定义，用户明确选择保留、覆盖或改名；非冲突名称可幂等导入。状态在处理完成后删除，不成为永久第二层宏。

旧 memoryRecall 暂作历史适配，继续维护原条件关联与组配对，转换为完整查询的等价计划并使用统一求值器。新表达式不提供跨宏递归或外部 Top K。重复 SQL 列名必须在保留列元数据时检测，不能等对象化后发现值已被覆盖；JSON 预算按完整行序列化，不能直接截字符串。

## 第十轮：新稿反例复审

Astra 对新稿做最终只读审阅，发现“没有有效向量就不检查连接”存在判定循环：已有向量的 profile 和指纹需要已选 profile 才能校验。修订为先校验表组及本地输入，无记录或无存储向量可免 profile；有存储向量先取得 profile，缺失则报配置错误，profile 下有效数为零才免 embedding。输入先检查 4000 本地上限，需要 profile 时再检查连接上限。

同时明确 SQL 保存对象包含 sources 与 sql，代码示例分开展示仅为阅读；SQL 普通宿主参数首版只提供 last_user_message，没有消息时绑定 NULL。旧 memoryRecall 对引用定义的兼容提取限定为普通单表 Query，改成 SQL 或加入 semantic／$similarity 都需要显式转换，防止忽略新条件。旧 enabled 在兼容期仍保存在原聊天配置，新当前宏才统一使用空间内 enabled；避免把历史例外重新扩大成第二套新宏启用名单。

## 第十一轮：用户确定命名与删除旧功能

用户明确将合并后的局部宏命名为“对话宏”，表示当前对话绑定空间中的宏；删除“当前宏”分区和单独“空间宏”层的提法。空间归属、预设复制及共享空间共享定义的规则保留。

用户同时要求整块废弃 memoryRecall。需求删除此前所有旧召回兼容计划，包括专用宏注册、设置、独立开关、绑定、运行服务、动态条件关联和转换器；旧配置不再执行，旧提示词需自行替换。新的表达式语义源提供召回，手动向量检索与索引继续保留。第十轮及以前关于保留兼容入口的内容仅为被撤销的讨论历史。

## 收敛与核查（最新）

最新设计树覆盖完整表达式、语义源接口、输入、空分数、组聚合、对话宏、预设、启用、输出、存储迁移冲突、统一求值及大致实现。真实 ST 接线、内存代价与评分性能属于实施验证，需求不将其写为已完成。此前的召回块、候选 SQL、外部 Top K、双局部作用域、修改即作废及 memoryRecall 兼容方案均已由最新需求替代。
