# 自动填表

Status: needs-triage

## 目标

在聊天进行过程中，根据待填楼层数量提醒用户或自动运行表格填写 Agent，按配置分批处理，并在失败后有限重试。用户可以通过排除当前 AI 楼层，避免刚生成、仍可能多次 Roll 的回复过早写入记忆表格。

本文记录需求与交互规则，供实现和验收使用。本次交付仅包含需求文档。

## 设置与会话覆盖

设置页提供全局默认配置，任务页提供相同配置项的会话覆盖。每项独立继承：输入框未填写时，以 placeholder 显示当前全局值；填写后覆盖该项，清空后恢复继承。选择框的未选择状态显示全局当前值，允许显式覆盖为关闭或否，不使用无法表达继承状态的复选框。页面不增加统一的覆盖开关或单独的「跟随全局」说明区。

| 配置项 | 取值与含义 |
| --- | --- |
| 运行模式 | 关闭、仅提醒、自动填表 |
| 触发间隔 | 正整数，待填楼层数量达到此值时触发 |
| 包含当前 AI 楼层 | 是或否，默认否 |
| 每批楼层数 | 正整数，每次 Agent 处理的楼层数量，与触发间隔独立 |
| 额外重试次数 | 非负整数，默认 2；0 表示失败后不自动重试 |
| 重试等待秒数 | 正整数，默认 10；每次失败后固定等待此时长 |

建议首次安装的全局运行模式为关闭、触发间隔为 10、每批楼层数沿用现有默认值 20。这三项初始值属于本文补充的产品默认值，供评审调整。

会话只保存显式覆盖值，全局设置变更后，未覆盖项随之更新。会话覆盖配置和自动填表暂停状态随对话保存，切换对话后分别恢复。暂停属于运行状态，独立于运行模式与继承关系。

## 楼层范围与触发

同步楼层沿用 ST 消息数组下标，从 0 开始。间隔和批大小均按全部消息楼层计算，包含用户消息与 AI 消息；同一楼层多次 Roll 不增加计数。

令 H 为当前对话范围内台账中状态为 processed 的最高楼层，A 为最新已完成的 AI 回复所在楼层。起点 S = H + 1；没有成功已填楼层时，S = 0。失败状态不算成功已填。初始化填表不产生楼层进度，不影响 H。

包含当前 AI 楼层时，终点 E = A；排除时，E = A - 1。排除当前 AI 楼层仍包含它之前的用户消息。AI 回复之后尚未得到回复的用户消息不纳入本次终点。

当 S ≤ E，且 E - S + 1 达到触发间隔时，处理完整闭区间 [S, E]。最高已填楼层之前的历史空洞不补填；更早的已填消息发生 Roll、编辑或删除时，不自动回滚记忆或重新填写历史。

每次 AI 回复完整结束后检查一次，流式输出过程中不触发。打开或切换到一个已就绪的聊天时也立即检查积压。无已完成 AI 回复、未保存对话或无可用记忆空间时不启动任务。重复完成事件和同楼层 Roll 不得为同一待填范围创建并发任务。

| 场景 | 预期 |
| --- | --- |
| 最高成功已填 #20，最新 AI #31，间隔 10，排除当前楼层 | 填 #21–#30，共 10 层 |
| 同上，包含当前楼层 | 填 #21–#31，共 11 层 |
| 已填 #0–#10、#20–#25，中间留空 | 从 #26 开始，忽略 #11–#19 |
| 待填 9 层，间隔 10 | 等待后续 AI 回复完成后重新检查 |
| 没有成功已填楼层 | 从 #0 开始计算 |

## 执行与分批

自动填表复用现有楼层填表任务、Agent 连接、提示词预设、清洗规则、批次提交、楼层台账和日志能力。自动、手动与初始化填表共享单记忆空间单活动任务约束。

触发时固定本次范围、分批大小及重试参数。例如 #21–#30、每批 4 层，依次处理 #21–#24、#25–#28、#29–#30，末批不足配置大小也执行。每批成功后，记忆变更与该批楼层进度一起原子提交。

任务运行期间产生新回复，先完成本次固定范围，再按最新进度和配置重新检查积压；未达到间隔时继续等待。手动或初始化任务占用空间时不并发启动，待其结束后重新计算范围。设置修改影响后续调度；切换为关闭或仅提醒时取消尚未执行的自动重试，已开始的批次沿用现有安全点停止能力。

## 重试、暂停与恢复

某批失败后，保留之前成功提交的批次，在等待配置时长后重试失败批次；成功后继续后面的批次。每个批次各自计算额外重试次数，最多尝试「1 + 额外重试次数」次。不得因自动重试而重新提交已成功批次。

参数非法、连接配置缺失等任务启动前即可发现的问题直接显示错误并暂停该会话的自动填表，等待用户修正；不消耗模型调用重试。执行中的批次失败按重试参数处理，等待期间显示剩余时间和当前尝试次数。

任一批次耗尽重试次数后停止本次执行，并持久化当前会话的自动填表暂停状态。后续新消息或重新打开聊天不会重新开启一轮自动尝试。用户主动取消自动任务或等待中的重试，也暂停该会话自动填表。

任务页显示暂停原因，提供手动重试与恢复自动填表入口。手动重试从失败批次继续，保持已成功批次；恢复自动填表清除暂停状态，并按最高成功已填楼层和当前有效终点重新检查。手动重试本身不隐式清除暂停状态。

补充交互约定：手动重试前重新读取最高成功已填楼层，原任务范围中不高于该楼层的部分跳过；剩余范围为空时提示已无需重试。剩余范围沿用原任务每批楼层数，采用当前生效的重试参数，重新计算尝试预算。此规则仅用于本功能产生的自动任务续跑，普通手动填表的重跑能力保持现有语义。

切换对话时停止原对话等待中的重试，并沿用现有任务的对话切换安全点停止机制。刷新页面后不恢复旧执行器或旧倒计时；保留已提交进度及显式暂停状态，聊天就绪后按正常打开检查规则处理。

系统因切换模式、切换对话或刷新而停止执行，不新增主动取消暂停。关闭或仅提醒模式生效后，当前自动任务在安全点停止，不再启动下一批；返回自动模式或重新打开未暂停的聊天时，重新计算范围并获得新的尝试预算。

## 提醒与任务页交互

仅提醒模式在达到间隔时显示「待填 #21–#30，共 10 层」一类通知。点击打开插件任务页并预填范围，由用户确认执行，不自动调用 Agent。点击时按当前进度重新计算，避免使用已过期范围；若已无待填内容，显示当前状态。同一待填起点的提醒保持一份，新增楼层更新范围和数量，避免逐条消息重复弹出。

自动模式显示任务开始、完成及最终失败通知。重试过程在任务页更新次数和倒计时，不为每次尝试重复弹通知。通知点击后进入对应对话的任务状态；切换对话不得展示或操作错误会话的任务。通知内容包含范围与必要的进度或错误信息，历史详情和日志沿用现有入口。

任务页同时呈现逐项会话覆盖配置、当前生效值、运行或等待重试状态、暂停原因及恢复入口。用户清空覆盖项后，placeholder 或选择框的继承占位立即更新为全局当前值。

## 验收场景

| 场景 | 验收结果 |
| --- | --- |
| 只覆盖每批楼层数 | 其余项继承全局；修改全局间隔后当前会话采用新间隔 |
| 会话显式选择关闭或否 | 覆盖全局自动模式或包含当前楼层；清空后恢复继承 |
| 排除当前楼层后反复 Roll | 当前楼层未写入，楼层计数不增长，不重复创建相同任务 |
| 10 层待填，每批 4 层 | 三批依次提交，最后一批 2 层 |
| 第 2 批失败后重试成功 | 第 1 批保持已提交，第 2 批重试，随后继续第 3 批 |
| 额外重试 2 次仍失败 | 失败批次共尝试 3 次，最终失败通知，会话进入暂停 |
| 暂停后收到新回复或刷新 | 保持暂停，直到用户明确恢复 |
| 仅提醒模式达到条件 | 只有提醒；点击进入任务页并预填，确认后才执行 |
| 手动填写了更高楼层 | 下次从当前最高成功已填楼层的下一层开始 |
| 任务运行期间新增楼层 | 当前任务范围不变，结束后重新检查新增积压 |
| 等待重试时切换对话 | 旧倒计时停止，不会向新对话提交原任务 |
| 同空间已有手动或初始化任务 | 自动任务等待，空闲后重新计算，不并发写入 |
| error 楼层高于最高 processed 楼层 | 起点仍为最高 processed 的下一层 |
| 多个批次分别失败 | 每批各自获得配置的额外重试次数 |
| 手动重试成功 | 会话仍保持暂停，点击恢复后才继续自动调度 |
| 暂停期间手动填了更高楼层再重试 | 跳过不高于当前最高成功已填楼层的部分 |
| 全局配置变更 | 已打开任务页的继承占位和生效值同步更新，显式覆盖值保留 |

## 实现边界与现有差异

现有手动重试会按原范围创建新任务，自动重试需要补充批次续跑语义，避免重放成功批次。现有任务页的未处理范围计算将 error 视为已经跑过，自动调度必须独立遵守本文的最高 processed 楼层规则。

楼层身份继续遵循 ADR st/0003 的消息数组下标约定，存储继续遵循 ADR st/0002 的分层约定。本需求不引入稳定消息身份、历史变更检测、历史空洞补填、已填楼层的 Roll 回滚、后台跨聊天执行或自动初始化填表。

实现参考：`src/features/fill-tasks/`、`src/ui/tasks/`、`src/features/settings/`、`src/infrastructure/sillytavern/chat-adapter.ts`。验证应覆盖调度的范围与互斥、批次重试、暂停持久化和设置继承；UI 验收覆盖占位值、通知跳转与仅提醒确认流程。
