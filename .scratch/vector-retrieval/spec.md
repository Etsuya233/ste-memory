## 3. 用户流程

用户打开面板“检索”，看到当前对话、记忆空间、连接配置身份和索引覆盖摘要。未绑定有效空间时，入口展示绑定指引，禁止请求。默认范围为当前空间内已启用且开启索引的表及其全部生效分组；面板同时列出未开启索引的表，避免误以为已检索整个空间。用户可选择部分表，并在每张表内选择分组，不增加字段条件编辑器。

用户输入自然语言查询，设置 Top K 和可选最低分，点击“搜索”。面板依次展示检查候选、生成查询向量、本地排序、完成或异常，并始终提供取消。输入时不自动请求，打开面板和调整结果展示也不请求。用户可手动把聊天内容复制进查询框，首版不自动读取待发送文本或拼接聊天历史。

结果展示实际执行的查询与范围、唯一记录列表、可用索引覆盖、耗时与远端调用次数。用户可展开命中原因、查看源记录及其现有字段证据／修订详情，也可前往现有向量管理入口补建或修正配置。补建与搜索是独立操作；补建完成后由用户再次搜索。

本次查询文本、表／组选区、Top K、阈值和结果只保留在当前页面的当前对话上下文，切对话重置，刷新后清空，不新增空间备份、镜像或表格预设内容。首版不增加命名检索配置库或搜索历史。

## 4. 查询输入、连接和兼容性

查询文本仅 trim 首尾空白，保留内部换行、大小写和标点；不得自动加表名、字段名、分组标签、查询前缀或 LLM 改写。空查询直接报错。查询长度上限取连接 maxInputChars 与 4000 字符中的较小值，字符计数与已有连接检查一致，界面说明字符数不等于 token 数。超长时要求用户缩短，不静默截断、不切片。

一条查询只为一个确定的活动 embedding profile 生成一次向量，供本次所有表／组使用。复用现有连接配置、请求格式、超时、错误分类和密钥存储方式，独立于查询 Agent 的聊天连接。任务开始固定 profile，真正发送时核对仍匹配；返回时再次检查版本，端点、模型或指定维度改变后丢弃旧请求，不把旧向量当作新模型结果。

沿用现有 profile.version，不新增模型修订标记或版本迁移。密钥轮换与超时修改不使向量过期。服务端在相同端点、模型名和维度下更换权重时，插件无法自动识别，用户需要通过现有强制重算功能重建相关索引；界面和帮助须说明这一限制。

候选同时要求模型、profile.version、实际维度及当前目标指纹匹配，不能仅凭维度或模型名认定兼容。维度未指定时以本次查询响应实际维度作为比较依据；不同维度的候选逐项排除并报告异常。零范数、非有限数值和非法向量同样排除；全部候选因此被排除时显示索引不兼容／异常，不能显示为正常的“无相关结果”。请求返回的查询向量非法时整次搜索失败。

首版不缓存查询向量。一次搜索结束后，再次提交搜索会重新请求查询向量，即使文本相同。修改范围、Top K 或阈值草稿不自动请求，点击搜索后按新参数重新执行；展开已经返回的结果只读取本次结果，不发请求。有效的记录向量仍按现有索引规则复用。

## 5. 范围与索引覆盖

范围由当前空间身份、所选表身份及各表所选分组身份确定。组名相同不会跨表合并；改名不改变身份。表停用、索引关闭、组被删除或字段配置失效时，明确显示原因；已显式选择的表／组失效后要求修正选择，不静默改成全空间搜索。默认“全部可检索表”随当前保存配置解释；手工选择时空表集合／空分组集合视为无范围，禁止请求。

首版只按空间、表和分组限定范围，不新增字段条件、条件组合或跨表条件编辑器。已有普通记忆查询与查询 Agent 的结构化能力保持原样。后续需要字段筛选时再复用现有条件契约，不为扩展提前增加设置或隐藏参数。

执行顺序为：校验表／组范围 → 读取范围内记录和向量 → 检查向量有效性 → 计算相似度 → 去重、阈值与 Top K。候选读取必须完整，不能把存储接口的单页结果当成全量，也不能先取 Top K 再排除范围外记录。显式选择失效时提示修正，不扩大搜索范围。

检索检查复用索引生成时的生效分组、实际输入和目标指纹规则，不另写一套近似判断。只读取当前合法、非空且指纹匹配的向量，不使用已过期索引。允许记录只有部分分组就绪；其有效分组参与搜索，其他组进入覆盖统计。强制重算失败但原向量仍匹配时，原向量可参与，并保留最近任务错误提示。

拟将索引目标输入中的引用显示统一为 Memory 已有读时显示语义，供生成与检索共同使用，结果展示的引用显示也保持一致。模板引用目标的显示变化须改变实际输入与目标指纹；存量向量在核对时自然成为待更新，无需搬迁数据库。自动表沿用自动补建，手动表只提示待更新。共享目标计算应批次复用读取和引用显示结果，避免检索逐条调用预览造成大量重复读取。

覆盖统计限定在所选表内的记录和所选分组，单位为记录 × 分组，展示有效／非空预期目标数，并分别列出缺失、过期、单目标输入异常和异常向量；空输入组单列且不计分母。所选表／组整体配置失效时在预检直接报错，显示配置问题，不计算貌似完整的覆盖率；合法分组中某条记录有无法解析的引用等问题时，才计单目标输入异常。任务失败、取消和重建中作为补充状态，避免与“缺失／过期”重复累计。用户能看见未检索的表／组及原因。

**首版决定：检索不等待索引生成，不隐式提交补建，不解除用户取消／失败／清除抑制，不自动重复搜索。** 有部分有效候选时按这些候选执行，并显著标注“部分索引，结果可能遗漏”；没有有效候选时先返回覆盖问题与操作入口，不发查询 embedding 请求。现有自动索引队列可以独立继续。

本次候选向量集合在预检完成时读取，覆盖统计带这一时点。查询等待和执行期间，新补齐的向量及相同目标指纹的强制重算结果不自动加入，也不使已有结果失效；提示“索引已更新，可重新搜索”即可。完成前后检查记忆／结构的已知变更状态，并核对所用目标仍有效；正文或配置变更、索引清除／删除使结果失效。这里仅保留一次搜索的读快照，不提供事务性索引发布或完整双份索引。

## 6. 相似度、去重与结果解释

使用本地余弦相似度 `dot(q,v) / (norm(q) * norm(v))`，无需预先假定向量已经归一化；有限浮点误差可将最终分数约束在 [-1, 1]。每个组单独计算分数，每条记录的排序分数取所选有效组的最高值。记录身份按空间、表、记录联合确定，一条记录在多组命中只返回一行；不按显示文本去重，名称相同的两条记录仍保留。

先合并记录，再应用最低分（含等于），最后取记录级 Top K。Top K 默认 10，允许整数 1–50。最低分默认关闭；开启时为 [-1, 1] 内有限数值。分数不代表事实可信度或正确概率，跨模型、跨查询不作绝对比较；未设置阈值时低分结果也可出现。比较使用完整精度，展示可保留四位小数。排序按分数降序，同分按表 position、表身份、记录身份稳定排列，不按更新时间打破平分。

同一记录保留全部有效组分数以供展开，突出最高分的“获胜组”；同分组按表级分组配置顺序、再按组身份确定唯一获胜组。其他组在结果详情供诊断。多组取最大值会增加多组记录撞高分的机会，首版接受这一简单取舍，用户可缩小组选区；暂不加权或按组数修正。

每项结果包含排名、记录当前显示文本、表名／Key、组名与组分、命中字段及其用于向量输入的文本、索引更新时间、记录身份和“查看记录”入口。解释使用“该记录的近况组余弦分数 0.8123，包含姓名、地点、状态”等可核验信息，不生成“为什么一定相关”的 LLM 解释或伪造关键词高亮。

结果显示当前保存的记忆内容，字段引用按现有读时显示规则解析，证据和修订沿用源记录详情；搜索范围中的记忆结论仍可能需要用户核对。结果不自动展开原聊天全文、引用目标全部字段或修改历史内容。查看证据楼层时沿用现有不可定位提示。

## 8. 调度、取消与结果时效

用户已确认：查询与索引 embedding 独立调度，允许同时请求。索引继续串行执行，保留当前手动索引 > 其他空间手动索引 > 当前自动索引 > 其他空间自动索引的顺序；查询使用独立请求，不进入索引队列。本页分别保留一个活动查询请求和一个活动索引请求，两者互不抢占。交互检索不伪装成记录向量任务，不写入 recordVectors 或向量任务历史；状态在检索面板显示。

索引正在请求时，查询通过预检后即可发出，无需等待该索引请求结束；查询运行期间也不暂停索引队列。取消或替换查询只影响查询，取消索引任务只影响对应任务。查询网络超时复用连接 timeoutSeconds，面板显示请求状态、耗时和取消入口。总耗时拆为本地检查、远端请求和本地排序，不只统计 fetch。

同一页面仅保留一个活动检索。相同查询／参数在运行期间的重复点击不新发请求；提交不同查询时取消前项，最后提交的请求才可更新搜索结果。已结束后再次提交则发起新的搜索，不复用查询向量。编辑查询或范围草稿不触发新请求；已显示结果一直标注其实际参数。取消不取消索引任务，不为索引建立取消抑制；远端已经收到的请求仍可能计费。取消后即使服务忽略 AbortSignal，迟到响应也不能更新结果。

切 chat、绑定变化、当前空间记忆／结构变化、所选范围索引清除／删除或 profile 改变使活动检索失效；尽可能 abort，并以运行代次、真实 chat 身份、空间身份、参数和已知数据版本检查迟到结果。纯索引新增与同指纹替换按第 5 节保留候选快照。即使切走再切回同一个 chat，旧请求也不恢复。切 chat 或绑定变化时清空搜索状态；其他变更后可保留标注为“已过期”的只读结果供对照，不能当作当前结果。发生连续正文变更时不无限重启查询。

查询与索引各自处理错误，不新增共享故障阻塞状态。查询鉴权失败、连接失败或超时只在搜索页报错，不暂停索引队列，也不建立索引目标失败抑制；索引继续沿用已有错误处理。索引自身的阻塞不禁止用户显式发起查询，查询成功也不自动解除索引阻塞。搜索失败后只在用户再次点击时重试，没有后台自动重试或网络探测。已有向量的只读搜索不受索引写入容量阻塞影响，查询响应也不需要落库。

| 所选表内无记录 | “所选表暂无记录” | 更换表或添加记忆；不发请求 |
| 全部所选组为空输入 | “所选记录的分组均无内容”，空组单列 | 调整分组字段或记录内容；不发请求 |
| 缺失／过期／部分失败 | 就绪覆盖、缺失及异常明细，已有结果标注可能遗漏 | 跳转补建／重试／修正分组；不等待、不隐式生成 |
| 全无有效索引 | “当前范围暂无可检索索引”及具体缺失／过期原因 | 补建后手动重搜；不发查询请求 |
| 全部向量维度或数值异常 | “索引不兼容／异常”及数量 | 检查连接、模型和维度后重建；已发查询才能发现的维度问题计入本次调用 |
| 查询连接缺失 | 配置指引 | 设置现有 embedding 连接；不悄悄切聊天连接 |
| 鉴权、网络、CORS、限流或服务错误 | 原因分类、可读错误和一次调用状态 | 修正连接／稍后显式重试，不自动调用聊天 LLM 或关键词检索 |
| 查询太长／服务拒绝输入 | 当前长度、本地上限或服务错误 | 缩短查询；本地超限不发请求 |
| 合法候选均低于阈值 | “没有达到最低分的记录”，同时展示候选量及覆盖 | 降低／关闭阈值或换问法；不拿旧结果填充 |
| 取消／切对话／资料变更 | 已取消／已失效，迟到结果被丢弃 | 按当前上下文重新搜索；取消自身不删除已保存向量 |

搜索失败和正常空结果须按本次请求显示，不能拿历史命中填充。保留供对照的旧结果必须明确标注旧查询和过期状态，避免误认为本次命中。

## 10. 延迟、调用与效果验证

每次提交搜索至多新增一次查询 embedding 请求；没有连接、输入非法、预检无有效候选或仅展开结果详情时不发请求。一次搜索结束后再次提交，即使文本相同也重新请求，不使用查询向量缓存。表数、组数和 Top K 不增加单次搜索的远端请求数。费用说明区分本次查询与独立运行的索引请求，取消不承诺免除已发请求费用。查询全文仅按连接设置发往 embedding 端点，不额外附带整段对话、角色卡或记忆表正文，不记录密钥。

先按当前空间、表和分组缩小候选，再在本地线性计算；保持可取消，并在扫描批次间让出主线程。不得把其他空间全部向量载入后才筛选，也不因存储分页遗漏候选。暂不引入常驻向量缓存、Worker、ANN 或新存储服务。结果和诊断仅页面内保留，不新增全文检索日志或备份格式；用户可使用现有记录备份维护验证样本。

验收使用实际记忆样本，事先写下问题和预期相关记录，检查范围是否准确、多组是否去重、相关记录能否找到，以及结果能否说明命中来源。包含人物背景／近况、同名记录、相关事件、部分索引和无关查询，具体样本数量不预设。相关性由人工判断，不能用算法自身排名作为正确答案；阈值关闭时无关问题也可能返回低分结果，应核对提示和最低分设置是否有效。

在目标浏览器上记录样本规模、本地检查与排序耗时、远端请求耗时、总耗时，以及搜索期间页面是否可操作、取消是否有响应。先报告实测结果和发现的问题，不设固定命中率或毫秒级达标线。效果不佳时先检查分组输入、连接适配和查询表述；性能问题先定位读取、引用解析与扫描成本，再决定是否需要额外优化，不提前引入复杂设施。

## 11. 验收场景

| 场景 | 通过标准 |
| --- | --- |
| 基本搜索 | 一次点击只发一个查询请求；跨所选表排序，返回 K 条以内唯一记录，可打开源记录 |
| 当前空间隔离 | A 的查询、索引和结果不混入 B；没有“全部空间”选项 |
| 多表同名组／同名记录 | 按真实身份限定组；同名不同记录保留，多组同记录仅一行 |
| max 与平分 | 已知向量样本按最高组分排序，同分顺序稳定，Top K 按记录计数 |
| 阈值边界 | 等于阈值保留，非法阈值拒绝，完整精度比较；关闭阈值不会宣称结果必相关 |
| 范围与完整候选 | 未选表／组中的高分向量不参与；候选超过单页容量仍完整读取，再统一排名 |
| 范围失效 | 表／组／字段被删除或停用后明确提示，要求修正选择或索引配置，不扩大搜索 |
| 未建与部分索引 | 全无有效索引零查询请求；部分就绪可搜并显示覆盖，不触发补建 |
| 最新输入与引用 | 修改来源值或引用显示后旧指纹不参与；搜索结果使用当前读时显示文本 |
| 模板引用缓存变化 | 引用目标模板依赖的其他记录变化而缓存 displayText 未改时，共享输入计算仍发现新显示文本，旧向量待更新，结果不会用新值冒充旧向量命中原因 |
| 重建失败保留有效索引 | 强制重算失败但旧记录向量仍有效时可检索，任务错误与就绪状态并存 |
| profile 隔离 | 相同维度但端点／模型或现有 profile.version 不同的向量不混搜；改密钥不使全部索引过期 |
| 沿用现有模型身份 | 不新增修订标记设置；端点／模型／指定维度变化使旧向量不兼容；同名模型换权重需用户强制重建 |
| 维度与坏向量 | 局部异常可定位并排除，全异常不报告正常空结果；非法查询向量失败 |
| 查询长度与重复搜索 | 超长不截断、不发请求；搜索结束后再次提交相同文本或修改 K 再提交，都重新生成查询向量；仅展开详情不请求 |
| 查询与索引并发 | 索引请求尚未结束时查询可以发出，查询期间索引可继续执行下一项；索引保持原四档顺序，各自取消互不影响 |
| 取消与替换 | 取消只影响该查询；新查询替换旧运行，迟到响应不能更新结果 |
| 对话切换竞态 | A→B→A 或两个 chat 共用空间，旧请求都不能回填；切对话清空搜索状态 |
| 数据变化 | 当前空间正文／结构变化使搜索失效，其他空间变化不影响；补建新增及同指纹向量替换保留搜索结果并提示时点；所选范围清除／删除索引则失效 |
| 宏推迟范围 | 不新增检索宏、发布入口、宏预览或宏预算设置；搜索结果不注入提示词，已有记忆宏保持原有行为 |
| 独立错误处理与容量 | 查询失败不改变索引阻塞，索引阻塞不禁止显式查询，查询成功不解除索引阻塞；不自动重试，本地写入容量阻塞不误禁只读检索 |
| 效果与性能 | 用实际样本核对预期记录和来源，报告样本规模、本地／远端／总耗时及交互问题，不设固定数量、命中率或耗时门槛 |
| 简化范围 | 不新增字段条件编辑器、模型修订标记、查询向量缓存或共享故障阻塞状态 |
