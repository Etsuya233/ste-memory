# 表格预设需求文档

状态：待审阅  
日期：2026-10-18  
范围：ste-memory 插件

## 1. 背景与目标

当前插件首次为对话创建记忆空间时，会安装固定的 8 张系统表。设置中的重置操作也会恢复这套固定结构，表格界面对系统表存在编辑限制。

本需求引入表格预设，让用户保存和复用不同的表结构，并选择新空间的默认预设。同时废弃系统表身份，空间中的所有表格采用统一的编辑与使用规则。

目标：

1. 将当前默认表格整理为系统自带预设，保留现有结构与填写规则。
2. 支持从当前空间保存用户预设，并管理预设。
3. 支持指定新空间默认预设。
4. 支持清空当前空间后应用指定预设，并在一次确认流程中提供备份。
5. 预设与空间独立维护，任何预设变更均不自动修改已有空间。

## 2. 术语与核心规则

| 术语 | 定义 |
| --- | --- |
| 表格预设 | 一整套可复用的表结构、字段、填写规则、引用关系和显示策略，不包含记忆记录。界面统一使用“表格预设”，不混用“表格模板”。 |
| 系统自带预设 | 插件提供的固定预设，不可删除、重命名或覆盖，可复制为用户预设。 |
| 用户预设 | 用户保存的结构副本，可重命名、覆盖、删除和设为默认。 |
| 默认预设 | 创建全新记忆空间时采用的全局预设，初始为系统自带预设。 |
| 应用预设 | 清空当前空间的结构与记忆数据，然后复制目标预设重新初始化空间。 |
| 初始化来源 | 最近一次创建或应用时使用的预设来源信息，仅用于说明，不建立实时关联。 |

核心规则：

- 设置默认预设只影响以后创建的全新空间。
- 应用到当前空间不会同时修改默认预设。
- 编辑或删除预设不会改变已有空间。
- 编辑空间中的表格不会反向更新预设。
- 应用预设使用执行时选定的已保存预设内容，本次应用全过程使用同一份内容。
- 每个空间拥有自己的表格与字段 ID；预设不保存来源空间的实体 ID。

## 3. 本期范围

### 3.1 包含

- 系统自带预设。
- 用户预设的保存、重命名、覆盖、删除与结构预览。
- 默认预设设置。
- 新空间根据默认预设初始化。
- 当前空间应用预设与按同一预设重新初始化。
- 一次确认流程中的备份与应用。
- 取消系统表身份及相关界面限制。
- 初始化来源信息的保存、展示，以及随空间备份、镜像和恢复保留。
- 应用预设时的任务停止、数据清理和界面同步。

### 3.2 不包含

- 已有表格记录向其他预设的数据迁移、字段映射或合并。
- 预设变更向已有空间自动同步。
- 预设版本管理、差异比较及空间修改状态追踪。
- 独立的预设表结构编辑器；本期通过空间表格编辑能力配置结构后保存。
- 预设文件导入导出、共享市场、角色卡绑定或按角色自动选择预设。
- 预置记忆记录、自动重新填表，以及恢复被清空数据的撤销功能。

不进行表格记录迁移，不代表省略删除系统表身份所需的存储格式调整；具体格式调整属于实施设计，不在本文制定历史数据迁移方案。

## 4. 预设内容

### 4.1 系统自带预设

系统自带预设命名为“系统默认”，以当前插件实际默认内容为基准，包含人物、人际关系、地点、物品、剧情、伏笔、待办和世界状态共 8 张表。

保留各表当前的字段定义、Prompt、选项、校验规则、引用关系和显示策略。本需求不同时采用其他文档中的表结构修订方案。

系统自带预设永久可用。插件升级改变其内容时，仅影响之后基于该内容初始化的空间，已有空间保持原样。

### 4.2 用户预设保存内容

| 层级 | 内容 |
| --- | --- |
| 预设 | 稳定 ID、名称、说明、创建时间和更新时间。 |
| 表格 | Key、名称、描述、填写 Prompt、启用状态、顺序及显示策略。 |
| 字段 | Key、名称、类型、填写 Prompt、必填、启用状态、顺序、选项、长度和格式校验规则，以及引用目标。 |

保存当前空间的全部表结构，包括停用的表和字段。应用后保留这些启用状态。

引用目标通过预设内的表 Key 表达；显示策略中的字段引用通过字段 Key 表达。创建空间实例时生成新的 ID 并转换引用。通用创建逻辑不得写死人物表或人际关系表的特殊显示行为。

预设不保存记录、证据、历史、填表任务、同步进度、问答历史、全局视图、对话级宏、Agent 提示词预设或连接设置。

## 5. 预设管理

预设库和默认选择属于全局插件设置，不随当前对话切换。

### 5.1 另存为预设

在有活动记忆空间时，提供“将当前表结构另存为预设”操作。

1. 用户填写名称和可选说明。
2. 界面提示“仅保存表结构和填写规则，不包含记录；空间备份请使用导出备份”。
3. 保存执行时当前空间的完整结构副本。
4. 始终创建新的用户预设，不覆盖已有预设，不自动设为默认，不修改空间初始化来源。

预设名称去除首尾空白后必须非空，且在预设库中唯一；“系统默认”名称保留给系统自带预设。

### 5.2 重命名与覆盖

- 用户预设可以修改名称和说明。
- 提供独立操作“用当前表结构覆盖”，明确目标预设，确认后替换其结构内容。
- 覆盖保留预设 ID，因此默认选择不变。
- 覆盖不影响任何已有空间。
- 系统自带预设不提供上述修改操作。
- 复制系统自带预设时，生成新的用户预设，内容与该预设一致。

### 5.3 删除

- 用户可以删除用户预设，确认文案说明已有空间不会受到影响。
- 删除当前默认用户预设时，在同一次设置更新中将默认选择改为系统自带预设。
- 系统自带预设不可删除。
- 已有空间中的来源名称快照继续保留，不要求来源预设仍存在。

## 6. 设置与交互流程

设置页增加“表格预设”分组，分别展示新空间默认设置、当前空间应用区和预设管理区。

### 6.1 新空间默认设置

- 展示当前默认预设，允许选择预设并保存。
- 说明“仅影响之后创建的全新记忆空间”。
- 保存不弹出清空确认，不改变当前空间。
- 无活动对话或记忆空间时，仍可管理预设与默认选择。

### 6.2 当前空间应用区

- 展示当前空间名称及“初始化自：预设名称”。
- 来源信息不代表当前结构与预设完全一致；不显示“当前使用”或“已同步”等文案。
- 尚无来源信息的空间显示“初始化来源未记录”，不推断其来自当前默认预设。
- 提供目标预设选择与只读预览，预览包含说明、表名、字段数量及字段定义和填写规则详情。
- 选择目标仅改变界面草稿，不写入空间、不修改默认选择、不触发清空确认。
- 点击“应用到当前空间”后进入确认流程。
- 目标 ID 与初始化来源 ID 相同时，允许执行，按钮和确认标题使用“按此预设重新初始化”。
- 不通过比较预设 ID 判断空间结构相同，不因空间没有记录而跳过确认。
- 无活动空间、插件关闭或空间正在重建时，应用操作不可用。

### 6.3 一次确认与备份

每次点击应用后出现一个确认框，包含当前空间名称、目标预设名称、删除范围、聊天正文保留说明，以及备份提醒。推荐文案：

> 应用「目标预设」到「当前空间」？
>
> 当前空间的全部表结构、记录、修订历史、证据、填表任务、同步进度和问答历史将被清空，当前对话级宏也将被清除。空间将按所选预设重新创建，对话文件中的记忆镜像将被覆盖。聊天正文、全局设置和预设库保留。
>
> 请先备份当前记忆空间，此操作无法撤销。

确认框提供：

| 按钮 | 行为 |
| --- | --- |
| 取消 | 关闭确认框，当前空间内容保持原样。 |
| 备份并应用 | 先执行空间备份导出；导出流程成功后自动应用，无第二次清空确认。 |
| 直接清空并应用 | 直接执行应用，不额外要求用户确认已备份。 |

备份取消或失败时不执行清空，保留确认框并允许重试或取消。浏览器只能确认导出流程完成，界面不得宣称已经核实文件落盘。

备份内容必须能够恢复本次将被删除的持久化空间内容，包括实际表结构、记录、证据、修订历史、任务、进度、初始化来源以及当前对话级宏。若现有空间备份格式缺少上述内容，需在实施时补齐。页面内存中的问答历史不纳入持久化备份。

“备份并应用”应保证备份后、重建前不会再有旧任务提交数据，防止出现最后一次写入未被备份便被清空的情况。

### 6.4 执行与结果

- 操作开始后禁止重复提交，确认目标与空间保持固定，切换对话不得让操作作用到新对话。
- 停止目标空间的进行中填表写入，并确保已停止的旧任务无法在重建后提交。
- 重建时保留空间身份和对话绑定，替换空间内部结构和数据。
- 持久化重建作为一个整体提交；失败保留原结构、记录等持久化内容，不出现半初始化空间。
- 任务为执行操作而发生的停止允许保留；失败后不自动重启任务。
- 成功后更新初始化来源、刷新表格和设置展示、重建宏快照，并同步当前对话的记忆镜像。
- 宏或镜像同步失败时明确报告同步失败，不把已提交的重建描述为未发生，也不自动再次清空空间。

## 7. 全新空间初始化规则

沿用现有创建时机，以“确实需要创建全新记忆空间”为条件，不额外提前创建空间。

| 场景 | 处理 |
| --- | --- |
| 对话首次创建记忆空间 | 复制当时默认预设，记录初始化来源。 |
| 打开已有绑定的对话 | 继续使用已有空间，不应用默认预设。 |
| 从记忆镜像或备份恢复 | 使用恢复内容的实际结构与数据，保留其中的初始化来源。 |
| 分支选择克隆原空间 | 克隆来源空间实际结构与数据，保留来源说明。 |
| 分支选择创建全新空间 | 使用当前默认预设。 |

初始化过程使用同一份预设内容。只有空间结构和引用关系全部创建完成后，才视为初始化成功并发布绑定；失败沿用现有空间创建失败的回收语义。

## 8. 应用预设的数据处理范围

| 数据 | 处理 |
| --- | --- |
| 当前空间身份与对话绑定 | 保留。 |
| 当前空间全部表格、字段和显示策略 | 删除后按目标预设重新创建，包括自行新增和修改过的结构。 |
| 记录、修订历史、证据 | 清空。 |
| 当前空间填表任务、同步楼层进度 | 停止进行中写入，清空任务和进度。 |
| 当前空间页面内存问答历史 | 清空。 |
| 当前对话级宏 | 清除，避免保留针对旧结构的局部配置。 |
| 当前对话中的记忆镜像 | 成功后同步为重建后的空间内容，不继续保留旧记录。 |
| 初始化来源 | 更新为本次应用的预设 ID、名称快照和应用时间。 |
| 聊天正文、角色卡、世界书 | 保留。 |
| 全局设置、全局记忆视图、预设库、Agent 配置 | 保留。 |
| 其他对话与记忆空间 | 保留。 |
| 通用日志 | 保留，继续遵循现有日志保留规则。 |

全局记忆视图是插件级配置，不因重建一个空间被删除。新结构不满足其表或字段要求时，沿用现有配置错误展示与求值语义。

当前实现中的对话级宏存储在对话元数据中。清理对话级宏与更新镜像必须针对本次操作所属对话，不能清理切换后另一个对话的元数据；具体跨存储同步方案在技术设计中说明。

## 9. 废弃系统表

- 空间表格不再区分系统表与自定义表，移除对应身份及其行为分支。
- 所有表格统一支持编辑、删除、增删字段、启停和显示策略修改，继续遵守通用引用与数据一致性约束。
- 移除“系统表”“自定义”“系统表只读”等分类和限制文案。
- 系统自带预设生成的表格也遵循统一规则。
- 表格顺序通过显式顺序表达，取消系统表优先等身份排序。
- 填表 Agent、查询、宏、备份、克隆和镜像读取空间实际结构，不能要求固定存在某张默认表。
- 现有“恢复系统默认 8 张表”的重置入口统一为应用预设流程，不保留另一套固定系统表重装行为。
- 现有“清除全部记录、保留表结构”入口继续保留，不改变初始化来源，也不重新应用预设。

## 10. 实施约束

本节记录必须达到的结果，不规定具体类名、函数名或数据表布局。

1. 预设管理、结构实例化和空间维护的职责需清晰；界面不逐表编排重建步骤。
2. 首次创建与应用预设共用结构实例化规则，引用和显示策略在空间内部完整建立。
3. 删除旧数据、新建结构、清理任务进度和保存来源等数据库变更需要原子提交。
4. 实施前核实现有任务停止机制，证明旧任务无法在重建后写入。
5. 明确 IndexedDB、对话元数据及页面内存之间的提交和同步顺序，区分重建失败与重建成功后的同步失败。
6. 来源信息随备份、克隆和镜像保留。恢复依赖实际结构，不依赖本地预设库中存在来源预设。
7. 更新领域词汇、原系统表说明及相关测试，使其与新的统一表格规则一致。

## 11. 验收标准

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| AC-01 | 初次使用 | 默认选择“系统默认”；该预设不可删除、重命名和覆盖。 |
| AC-02 | 基于系统默认创建空间 | 生成当前实际默认的 8 张表及完整规则，表格全部可按统一规则编辑。 |
| AC-03 | 将用户预设设为默认 | 当前空间不变，后续全新空间采用该预设。 |
| AC-04 | 删除默认用户预设 | 默认选择自动改为系统默认，已有空间不变。 |
| AC-05 | 另存当前结构 | 创建独立用户预设，包含停用结构，不含记录，不改变默认选择。 |
| AC-06 | 覆盖或重命名用户预设 | 预设 ID 保持，已有空间内容不变。 |
| AC-07 | 仅切换预览选项或取消确认 | 当前空间、初始化来源和默认选择均不变。 |
| AC-08 | 应用其他预设 | 一次确认后按文档范围清空并重建，空间身份和绑定不变。 |
| AC-09 | 同一预设重新初始化或应用到空白空间 | 操作可执行，仍显示完整确认流程。 |
| AC-10 | 备份并应用 | 先完成导出流程再应用，无第二次清空确认；备份可恢复约定的持久化内容。 |
| AC-11 | 备份取消或失败 | 不清空、不应用，确认框允许重试或取消。 |
| AC-12 | 原空间存在运行中填表任务 | 备份与重建期间无遗漏的旧提交，重建后旧任务无法再写入。 |
| AC-13 | 数据库重建中途失败 | 原持久化空间内容保留，无半初始化结构，不更新来源为成功。 |
| AC-14 | 应用期间切换对话或重复点击 | 只操作原目标空间一次，不改变新对话的数据或元数据。 |
| AC-15 | 镜像同步失败 | 明确提示同步失败，已提交空间不再次清空、不被旧镜像恢复覆盖。 |
| AC-16 | 预设含跨表引用和组合显示策略 | 新 ID 正确映射，引用局限在新空间，显示策略正常工作。 |
| AC-17 | 删除来源预设后打开、备份或恢复空间 | 实际结构与记录仍可使用，来源名称快照仍可展示。 |
| AC-18 | 恢复、克隆和分支新建 | 按第 7 节规则处理，不意外套用当前默认预设。 |
| AC-19 | 应用后检查关联配置 | 当前对话级宏和问答历史清除，全局视图及其他对话保留。 |
| AC-20 | 清除记录、保留结构 | 保留用户修改过的结构与初始化来源，不套用预设。 |

## 12. 审阅说明

本文整理已讨论的产品规则。具体界面排版、存储格式以及跨存储同步方案在实施设计中细化；实施阶段不得默认扩大清理范围或增加预设自动同步行为。
