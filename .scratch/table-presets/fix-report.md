# 表格预设复核与修复报告

日期：2026-10-18

修复基准：`69a5c472176329c5dd71faae8ab7077b9028211c`

## 复核结果

原审查中的六项均有实际触发路径。本次针对已确认问题修复，没有重做表格预设架构，没有进行表格记录迁移。

| 问题 | 修复 |
| --- | --- |
| 确认后切换对话，备份与清理使用了新对话 | 确认框固定空间 ID、对话身份和预设内容。备份、停止任务及应用前核对目标，身份或绑定变化即拒绝清空。重建中途切换时不触碰新对话的宏或镜像，结果明确报告同步未完成。 |
| 触发下载就认为备份完成 | “备份并应用”使用文件保存器，等待内容写入且文件关闭成功。用户取消返回未完成，写入失败明确报告，均不进入清空。 |
| 镜像历史开关裁掉安全备份中的历史 | 操作前备份强制包含完整修订历史。普通手动导出的既有历史设置继续保留。 |
| 镜像 kick 仅排队却被认为同步成功 | 新增显式重建写回方法，串行等待实际镜像元数据写入，失败向应用流程传播；显式重建可覆盖旧 LWW 镜像。普通轮询防抖和 LWW 规则保持原语义。 |
| 克隆或恢复出无执行器的 running 任务 | 四条克隆、恢复路径将非终态转换为 interrupted，保留任务历史，源任务不变。 |
| 删除所选预设后静默应用系统默认 | 未知 ID 明确报错，失效应用目标显示待选择并禁用应用。删除全局默认用户预设后自动选择系统默认的需求保持。 |

同时修正两处相关行为：打开和取消确认框不再提前中断任务；通过同步 ref 阻止连续点击重复执行。备份与应用的错误统一显示“操作失败”，避免把保存失败误称为重建失败，或者错误承诺原数据已回滚。

8. 390 像素宽视口下完成交互；页面没有未处理异常。

补充单元测试覆盖原生保存函数的取消、不支持、写入失败和关闭等待；镜像立即写回、异常传播、较新旧镜像覆盖和同步期间切换；真实 Dexie 仓储的四条任务恢复路径。

## 范围与实际限制

- 未操作真实记忆空间、未部署、未发布。
- “备份并应用”需要浏览器提供文件保存器。缺少该能力时明确报错，禁止借助普通链接下载继续执行清空。
- 重建提交后如果切换对话，会明确报告原对话同步未完成，不向新对话写入原空间的数据。
- ST 的持久化入口仍为 `saveMetadataDebounced`，宿主没有提供文件落盘确认。立即同步保证镜像元数据更新及同步错误传播，不声称已经核实 ST 文件落盘。
