# 宏作用域：全局 + 聊天 Scope + 内置宏

Feature spec。基于 grilling session 2026-08-30 设计决策。

## Problem Statement

当前记忆宏系统只有一个全局注册名（用户配置的 `{{memoryContext}}`），所有对话共享同一套宏定义和快照。用户需要：

1. **按对话定制宏**：不同对话可能需要不同的记忆注入策略（如某个对话只关注特定表的特定筛选），但当前只能改全局设置影响所有对话。
2. **内置全量预览**：用户想快速查看当前空间的完整数据（所有表的所有记录），但当前 `{{memoryContext}}` 只输出启用表的分组摘要，不包含表结构信息。
3. **按表注入**：用户想单独注入某张表的所有数据（如「只看角色表」），但当前只能通过视图配置实现，且视图是全局的。

## Solution

扩展宏系统支持三种作用域：

- **内置宏**：`memoryFull`（全量数据 Markdown 表格）+ `memory_<表Key>`（单表数据），跟随当前活动空间，不显示在设置列表。
- **全局宏**：存 `extension_settings`，所有对话共享（当前行为）。
- **聊天 Scope 宏**：存 `chatMetadata`，随 `.jsonl` 导入导出，只在当前对话生效。

名称全局唯一，优先级：聊天 Scope > 全局 > 内置（聊天 Scope 可覆盖全局同名宏，全局可覆盖内置同名宏）。

## User Stories

1. 作为用户，我可以使用 `{{memoryFull}}` 宏展开当前空间所有表的完整数据（Markdown 表格格式），以便快速预览记忆全貌
2. 作为用户，我可以使用 `{{memory_<表Key>}}` 宏展开当前空间指定表的所有数据，以便按需注入单表内容
3. 作为用户，内置宏跟随当前活动空间（切对话后内容自动刷新），以便不同对话看到不同记忆
4. 作为用户，内置宏不显示在设置面板的宏列表中，以便列表只展示可管理的自定义宏
5. 作为用户，我可以在设置面板配置全局宏（当前行为不变），以便所有对话共享同一套宏定义
6. 作为用户，我可以在特定对话中创建聊天 Scope 的自定义宏，以便该对话使用不同的注入策略
7. 作为用户，聊天 Scope 宏存储在 `chatMetadata` 中，随 `.jsonl` 文件导入导出，以便对话资产完整迁移
8. 作为用户，聊天 Scope 宏可以覆盖全局同名宏（局部优先），以便在特定对话中覆盖全局行为
9. 作为用户，所有宏名全局唯一（内置 > 聊天 Scope > 全局），以便避免注册冲突
10. 作为用户，创建聊天 Scope 宏时面板实时检查名称冲突（不允许与内置宏或全局宏同名），以便提前发现问题
11. 作为用户，非法表 Key 的内置宏（不符合 ST 标识符规则）被跳过并记录警告，以便不阻断其他宏注册
12. 作为用户，内置宏输出受全局 `macroLimit` 截断，以便控制输出长度
13. 作为用户，内置宏输出空表时显示表头但无数据行，以便确认表存在但没数据
14. 作为用户，内置宏按表创建时间排序输出，以便与当前 `listTables` 行为一致
15. 作为用户，聊天 Scope 宏的管理入口是设置面板的独立 Tab（"对话级宏"），以便与全局设置清晰分离
16. 作为用户，导入聊天文件时自动还原聊天 Scope 宏，不需要手动操作，以便对话恢复后宏配置完整
17. 作为用户，导出聊天文件时自动包含聊天 Scope 宏，不需要手动操作，以便对话资产完整
18. 作为用户，内置宏的 `memoryFull` 输出格式为每表一个 section（表名标题 + Markdown 表格），以便可读性好
19. 作为用户，`memoryFull` 的 Markdown 表格表头为字段名，行为记录数据，以便直观理解
20. 作为用户，内置宏的表 Key 宏名为 `memory_<表Key>`（如 `memory_角色`），以便与 `memoryFull` 命名空间一致

## Implementation Decisions

### 1. 宏作用域存储

- **内置宏**：无存储，动态计算（根据当前空间的表结构生成）
- **全局宏**：存 `extension_settings.steMemory`（当前 `memoryViews` 同层）
- **聊天 Scope 宏**：存 `chatMetadata.steMemoryChatMacros`（与绑定指针同层）

聊天 Scope 宏的类型复用 `MemoryView`（声明式配置：表 Key + 筛选 + 投影），与全局视图同构。存储结构：

```typescript
// chatMetadata.steMemoryChatMacros
interface ChatScopeMacroStore {
  version: 1;
  macros: MemoryView[]; // 复用 MemoryView 类型
}
```

### 2. ST 注册策略

每个宏独立注册名（不使用位置参数模式）：
- 内置宏：`memoryFull`、`memory_<表Key>`（表 Key 合法则注册，否则跳过）
- 全局宏：用户配置的宏名（当前行为）
- 聊天 Scope 宏：用户在面板配置的宏名

注册顺序：先注册内置宏，再注册全局宏，最后注册聊天 Scope 宏（后者可覆盖前者）。ST 同名覆盖机制保证后注册的赢。

### 3. 名称唯一性校验

- **创建时**（面板 UI）：实时检查聊天 Scope 宏名是否与内置宏名或全局宏名冲突，冲突则禁止保存
- **注册时**（`MemoryMacroService`）：按优先级顺序注册，聊天 Scope 后注册可覆盖全局同名宏（ST 机制）
- **内置宏名**：`memoryFull`（固定）+ `memory_<表Key>`（动态，表 Key 合法则生成）

### 4. 内置宏内容格式

**`memoryFull`**：每表一个 section，Markdown 表格格式：

```
## 角色

| 姓名 | 身份 | 状态 |
|------|------|------|
| 张三 | 主角 | 活跃 |
| 李四 | 配角 | 已退场 |

## 事件

| 名称 | 时间 | 关联角色 |
|------|------|----------|
| 初遇 | 第1章 | 张三、李四 |
```

- 表顺序：按创建时间（与 `listTables` 一致）
- 空表：输出表头但无数据行
- 截断：全局 `macroLimit`（从尾部截断 + 标记）
- 输出不含 `{{...}}`（避免二次展开）

**`memory_<表Key>`**：单表 Markdown 表格，格式同 `memoryFull` 的单个 section。

### 5. 内置宏动态计算

内置宏在指纹变化时重新计算（与当前宏快照重建同节奏）：
- 读取当前空间的表列表（`listTables`）
- 为每张启用的表生成 `memory_<表Key>` 宏名（表 Key 合法则注册，否则跳过）
- 注册/注销变更的表 Key 宏（与当前 `memoryViews` 轮询重建同模式）

### 6. 快照架构

- **统一 `MemoryMacroService`**：管理所有宏（内置 + 全局 + 聊天 Scope），共享 `getSpaceId()` 和指纹轮询
- **快照预计算**：每个宏一个预计算快照（文本），handler 同步返回
- **重建时机**：指纹轮询（2s）+ 设置变化 kick + 空间切换 kick（当前行为不变）

### 7. 导入导出

- **自动随 `.jsonl`**：聊天 Scope 宏存在 `chatMetadata`，导入导出时自然携带（与绑定指针/镜像同模式）
- **不导出全局宏**：全局宏是用户级配置，不属于对话资产，避免覆盖导入方的全局设置
- **不导出内置宏**：内置宏是动态计算的，无存储

### 8. 设置面板 UI

- **独立 Tab**："对话级宏"，列表显示当前对话的聊天 Scope 宏
- **CRUD**：新建/编辑/删除聊天 Scope 宏（复用视图编辑组件）
- **名称校验**：创建时实时检查与内置宏名和全局宏名的冲突

### 9. 优先级仲裁

注册顺序保证优先级：
1. 内置宏先注册（最低优先级）
2. 全局宏后注册（可覆盖内置同名宏，但用户不太会用 `memory_` 前缀）
3. 聊天 Scope 宏最后注册（可覆盖全局同名宏，实现"局部覆盖"）

ST 同名覆盖机制：后注册的赢 + 控制台警告。

## Testing Decisions

- **原则**：只测外部行为（端口契约、纯函数输入输出），不测实现细节。沿用 st-extension「唯一纯逻辑 seam」理念。
- **内置宏渲染**：Markdown 表格格式（表头/行/空表/截断/排序）、表 Key 合法性跳过
- **作用域合并**：聊天 Scope 宏与全局宏的合并逻辑（名称冲突、优先级、空值处理）
- **名称唯一性**：创建时校验（内置名冲突、全局名冲突、合法名）
- **快照重建**：内置宏随指纹变化重建、聊天 Scope 宏随设置变化重建
- **导入导出**：聊天 Scope 宏随 `chatMetadata` 持久化（与绑定指针同模式）
- **先例**：`memory-macro-service.test.ts`（fake 端口 + fake timers）、`memory-view-render.test.ts`（渲染纯函数）

## Out of Scope

- 聊天 Scope 宏的视图编辑器（复用既有 `MemoryView` 编辑组件）
- 内置宏的字符上限独立配置（使用全局 `macroLimit`）
- 内置宏的表顺序自定义（按创建时间）
- 聊天 Scope 宏的批量导入/导出（独立于 `.jsonl`）

## Further Notes

- ST 宏标识符规则：`/^[a-zA-Z][A-Za-z0-9_-]*$/`（字母开头，后接字母数字下划线连字符）。表 Key 可能包含中文/特殊字符，非法则跳过 + 警告。
- `memoryFull` 和 `memory_<表Key>` 是系统语义，用户不应覆盖（面板校验阻止）。
- 聊天 Scope 宏的 `MemoryView` 类型复用意味着翻译/查询/渲染层零改动。
- 实现顺序：Phase 1（双 Scope + 校验）→ Phase 2（内置宏）→ Phase 3（导入导出）。
