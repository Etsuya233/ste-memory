# 宏作用域：`前缀::名字` 统一分发（全局 + 对话级 + 内置）

Feature spec。基于 grilling session 2026-08-30 + 2026-08-30 复审设计决策。

## Problem Statement

当前记忆宏系统只有一个全局注册名（用户配置的 `{{memoryContext}}` + 位置参数视图），所有对话共享同一套宏定义和快照。用户需要：

1. **按对话定制宏**：不同对话可能需要不同的记忆注入策略（如某个对话只关注特定表的特定筛选），但当前只能改全局设置影响所有对话。
2. **内置全量预览**：用户想快速查看当前空间的完整数据（所有表的所有记录），但当前 `{{memoryContext}}` 只输出启用表的分组摘要，不包含表结构信息。
3. **按表注入**：用户想单独注入某张表的所有数据（如「只看角色表」），但当前只能通过视图配置实现，且视图是全局的。
4. **局部覆盖**：特定对话想覆盖全局同名宏，但当前宏名全局唯一，无覆盖能力。
5. **可发现性**：内置宏对用户不可见，设置界面没有任何说明。

## Solution：一个前缀，分发一切

全部宏收敛为**一个 ST 注册名（全局前缀，默认 {{ste}}）+ `::` + 名字参数**的查找分发，没有第二个独立宏名：

- `{{前缀}}`：无参 = 全部启用表分组快照（现行 memoryContext 效果，默认快照）。
- `{{前缀::full}}`：内置宏，所有启用表完整 Markdown。
- `{{前缀::<表Key>}}`：内置宏，单表完整 Markdown（表 Key 是字符串参数，**无需满足 ST 标识符规则**，`{{ste::角色}}` 可用）。
- `{{前缀::<视图名>}}`：全局视图（extension_settings，随设置走）。
- `{{前缀::<对话宏名>}}`：对话级宏（chatMetadata，随 .jsonl 导入导出）。

**分发优先级（同名覆盖）**：对话级宏 > 全局视图 > 内置宏（full / 表 Key）。

收益：无 ST 同名抢占/影子恢复机制；覆盖是查表顺序；中文表 Key 直接可用；`memory_` 前缀与表 Key 标识符校验整个删除（注册层只剩一个宏）。

## User Stories

1. 作为用户，我可以在提示词/世界书里写 `{{前缀::full}}` 展开当前空间所有启用表的完整数据（Markdown 表格格式），以便快速预览记忆全貌
2. 作为用户，我可以写 `{{前缀::<表Key>}}` 展开当前空间指定表的所有数据（中文表 Key 如 `{{ste::角色}}` 直接可用），以便按需注入单表内容
3. 作为用户，内置宏跟随当前活动空间（切对话后内容自动刷新），以便不同对话看到不同记忆
4. 作为用户，内置宏（`{{前缀}}`、`{{前缀::full}}`、`{{前缀::<表Key>}}`）以只读形式列在设置面板「记忆宏」组的「内置宏」分区（不可编辑/删除，便于发现与避名）
5. 作为用户，我可以在设置面板配置全局前缀（当前记忆宏行为不变：`{{前缀}}` = 默认快照、`{{前缀::视图名}}` = 视图），以便所有对话共享同一套宏定义
6. 作为用户，我可以在特定对话中创建对话级宏，该对话内 `{{前缀::宏名}}` 优先于同名全局视图与内置宏，以便按对话定制注入策略
7. 作为用户，对话级宏存储在 `chatMetadata`，随 `.jsonl` 导入导出，以便对话资产完整迁移
8. 作为用户，同名对话级宏覆盖全局视图/内置宏（对话级 > 全局 > 内置），不需要额外配置
9. 作为用户，对话级宏名字不与任何作用域冲突——同名即覆盖，创建面板只做语法与对话内唯一校验
10. 作为用户，名字参数是字符串：视图名、对话宏名、表 Key 都可以用中文，不需要满足 ST 标识符规则
11. 作为用户，内置宏输出受全局 `macroLimit` 截断，以便控制输出长度
12. 作为用户，内置宏输出空表时显示表头但无数据行，以便确认表存在但没数据
13. 作为用户，内置宏按表创建时间排序输出，以便与 `listTables` 行为一致
14. 作为用户，对话级宏的管理入口是设置面板「记忆宏」组内的「对话级宏」分区，与全局视图同构的编辑器（筛选/投影齐全）
15. 作为用户，导入聊天文件时自动还原对话级宏，导出时自动携带，不需要手动操作
16. 作为用户，同名对话级宏配置错误（表/字段缺失）时展开为空串 + 面板配置错误徽标，不静默回落全局定义

## Implementation Decisions

### 1. 宏命名面与注册

- **存储**：前缀存 `extension_settings`（现 `macroName` 字段，默认值改为 `{{ste}}`）；全局视图存 `extension_settings.steMemory`；对话级宏存 `chatMetadata.steMemoryChatMacros`。
- **注册**：只注册一个 ST 宏（前缀名，裸标识符规则），带一个可选名字参数声明（`unnamedArgs [{ name: "name", optional: true }]`）。两个以上参数由 ST 参数校验拒绝。
- **旧用户迁移**：已发布版本存的自定义「宏名」值保留为前缀——`{{旧名}}`、`{{旧名::视图名}}` 语义不变；仅默认值变化（新装 = `{{ste}}`）。
- `memory_` 前缀与「表 Key 必须满足 ST 标识符规则」的限制废除（参数是字符串）。

### 2. 分发与优先级

handler（同步查表，全部预计算快照）：

```
无参       → 默认快照（全部启用表分组摘要）
1 个参数 n → 对话级宏快照[n] ?? 全局视图快照[n] ?? 内置:
              n === "full" → 全量 Markdown
              否则启用表 Key 命中 → 单表 Markdown
              ?? 未知名字 → 空串 + 警告
```

- 对话级宏配置错误 → 快照 = 空串（覆盖优先，不回落）。
- 视图/对话宏查询或渲染异常 → 单轮保旧值 + 日志。
- 空参数 `{{前缀::}}` → 空串 + 警告。

### 3. 快照架构

- **统一 `MemoryMacroService`**：默认快照 + 每视图快照 + 每对话宏快照 + 内置快照（full + 每启用表）。
- 内置/视图/对话宏共用同一批数据加载（listTables/listRecords + 读时重渲显示文本）与 digest（每次重建构建一次，翻译共用）。
- 重建时机：指纹轮询（2s）+ 设置变化 kick + 空间切换 kick（当前行为不变）；对话切换（chatMetadata 签名变化）同样在轮询里收敛。

### 4. 内置宏内容格式

- `{{前缀::full}}`：每表一个 section，Markdown 表格（表名标题 + 表头字段名 + 行为记录）；空表输出表头无数据行；截断 = 全局 `macroLimit` 尾部截断 + 标记；顺序 = 按表创建时间；输出不含 `{{...}}`。
- `{{前缀::<表Key>}}`：单表同一格式。

### 5. 设置面板 UI（合并设置项 + 内置宏入列）

- 一个折叠组「记忆宏」，组内三段式分区（segmented tabs）：
  - **内置宏**：只读列表，`{{前缀}}`（默认快照）、`{{前缀::full}}`、`{{前缀::<表Key>}}`（按当前空间启用表动态生成，全部可用——无非法 Key 概念）；「内置」徽标，无操作按钮。
  - **全局宏**：前缀输入（`data-stm-field="macro-name"`，默认 `{{ste}}`）+ 字符上限 + 视图 CRUD（复用 MemoryViewsManager，行为不变）。
  - **对话级宏**：对话级宏 CRUD（复用 MemoryViewEditor 与视图草稿模型，筛选/投影齐全）；仅语法 + 对话内唯一校验；提示「同名宏优先于全局视图与内置宏」。
- 折叠摘要 = `宏名 · N视图 · N对话宏`。

### 6. 导入导出

- 对话级宏随 `chatMetadata` 自动导入导出（与绑定指针/镜像同模式）。
- 全局视图/前缀是用户级配置，不随对话文件走。

## Testing Decisions

- **原则**：只测外部行为（端口契约、纯函数输入输出），不测实现细节。
- **注册**：只注册一个前缀宏；参数声明 = 一个可选名字参数。
- **分发**：`{{前缀}}` 默认快照；`{{前缀::full}}` / `{{前缀::表Key}}`（含中文 Key）Markdown 渲染（表头/行/空表/截断/排序）；优先级链 对话 > 视图 > 内置（同名覆盖与回落）；未知名字空串 + 警告。
- **重建**：内置宏随指纹/设置变化重建；对话宏随 chatMetadata 签名变化重建（CRUD kick 即时生效、删除后同名视图接管）；配置错误空串（不回落）；查询失败单轮保旧值；停用清空与恢复。
- **UI**：面板三个分区就位（SSR 冒烟：tab 存在、默认全局分区、摘要含对话宏数）；内置宏列表行（真机验收脚本覆盖数据渲染）。
- **导入导出**：对话级宏随 `chatMetadata` 持久化（与绑定指针同模式）。

## Out of Scope

- 前缀多注册（一个插件前缀就够；用户自定义前缀已覆盖改名需求）。
- 内置宏的字符上限独立配置（使用全局 `macroLimit`）。
- 内置宏的表顺序自定义（按创建时间）。
- 对话级宏的批量导入/导出（独立于 `.jsonl`）。

## Further Notes

- 表 Key 恰好为 `full` 时 `{{前缀::full}}` 是内置全量宏，该表不提供单表宏（数据仍在 full 里）。
- `{{前缀}}` 无参展开不参与覆盖（需要按对话定制就写 `{{前缀::宏名}}`）。
- 已发布版本的 `{{宏名::视图名}}` 写法在新模型下不变（前缀即原宏名）。
