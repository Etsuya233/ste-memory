# 记忆表格设计

Status: 已确认

## 目标

为长达 1K+ 楼的会话维护可修订的当前认知，减少模型对上下文窗口的依赖。第一阶段通过 HTTP Adapter 和桌面实验前端验证，由用户上传来源文件；`tmp/st_source` 只作为格式与规模参考。SillyTavern 插件、Prompt 注入和移动端交互后续一起设计。

记忆表格是对话之外的辅助认知层，不取代原始对话，也不天然等同于客观事实。

## 已确认范围

- 系统表和自定义表使用统一表格模型。
- 一个内部记忆空间隔离一段会话的表格、配置、记录和历史。
- 持久化使用统一结构和 `memory_space_id` 进行逻辑隔离，不为每个会话创建物理数据库表；外部会话身份到记忆空间的映射由 Adapter 管理。
- 每个记忆空间独立拥有表格定义；系统模板仅在创建时复制。
- 表格与字段均可启用或禁用，并支持各自的 Prompt。
- Agent 更新和用户手动更新遵守相同领域规则。
- 记忆空间、表格、字段和正式记录提供必要 CRUD；历史记录只读。
- 旧楼层被编辑后的自动失效与重算不属于当前阶段，过时记忆暂由用户手动修正。
- SillyTavern swipe 和同步策略留在未来的 SillyTavern Adapter；Adapter 默认不立即同步最新消息，以减少 swipe 引起的频繁更新。

## 字段模型

v1 支持短文本、长文本、自由短文本列表、整数、小数、布尔值、日期、日期时间、单选、多选、单引用和多引用。多选使用预定义选项；不支持任意 JSON 或嵌套结构。

字段创建后 v1 不支持修改字段类型；需要其他类型时新建字段。字段名称、Prompt、启用状态和选项配置另行遵守各自的 CRUD 规则。

字段定义支持 `required`。创建记录时必填字段必须有值，更新时不能清空；系统表的名称/显示字段以及关系表的人物 A、人物 B 必填。v1 不支持默认值、公式或计算字段。必填字段允许关闭，但 UI 需要提示 Agent 可能因此无法创建记录。

字段和表格删除在 v1 直接物理删除，不提供归档或恢复。删除后对既有值、历史解释和依赖关系的迁移策略延期设计。

记录更新使用字段 Patch 语义：命令中省略的字段保持不变，显式值完整替换旧值，`null` 清空可空字段。v1 不提供追加文本或自动合并列表操作；只有实际变化的字段更新证据并产生历史状态。

每张表必须指定显示策略，通常是短文本显示字段，也可使用由其他字段派生的显示模板。记录使用不可变内部 ID，显示值允许重复。引用只允许指向同一记忆空间中的记录；目标仍被当前记录引用时限制删除，调用方须在同一批次解除或转移引用。

## 数据修订

- 一次批量记录变更原子提交，并在相关数据行上使用统一修订 ID。
- 正式表只保存当前状态；历史表只保存被替换或删除的旧状态。
- 删除正式记录时先写入历史快照，再从正式表物理删除；不保留软删除标记。
- 历史行拥有独立主键，并保留原记录 ID 和导致归档的修订 ID。
- 不建立修订批次头，不版本化表格定义、Prompt 或开关。
- 原因可作为普通表格字段，由表格填写 Agent 生成。
- 当前行和历史行保存 `revision_id`、`revision_source`、`created_at`、`updated_at` 等系统元数据；`revision_source` 区分 `agent` 与 `user`，历史行额外保存 `archived_at`。
- v1 历史记录只支持查看和筛选，不支持修改、删除或恢复旧版本。

## 证据

Agent 更新的证据引用保存到字段值级；同一记录的不同字段可以引用不同证据。手动修改允许没有证据并标记为手动，历史状态保留旧字段证据。

Adapter 为证据传入存储模式。`snapshot` 在 Core 中保存 `content` 和详细元数据；`reference` 在 Core 中只保存 `source_type`、`source_id` 和 `extraProps`，完整消息仍由 Adapter Source Store 持有。

## Agent 与架构边界

- 领域层拥有统一表格模型、字段校验、引用约束和修订规则，不依赖 HTTP、SillyTavern 或 LLM SDK。
- 应用层编排表格填写 Agent、事务和用例。
- HTTP、SillyTavern、LLM Provider 和持久化位于 Adapter。
- Agent 通过通用批量命令提出记录变更，不直接写库。
- Agent 可多次使用只读 `query_records` Tool 查询当前记录和引用候选，但只提交一个跨表原子 `MutationBatch`。`query_records` 以表、字段条件、返回字段、分页和排序表达列出、搜索或按身份读取；批次内新记录可通过临时 ID 相互引用，提交时统一转换为真实 ID。
- `query_records` 使用稳定 `table_id` / `field_id` 和类型感知的受控操作符，支持字段投影、AND 条件、分页和排序；不支持任意嵌套表达式或原始 SQL。
- 当前每个处理块只运行一个表格填写 Agent，并覆盖所有启用表；逐表 Agent、多 Agent 协作和并行处理延期。
- Tool 调用和结构化 JSON DSL 最终编译为同一种 `MutationBatch`。
- `MutationBatch` 只允许显式 `create`、`update`、`delete`，不提供按名称 upsert。创建使用批次内临时 ID；更新和删除指定已有记录 ID 与预期修订 ID；服务端生成真实记录 ID 和统一修订 ID。
- 当前不自动向 Agent 发送正式表记录索引或完整数据；Agent 通过只读 `query_records` 查询已有记录。自动附带记忆及上下文模板留待后续设计。
- 预览和正式提交共用命令解析、领域校验和差异计算逻辑，仅在末端是否持久化上不同。
- v1 不持久化长期待审提案；确认预览时使用版本条件避免覆盖并发变化。

## 实现栈

第一阶段使用 TypeScript 单仓库：根级 `core` 包通过内部目录划分纯领域模型、应用用例、Agent 编排与 Ports；业务接入 Adapter 放在 `apps`，其中 `apps/api` 实现 HTTP Adapter，`apps/web` 为 React 桌面实验前端；Core SQLite 持久化 Adapter 与通用 SQLite 工具合并在 `packages/core-sqlite`，共享工程配置放在 `packages/shared`。未来 SillyTavern 插件作为独立 Adapter 或包，复用契约而不依赖领域层。

v1 只实现 SQLite 持久化；PostgreSQL 和迁移工具延期。Core Memory 与 HTTP Adapter Source Store 分别接收数据库连接 URL，可以指向同一个 SQLite 文件，也可以分开；双方可使用不同的数据访问依赖。共享文件时仍保持表名和所有权边界分离。

应用层定义厂商无关的 LLM 端口，v1 只实现 OpenAI-Compatible Tool Calling Adapter，配置 Base URL、API Key 和 Model。不实现其他厂商原生协议、不支持 Tool Calling 的模型或 JSON-only fallback。

HTTP API 和实验前端限定为本机单用户工具，默认只监听 `127.0.0.1`，不实现账号、认证或多用户权限。网页提供 LLM 配置填写框；网页传入的配置覆盖服务端环境变量，未填写的项目回退到环境配置。

网页填写的 API Key 只保存在当前页面内存中，刷新后清除，且不写入 SQLite 或浏览器持久存储；留空时使用服务端环境变量。Base URL、Model 和非敏感运行参数可以在浏览器本地保存。

## 证据处理

Adapter 将外部聊天记录列表转换为应用层可识别的规范化证据条目后传入。应用层支持可选的消息数量参数，将输入顺序切分为多个“处理块”；不传参数时一次处理全部输入。当前不引入 `max_token`，处理块也不自动附带前文尾部；Agent 需要时通过只读 Tool 查询当前记忆记录。处理块是运行编排概念，不等同于记录数据的修订批次。

当前 HTTP 实验前端把用户选择的消息范围作为一个处理块，不暴露自动处理完整会话的流程。其他 Adapter 以后可以传入每块消息数量。

实验前端创建记忆空间时要求用户上传一个聊天 JSONL。HTTP Adapter 解析为自己的来源数据结构并持久化，负责处理范围和进度；应用层只接收规范化证据。角色卡和 Persona 不属于当前上传流程，服务端也不依赖本地 `tmp` 路径。

上传仅创建记忆空间并保存来源数据，不自动调用模型。用户检查表格、字段、Prompt 和 LLM 配置后，选择一个消息范围并手动触发一次预览或正式处理；所有 Agent 运行均由用户明确启动。网页不自动调度整段会话，也不逐块要求确认；处理下一段由用户再次选择范围触发。

网页通过原始聊天面板的 1-based 闭区间选择消息范围。HTTP Adapter 在内部映射到稳定 `source_id`；运行记录同时保存显示序号范围和实际来源标识。

消息范围处理由 HTTP Adapter Service 作为后台运行任务管理。启动后立即返回 `run_id`；前端通过轮询查看是否有任务运行、当前进度、变更数和错误，同时仍可读取表格。任务状态和运行日志属于 HTTP Adapter，不进入记忆领域或历史表，刷新页面后仍可查询。

v1 全局最多运行一个后台 Agent 任务，不提供队列或并行任务。任务运行时其他记忆空间仍可浏览和手动编辑，但不能启动新的 Agent 任务。

任务支持暂停、恢复和中止。暂停或中止请求先进入 `pause_requested` 或 `cancel_requested`，并在 Agent Tool 轮次之间、最终提交前等安全点生效；不强行打断进行中的 LLM 请求或 SQLite 事务。暂停后任务占用全局任务槽，对应记忆空间继续只读；恢复后从原运行继续。中止会丢弃尚未提交的 `MutationBatch` 并释放任务槽；若最终事务已经开始，则等待事务完成并以实际提交结果结束。

任务状态至少包括 `queued`、`running`、`pause_requested`、`paused`、`cancel_requested`、`cancelled`、`succeeded`、`failed` 和 `interrupted`。服务启动时将所有遗留的非终态任务标记为 `interrupted`，保留其消息范围、进度和错误，但不自动恢复或重放模型请求。已经原子提交的记忆数据保持不变。

后台任务处于任一非终态时，对应记忆空间只读：用户可查看表格、证据和进度，但不能手动修改记录、表格、字段、Prompt 或开关。任务进入 `cancelled`、`succeeded`、`failed` 或 `interrupted` 后恢复写入。

规范化证据条目包含 `source_type`、`source_id`、`content`、`storage_mode` 和 Adapter 自由扩展的 `extraProps`。同一来源条目的 `source_type + source_id` 必须稳定，应用层据此幂等导入并生成内部 `evidence_id`；`extraProps` 仅作为适配器元数据传输，不参与表格字段类型、引用或领域规则。处理进度由 Adapter Service 管理，应用层不保存来源游标；应用层返回本次处理过的来源标识和变更结果，下一次处理范围由 Adapter 决定。

应用层返回按 `source_id` 组织的处理结果：状态、已处理标识、跳过标识、预览或提交差异、警告和错误。只有正式变更成功后才返回已处理标识；预览不推进 Adapter 进度。

## Prompt 组合

表格 Prompt 定义整张表的共同填写意图，字段 Prompt 作为字段级追加规则。Agent 指令、表格 Prompt、字段 Prompt、结构化字段约束、当前记录和本次证据一起构成填写上下文；字段 Prompt 不能绕过类型、引用、启用状态或其他领域规则。空 Prompt 仅表示没有额外自然语言规则。

v1 Prompt 为纯文本，不支持用户自定义模板变量或表达式；应用层负责提供结构化上下文。受控变量可在后续版本扩展。

每张系统表提供完整的默认表格 Prompt；只为当前状态、引用、关系和更新原因等容易混淆的字段提供默认字段 Prompt。名称、标签等直观字段默认 Prompt 为空，通用校验规则不在每个字段 Prompt 中重复。

默认 Prompt 使用简洁中文；专有名词和称呼保留证据原文，不强制翻译。通用规则集中在 Agent 基础指令中，具体草案见 [system-prompts.md](./system-prompts.md)。

## 启用状态

表格和字段开关只控制其是否参与 Agent 自动填写与后续记忆输出。关闭后已有数据和历史保持不变，用户仍可查看和手动 CRUD；重新开启后继续使用原数据。引用完整性不因目标表或字段关闭而失效。

## 当前读取范围

当前阶段的读取仅指记忆表基础 CRUD：按记忆空间、表格、记录 ID、显示值、字段值和引用查看或筛选记录，并展示字段证据。RAG、复杂语义检索和把记忆注入 SillyTavern Prompt 均延期；后者只在 SillyTavern Adapter 阶段处理。

## HTTP 实验前端

创建记忆空间和上传 JSONL 使用独立页面。空间工作台采用桌面三栏：左侧为表格列表、开关和配置；中间为当前表格网格、搜索、筛选和手动 CRUD；右侧检查器在记录详情、字段证据、历史版本和原始聊天之间切换。点击字段证据会跳转并高亮 HTTP Adapter Source Store 中对应的 `source_id`，以便同时对比表格和原始聊天数据。

## 验收标准

- 上传并保存包含 1K+ 消息的 JSONL。
- 按消息范围启动后台 Agent 任务，并通过轮询展示运行状态和进度。
- 后台任务可以暂停、恢复和中止，并只在安全点切换状态。
- Agent 通过 `query_records` 查询已有记录，并原子更新所有启用系统表。
- 后台任务运行期间仍可查看表格和原始聊天。
- 用户可以手动 CRUD 当前数据。
- 更新和删除产生只读历史，删除不会在正式表留下软删除行。
- 字段证据可以跳转并高亮对应原始消息。
- 失败任务不留下半批数据。
- 用户通过表格和原始聊天对照界面人工评估提取质量。

RAG 命中率、SillyTavern Prompt 注入和移动端体验不属于本次验收。

## 工程约束

- 领域代码不得依赖 HTTP Controller、SillyTavern 或具体 LLM SDK。
- SillyTavern 插件和 Adapter 后续独立实现，不把其业务语义移入领域层。
- 单个代码文件不得超过 300 行；超出前按职责拆分。
- 仅在边界、约束或非显然逻辑处添加必要注释，避免叙述代码表面行为。

## 模块功能列表

### Core Domain

- 创建、读取、更新和删除记忆空间。
- 使用 `memory_space_id` 隔离表格定义、字段定义、记录、引用和历史。
- 从七张系统表模板初始化新记忆空间。
- 创建、读取、更新和物理删除系统表或自定义表定义。
- 启用和关闭表格；关闭时保留数据并允许用户手动管理。
- 设置和修改纯文本表格 Prompt。
- 创建、读取、更新和物理删除字段定义。
- 启用和关闭字段；关闭时保留字段值并允许用户手动管理。
- 设置和修改纯文本字段 Prompt。
- 配置字段类型、必填状态、单选/多选选项和显示顺序。
- 禁止修改已创建字段的类型。
- 支持短文本、长文本、自由短文本列表、整数、小数、布尔值、日期、日期时间、单选、多选、单引用和多引用。
- 校验必填字段、字段值类型、枚举选项和引用目标。
- 支持短文本字段显示策略和派生显示模板。
- 使用不可变内部记录 ID，允许显示值重复。
- 限制引用指向同一记忆空间内的当前记录。
- 限制删除仍被当前记录引用的目标记录。
- 创建、读取、更新和删除正式记录。
- 使用省略不变、显式替换、`null` 清空的字段 Patch 语义。
- 对一批跨表记录变更执行原子校验和提交。
- 支持批次内临时 ID，并在提交时解析为真实记录 ID。
- 为批次生成统一 `revision_id`。
- 保存 `revision_source`、创建时间和更新时间等记录元数据。

### Revision History

- 更新正式记录前，将旧状态写入历史表。
- 删除正式记录前，将旧状态写入历史表，再从正式表物理删除。
- 为历史行生成独立主键，并保存原记录 ID 和归档修订 ID。
- 保存历史字段值、字段证据、变更来源和归档时间。
- 按表格、原记录、修订 ID 和时间查看或筛选历史。
- 保持历史记录只读，不支持修改、删除或恢复。
- 不为表格定义、字段定义、Prompt 和开关创建历史版本。

### Evidence

- 接收 Adapter 提供的 `source_type`、`source_id`、`content`、`storage_mode` 和 `extraProps`。
- 使用稳定的 `source_type + source_id` 幂等识别来源条目。
- 生成内部 `evidence_id`。
- 在 `snapshot` 模式保存正文和详细元数据。
- 在 `reference` 模式只保存来源身份和 `extraProps`。
- 为 Agent 更新的每个字段值保存零到多个证据引用。
- 允许用户手动更新的字段没有证据，并标记其来源为用户。

### Application Services

- 编排记忆空间、表格、字段、记录、历史和证据用例。
- 将 Tool Calling 或结构化 DSL 转换为统一 `MutationBatch`。
- 使用同一条命令解析、校验和差异计算管线执行预览或正式提交。
- 预览返回 diff，但不持久化数据或推进来源进度。
- 正式提交成功后返回修订 ID、变更结果和已处理来源标识。
- 返回已处理、跳过、警告和错误对应的 `source_id`。
- 接受可选的每块消息数量；未提供时一次处理全部输入。
- 不保存 Adapter 的来源处理游标。

### Table Filling Agent

- 为每个处理块启动一个 Agent，覆盖所有启用表和字段。
- 向 Agent 提供本次证据、启用表格定义、字段定义和组合 Prompt。
- 不自动向 Agent 注入已有记录索引或完整表格数据。
- 提供唯一只读 Tool `query_records`。
- 使用稳定 `table_id` 和 `field_id` 查询记录。
- 支持字段投影、类型感知条件、AND 匹配、分页和排序。
- 禁止任意 SQL 和任意嵌套查询表达式。
- 允许 Agent 多次查询，但只提交一个最终跨表 `MutationBatch`。
- 只允许显式 `create`、`update` 和 `delete`，不提供模糊 upsert。
- 要求更新和删除携带预期修订 ID。
- 要求 Agent 为变化字段附上证据引用。

### LLM Adapter

- 提供厂商无关的应用层 LLM 端口。
- 实现 OpenAI-Compatible Tool Calling Adapter。
- 接收 Base URL、API Key 和 Model 配置。
- 使用网页配置覆盖服务端环境变量，空值回退到环境配置。
- 不持久化网页填写的 API Key。
- 不支持其他厂商原生协议或 JSON-only fallback。

### SQLite Persistence

- 持久化记忆空间、定义、当前记录、历史记录、证据和字段证据。
- 使用结构化元数据表和 JSON 记录文档保存动态字段。
- 为正式记录和历史记录保存同形状的 JSON 数据。
- 在事务中原子提交跨表 `MutationBatch`。
- 为 Core Memory 和 HTTP Adapter Source Store 分别接收数据库连接 URL。
- 支持两个 Store 使用同一 SQLite 文件或不同 SQLite 文件。
- 共享 SQLite 文件时保持表名和所有权边界分离。

### HTTP Adapter

- 提供本机单用户 HTTP API，默认监听 `127.0.0.1`。
- 接收用户上传的 SillyTavern 聊天 JSONL。
- 解析 JSONL，并将聊天消息保存到 HTTP Adapter Source Store。
- 创建与上传聊天对应的记忆空间。
- 将消息列表转换为应用层规范化证据格式。
- 使用 1-based 闭区间把用户选择的消息范围映射为稳定 `source_id` 列表。
- 将一个网页选择的消息范围作为一个处理块。
- 管理来源处理范围和进度，不要求 Application 保存游标。
- 提供后台任务创建、查询、暂停、恢复和中止接口。
- 全局只允许一个非终态 Agent 任务，不提供队列。
- 在安全点应用暂停或中止请求，不强制打断 LLM 请求或 SQLite 事务。
- 服务启动时将遗留非终态任务标记为 `interrupted`。
- 在任务非终态期间将目标记忆空间设为只读。
- 允许其他记忆空间在任务期间继续读取和手动编辑。
- 提供轮询所需的任务状态、进度、变更数、警告和错误。

### HTTP Experiment Web

- 展示记忆空间列表。
- 创建记忆空间并要求上传一个聊天 JSONL。
- 提供 Base URL、API Key 和 Model 填写框。
- 仅在页面内存保存 API Key；刷新后清除。
- 在浏览器本地保存 Base URL、Model 和非敏感运行参数。
- 使用三栏空间工作台。
- 在左栏选择表格、切换表格/字段开关并编辑定义和 Prompt。
- 在中栏以表格网格查看、搜索、筛选和手动 CRUD 正式记录。
- 在右栏查看记录详情、字段证据、只读历史和原始聊天。
- 点击字段证据后跳转并高亮对应原始消息。
- 使用起始序号和结束序号选择一次处理范围。
- 预览所选范围产生的新增、修改和删除 diff。
- 手动启动所选范围的正式后台处理任务。
- 通过轮询展示任务是否运行、当前状态和进度。
- 提供暂停、恢复和中止任务操作。
- 在目标空间只读期间禁用所有写入控件，但保持数据可查看。

### System Table Templates

- 提供人物、人际关系、地点、物品、剧情、伏笔和待办七张系统表。
- 为每张系统表创建本 Spec 已定义的字段、字段类型、必填状态、引用目标和显示策略。
- 为每张系统表提供可编辑的中文默认表格 Prompt。
- 为语义容易混淆的字段提供可编辑的默认字段 Prompt。
