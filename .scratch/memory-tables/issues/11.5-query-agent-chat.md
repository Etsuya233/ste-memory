# 11.5 — QueryAgent 后端接入与调试聊天界面

**Type:** task

**What to build:** 实现 QueryAgent 的 api 接入与调试聊天界面：api 提供 SSE 流式聊天端点与 LLM 配置接入（环境变量回退、API Key 不落盘），web 提供每记忆空间聊天面板与 LLM 配置表单，实时展示思考过程与工具调用参数/结果，主要用于调试 11 的 QueryAgent。本 Ticket 不涉及提案相关 UI。

**Blocked by:** 11 — 实现 Agent 引擎与 QueryAgent

**Status:** ready-for-agent

**api：**
- [ ] SSE 流式聊天端点 `POST /api/memory-spaces/:id/chat`：输入提问与历史，流式返回思考、工具调用参数/结果与回答增量；支持取消（AbortController / 客户端断开）。
- [ ] LLM 配置接入：`OPENAI_BASE_URL` / `OPENAI_API_KEY` / `OPENAI_MODEL` 环境变量，网页配置逐字段覆盖、空值回退；API Key 仅本次请求内存，不落库/落盘/打日志；provider 构造按 11 设计文档「参考」实现。

**web：**
- [ ] 每个记忆空间一个聊天面板：输入提问、接收流式回答，消息历史保留在页面内。
- [ ] 实时展示思考过程与工具调用参数/结果（工具结果可展开/收起）。
- [ ] LLM 配置表单：Base URL / API Key / model；留空字段由服务端环境变量回退并标注生效来源（网页配置 / 环境变量）；API Key 仅保存在当前页面内存（刷新即失，不写 localStorage/sessionStorage/数据库）；Base URL、Model 等非敏感配置可保存浏览器本地。
- [ ] 提问中可取消（AbortController）；网络错误、LLM 鉴权失败、超时等有明确提示，不阻塞继续操作。
- [ ] 不提供提案相关 UI（范围选择、提案面板、确认提交随提案流归入 12 及后续）。

## Comments

### 拆分说明

- 11 只做 core（引擎 + query_records + QueryAgent），不碰 api/web；本票承接 11 移出的 api（SSE 端点、LLM 配置接入）与 web（聊天界面、配置表单、Token 浏览器保存约束）内容。
- 技术设计：`.scratch/memory-tables/11-agent-engine-design.md`——§4 配置接入（参考）、§8 端点归属本票；SSE 事件映射与多轮上下文为本票待定项。

### 待定项（实现时定）

- SSE 事件映射的精确形状（pi 事件 → 应用事件 → SSE）。
- 多轮上下文：无状态回传历史（推荐 v1）vs 有状态会话（服务端保留 Agent 实例、`continue()` 续跑）。
- 思考过程展示依赖模型是否输出 thinking（pi 事件支持时透传）。

### 调试价值

通过聊天界面观察 QueryAgent 的查询路径——是否先查再答、查了正确的表/字段、条件是否正确；工具调用参数与结果实时可见，便于迭代提示词与工具设计。
