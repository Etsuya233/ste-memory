## Answer

已实现并提交（commit 见 git log）。api 侧：`POST /memory-spaces/:id/chat` SSE 流式端点（预检错误走 JSON 4xx、流中错误走 SSE error 事件、客户端断开经 AbortController → QueryAgent 以 stopReason "aborted" 收尾、不抛异常）；`GET /llm-config` 只暴露非敏感环境回退信息（API Key 仅存在性布尔）。LLM 配置接入按 11 设计 §4「参考」：`OPENAI_BASE_URL/OPENAI_API_KEY/OPENAI_MODEL` 环境变量 + 逐字段 web ?? env 合并（llm-config.ts），provider 用 `createModels + createProvider({ id, baseUrl, auth, models, api: openAICompletionsApi() })`、模型带 baseUrl、`getApiKey` 钩子注入显式 key（resolve 经 credential 参数回传）；API Key 每次对话按解析结果闭包内存构造，不落库/落盘/打日志。SSE 事件映射（待定项落定）：`thinking_delta` / `message_delta` / `tool_start` / `tool_result`（取工具 details，可展开收起）/ `done` / `error`；多轮上下文采用无状态回传历史（推荐 v1，工具结果不跨轮回传）；不吐 text_delta 的 provider 由服务端在终态前补发全文回答。

web 侧：检视栏新增「Agent 聊天」标签，每记忆空间一个聊天面板（历史按空间存页面内存 Map，切换空间/标签不丢失，面板常驻隐藏而非卸载）；实时展示思考过程（可折叠）、工具调用参数与结果（结果可展开收起、错误高亮）；提问中可停止（AbortController）；网络错误/鉴权失败/超时/取消均有明确提示且不阻塞继续操作；LLM 配置表单三字段带生效来源徽标（网页配置/环境变量/默认/未配置），API Key 仅当前页面内存（刷新即失，不写 localStorage/sessionStorage），Base URL/Model 自动存 localStorage。无提案相关 UI。

测试：api 新增 llm-config 合并规则、chat SSE 全流程（脚本化假 streamFn 跑通工具调用→真实查询→回答→done）、多轮历史回传、配置缺失/404/形状校验、鉴权失败 error 事件、超时中止、真实 provider 对本地假 OpenAI 端点的流式往返（含 Bearer 头断言）；web 新增 query-chat-state 纯函数测试。全仓 120 测试通过，typecheck/lint/prettier 干净。
