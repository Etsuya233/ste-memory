# 07 — 更新和物理删除记录并保存只读历史

**Type:** task

**What to build:** 实现当前记录的手动更新、删除和历史快照。每次更新或删除必须先保存旧状态，使用同一 `revision_id` 标记同一批原子变更；历史只读，不提供恢复。

**Blocked by:** 06 — 创建和浏览当前记忆记录

**Status:** resolved

- [x] 更新支持字段级 patch、显式置空和 `expected_revision_id` 并发校验。
- [x] 删除当前记录为物理删除，删除前保存完整旧记录快照。
- [x] 更新前保存完整旧记录快照，再写入新当前记录。
- [x] 同一原子批次跨表变更共享一个 `revision_id`，并记录 user/agent 来源、原因字段由记录自身承载、时间信息。
- [x] 历史记录不可编辑、不可删除、不可恢复，只支持按表、记录、revision 和时间过滤。
- [x] 页面可从当前记录打开历史列表和快照详情。
- [x] 并发版本冲突不会覆盖他人更新，并返回可理解的错误。

## Answer

Core 新增统一记录变更批次，支持跨表更新和删除共享修订 ID。更新使用字段 Patch 语义，省略字段保持原值，显式 `null` 清空可空字段；所有操作在提交前校验 `expected_revision_id`，SQLite 再以修订条件执行更新或删除，任一冲突会回滚整批变更。更新与物理删除均先保存完整旧状态，历史快照同时保留旧修订元数据、导致归档的修订 ID、user/agent 来源和归档时间。

SQLite 新增只读历史存储及表格、原记录、修订 ID、归档时间过滤。HTTP 提供手动更新、删除和历史查询，版本冲突返回 409；时间边界统一转换为 UTC ISO 后再比较。工作台检查器支持编辑、删除、打开历史列表并查看字段快照，保存后同步刷新当前网格和详情。
