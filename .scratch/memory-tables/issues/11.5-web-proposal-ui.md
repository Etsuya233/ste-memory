# 11.5 — Web 提案界面：LLM 配置、范围选择与提案展示

**Type:** task

**What to build:** 在桌面实验前端接入 11 的提案生成端点：LLM 配置表单、原始聊天 1-based 闭区间范围选择、「生成提案」交互与结构化提案面板。本 Ticket 只做界面与交互；Agent 主流程、query_records 工具与后端端点见 11；确认提交与后台任务见 12/13/14。

**Blocked by:** 11 — 为选定消息范围生成 Agent 提案

**Status:** ready-for-agent

- [ ] 页面提供 Base URL、API Key、model 配置表单；留空字段由服务端环境变量回退，界面标注当前生效来源（网页配置 / 环境变量）。
- [ ] API Key 只保存在当前页面内存（React state），刷新即失；不写入 localStorage、sessionStorage 或数据库；Base URL、Model 等非敏感配置可保存到浏览器本地。
- [ ] 原始聊天面板支持 1-based 闭区间范围选择（点击起点/终点），选区高亮并显示消息数。
- [ ] 「生成提案」按钮：仅在存在选区且配置可解析（网页或环境变量）时可用；运行中禁用并显示 loading，防止重复提交。
- [ ] 生成请求可取消（AbortController）；取消、网络错误、LLM 鉴权失败与超时等均有明确提示，不阻塞用户继续操作。
- [ ] 提案面板结构化渲染：按表列出 create/update/delete 意图、字段变更值与证据引用（定位到原始消息）；提供「复制 JSON」。
- [ ] 提案展示只读，不提供确认/提交入口（确认提交与任务状态见 12/13/14）。

## Comments

### 拆分说明

从 11 拆出：原 11 的「页面提供 LLM 配置」与「API Key 仅页面内存」两项 Web 行为移至本 Ticket；11 保留后端：HTTP Adapter 端点（含逐字段 env 回退合并、API Key 仅请求内存不落盘）、`core/src/agent` 模块、provider 构造与提案生成。

设计要点（与 11 讨论同步）：

- 范围选择用 1-based 闭区间，显示序号由后端映射为稳定 `source_id`（HTTP Adapter 职责，见 11）。
- 生成请求体携带 `{ range, llm? }`，`llm` 缺省字段由服务端环境变量回退。
- 配置解析失败（网页与环境变量均无）时按钮不可用或点击给出提示。
- 提案面板消费 11 返回的结构化提案：create/update/delete 操作 + 字段级证据引用；渲染时可按表分组。
- 选区消息数显示帮助用户控制处理块规模（v1 不做按 token 切分）。
