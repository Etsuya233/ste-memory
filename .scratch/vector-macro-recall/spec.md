# 自动召回与检索宏

状态：已实现并完成真实 ST 验证。2026-10-22。由主代理协调 Sol 6.1 Medium 子代理开发与验证；结果见 summary.md。

## 用户流程

用户打开自动召回，绑定一个或多个已有命名视图，并为每个视图选择其所属表的向量组，再设置 Top K、可选最低分和宏输出字符上限，自行把 `{{memoryRecall}}` 放进角色卡或提示词预设。发送消息后，ST 等待插件检索，插件准备好文本，ST 再构建本轮提示词；宏同步返回这份文本，同轮展开多次也不重复请求。即使没放宏，开启自动召回仍会检索，设置中明确说明。

每个对话默认关闭，只在现有聊天元数据中保存一份配置，不做命名、继承或配置库；两个对话共用空间时各自开关和选区独立。Top K 默认 10、范围 1–50，最低分默认关闭，输出上限默认 4000 字符。默认没有视图绑定，启用前至少选择一个视图；没有合适视图时前往现有记忆视图／对话宏管理中新建。首次选中视图时预选其所属表当前全部有效向量组，并保存组选区；之后新增视图或组不自动加入。选中项失效时提示修正，不扩大范围。更换绑定空间时关闭自动召回并清空选区，重新选择后再启用。配置随对话保存，查询和召回文本仅留在页面内，刷新清空。宏名首版固定为 memoryRecall，避免与已有记忆宏含义混用。

## 时序依据与接入方案

已检查当前 ST 源码，并核对运行中的本地 ST 所提供的 `script.js` 与该源码一致。普通发送顺序为：`GENERATION_STARTED` → `GENERATION_AFTER_COMMANDS` → `sendMessageAsUser` 执行用户输入正则和宏展开、保存消息 → **等待 `MESSAGE_SENT` 的监听器** → `getCharacterCardFields` 展开角色卡 → 后续提示词构建。事件发射器逐个 await 监听器。因此新消息的检索放在可等待的 `MESSAGE_SENT`，监听器必须把准备工作的 Promise 返回给 ST。

`GENERATION_AFTER_COMMANDS` 尚未落定消息，只用于准备发送状态；生成拦截器执行时角色卡已展开，不能承担本轮召回准备。消息自身也会提前展开宏，所以进入新发送时先撤下旧召回；该阶段检索宏返回空串。读取事件指向的已保存用户消息后，不再次调用 ST 宏展开。此入口支持提示词构建中的宏，不承诺把新结果写进已经保存的用户消息。

群聊有外层 wrapper 和逐成员 Generate；不能每次 STARTED 都清空结果。以一次用户发送为单位检索，整个群聊回复批次共享。单独发送消息的命令、历史插入与第三方扩展调用不因一个孤立 MESSAGE_SENT 自动检索；仅接入已识别的 ST 主聊天发送流程。零回复成员的群聊不请求。

证据定位：ST `script.js` 的 Generate、sendMessageAsUser、getCharacterCardFields 和 stopGeneration；`lib/eventemitter.js` 的 emit；`scripts/group-chats.js` 的 generateGroupWrapper。项目当前事件桥丢弃消息下标且未接入生成生命周期，需要补充；现有宏已经采用同步快照模式。

## 查询与结果规则

查询只取本次已保存用户消息的正文：ST 输入正则与 ST 宏展开 → 读取消息正文 → trim → 空值及长度检查 → 检索。首版不增加插件清洗步骤或开关，现有填表清洗列表保持原有用途。长度沿用 `min(4000, embedding 连接输入上限)`，超长跳过并显示原因，不截断、不拼历史、不读取附件全文、不调用 LLM 改写。消息中的检索宏在保存前为空，查询阶段不再展开，输出文本也复用现有宏语法消毒，避免递归。

复用 VectorRetrievalService 的候选检查、余弦排序、记录去重、Top K、最低分与覆盖统计。自动召回和手动搜索复用实现、各持运行状态，互不取消；两者都可与索引请求并发。不等待补建、不触发补建、不自动重试，每次发送至多一次查询 embedding 请求。

### 绑定命名视图与条件筛选

召回直接绑定已有命名视图，支持全局记忆视图和当前对话的命名宏配置；每条绑定保存“作用域＋视图名＋向量组选区”。选择器显示作用域、所属表及条件摘要，固定引用用户选中的视图，同名全局视图与对话视图互不替代。首版不增加视图 ID 或召回配置库，不提供另一套内联条件编辑器；条件在原有视图管理入口维护，召回实时读取。

绑定使用视图的表和筛选条件，界面明确标注“使用该视图的表和筛选条件”。视图的显示字段、更新时间排序和条数上限仍用于原记忆宏展示，召回由相似度、全局 Top K 和输出字符预算控制，输出继续使用命中组字段。不会先展开原宏文本再做检索，也不会只搜索该视图当前显示的前几条记录。无条件视图可搜索该表全部符合索引要求的记录；内置 full／表 Key 宏不属于可绑定命名视图，需要时在现有入口创建无条件视图。

复用现有 MemoryViewCondition 和查询求值：单选／短文本字段匹配值集合中的任一完整值，例如“状态 ∈ 未完成、进行中”；“上海”不匹配“上海浦东”。条件值按字面解释，不额外展开宏。条件字段无需属于向量组，例如用“状态”筛选“事件正文”组，无需为筛选字段建向量。

执行顺序为：解析绑定并校验视图／表／组／条件 → 经现有 Memory 查询能力筛选每个视图的记录 → 在该视图所选组内检查有效索引 → 合并候选 → 向量匹配 → 记录去重 → 最低分 → 全局 Top K → 输出预算。多个视图取候选并集，同表也可绑定多个视图，但每个视图的条件和组选区保持成对：视图 A 匹配的记录只能使用 A 选中的组，除非该记录也符合视图 B。重叠的记录／组候选只计算一次，最终同一记录只输出一次；全部视图共用一次查询 embedding。

条件翻译为已有查询契约的 in，复用校验与求值。完整读取所有匹配记录的分页结果，再限定向量候选；不沿用原视图前 100 条限制，也不先取 Top K 再过滤。覆盖统计、缺失索引和任务提示仅针对候选并集，重叠目标不重复计数；面板展示本次实际视图、作用域、条件、组选区和匹配记录数。全部视图均无匹配记录时显示“没有符合筛选条件的记录”，零 embedding 请求、空宏继续；部分视图无匹配时继续检索其他视图。

绑定的视图删除、改名，或表／组／条件失效时，本次召回整体跳过并提示修正，不回落到其他同名视图、不忽略失效绑定。视图改名后需重新绑定；视图改目标表后原组选区失效，需重新选择。修改视图条件会撤下现有召回快照，下次发送使用新条件，不自动重查。相关记录字段值变更同样沿用现有失效规则，包括未参与向量化的筛选字段；不要求仅为筛选重建索引。

首版沿用原视图已有条件能力，不增加多字段组合、嵌套 AND／OR、包含匹配、数值比较或跨表关联。共享检索实现支持这些筛选后的候选范围，手动检索面板本轮保持现有入口。

宏按相关度顺序输出“表名／Key、记录 ID、命中组、命中组的字段文本”；分数及其他组详情放在面板。按整条记录装入字符预算，首条放不下时保留来源并截断正文、标注截断；后续记录放不下即停止，不用低分短记录替换高分记录。标题、来源和截断标记都计入上限；上限最低 500 字符，默认 4000。首条来源及标记本身已耗尽预算时输出为空，提示预算不足。面板展示实际查询、范围、状态、覆盖、耗时、命中数／输出数及与宏同源的实际文本，可查看原记录。错误说明留在面板，宏返回空串。

## 等待、异常与隔离

召回从进入准备到文本就绪固定最多等待 10 秒，首版不增加等待时长设置，包含本地检查、远端调用和文本整理；连接自身超时仍生效，先到者结束。超时必须释放 ST 的等待，即使远端不响应取消也不能继续挂起。请求期间可“跳过本次召回”，取消查询后用空宏继续生成。失败、无连接、无空间、非法范围、空输入、超长、无有效索引和空结果同样以空宏继续，并显示具体状态。部分索引可用时照常检索，提示可能遗漏。

ST 的“停止生成”同时撤销本次召回，保持 ST 的停止语义；切换对话撤销旧等待中的主生成及召回，不能解除等待后在新对话继续旧生成。事件监听器抛错会被 ST 捕获，不能依靠抛错实现停止，需使用 ST 已有停止入口与取消信号并实测。

新发送先清旧文本。用已有真实对话身份、对话切换代次、空间身份，再加当前发送身份判定结果归属；A→B→A、同空间不同对话、新发送替换旧发送、停止后远端迟到，都不能回填。只保留一个当前发送快照，不做历史快照库。设置、绑定、查询源消息编辑／删除、相关记忆或结构变更时撤下快照，不自动重查；纯补建沿用现有候选快照规则。本轮已经完成提示词构建后不追改已发提示词，不追求事务一致性。

## 各种生成入口

| 入口 | 首版行为 |
| --- | --- |
| 新用户消息、编辑后重新发送 | 新发送，清旧快照并检索一次；相同文字也重新请求 |
| 重生成、生成新 swipe | 不新增检索；仅复用同一查询源用户消息仍有效的快照，无快照或上次失败则空宏 |
| 续写、自动续写 | 不新增检索，沿用同一用户轮次的有效快照；没有则为空 |
| 切换已有 swipe | 不检索，不产生新快照 |
| 群聊 | 一次用户消息检索一次，各成员共享；群聊自动闲聊无新消息时不检索、空宏 |
| 普通空输入触发 | ST 若实际生成 send-if-empty 用户消息则正常召回；没有新用户消息则不检索、空宏 |
| dry run | 零请求，不改变真实召回状态；独立运行时检索宏为空，并发边界见下文 |
| quiet、impersonate | 零请求、空宏，不覆盖正常发送快照 |
| 插件填写／查询 Agent | 不参与自动召回，也不自动注入检索宏；现有 Agent 直接调用后端接口 |

“复用”仅指当前页面同一用户轮次的已准备文本；切对话、刷新、停止、失效后不恢复。宏在正常提示词构建阶段返回当前快照，面板预览直接读取快照；dry run 等排除路径不消费或污染它。ST 自身同次生成的工具递归不得额外检索。

真实 ST 验收发现，自动 token 预估会与正常发送交错；宏调用参数没有提供 dry run 作用域，且提示词构建跨越多个 await。首版保持简单：正常提示词构建期间优先提供本轮召回，并发 dry run 可能读到同一文本；独立 dry run 仍为空。两种情况都不额外检索、不清除正常发送资格或快照。预估 token 数因此不保证排除召回，不为此增加提示词队列或第二套等待机制。

## 验收与首版排除项

确认后用真实 ST 正常生成链路验收：在预设和角色卡放宏，延迟查询响应，检查本轮最终发送请求确实包含本轮命中，查询完成前不发主生成请求，同轮多次宏只产生一次查询。分别检查 Chat Completion 与 Text Completion 的提示词路径。还要覆盖超时、跳过召回、ST 停止、A→B→A、同空间不同对话、旧响应迟到、新消息失败不带旧结果、重复生成、swipe、续写和多成员群聊；dry run 与插件 Agent 的 embedding 调用数为零。远端延迟／错误可受控模拟，提示词构建必须走真实 ST。功能验收已完成，环境与验证范围见 summary.md。

筛选验收使用同一条件对比已有宏与召回的记录资格：范围外的高分记录不能进入宏，符合条件且位于第 100 条之后的高分记录不能漏掉，多个视图各自筛选后统一 Top K。覆盖同表多视图组选区不串用、重叠候选去重、全局／对话同名视图固定作用域、视图修改／改名／删除，以及无条件、多值精确匹配、条件字段不在向量组、零匹配、非法条件及字段变更；实际宏文本不得包含被条件排除的记录，零匹配不发查询请求。

首版不自动写 ST 预设，不使用 setExtensionPrompt，不加配置库、查询向量缓存、额外模型版本、共享故障阻塞、LLM 改写或重排、跨空间检索、附件检索、持久召回历史或复杂一致性设施。正式词汇和使用说明在选择确认后更新，本稿不提前改现有领域定义。

## 双方讨论结论与确认边界

Grill with Docs 的质询由主代理与 Astra Low 相互完成，不要求用户逐项作答。双方质疑过全局配置跨空间如何对应表／组：按 Key 猜匹配容易误选，删去选区又不满足原始需求，最终采用每对话一份简单配置。固定 10 秒、失败空宏继续、同轮重生成复用、正文只 trim、4000 字符命中组输出均纳入本稿方案。

双方接受两个首版取舍：独立 dry run 不请求且空宏，ST 的预估 token 数会少计召回（并发例外见上文真实验收发现）；超长 RP 消息跳过召回并在面板显示原因，避免静默截头／截尾改变查询含义。群聊嵌套开始事件、用户正文提前展开宏、失败后误用旧结果、手动搜索被取消、抛错无法停止 ST 等反例，已落实为上文规则和真实 ST 验收项。

用户明确要求绑定命名视图，替代此前“每表单独编辑条件”的建议。主代理与 Astra Low 进一步质询并采用“作用域＋名称”的直接绑定，避免删除对话视图后自动落入同名全局视图；同表多个视图保持条件与组选区成对，避免扩大候选。视图表与条件实时复用，展示字段、更新时间排序和条数上限留给原宏展示，召回保持全量候选与相关度排序。只更新本轮需求，不改动已完成独立检索的历史需求。

用户已确认本稿，并授权基于当前分支创建新 Worktree、提交需求文档及开始开发；完成后须用真实 ST 验证。
