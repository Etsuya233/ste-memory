# 初始化填表（ST 插件）

Status: ready-for-agent

## Problem Statement

SillyTavern 新对话开始时，记忆空间是空的：人物、地点等系统表没有一条记录。现有的填表任务只能以对话消息（同步楼层）为输入——新对话还没有消息，就无法让表格填写 Agent 初始化表格。用户必须等对话进行几轮、有了消息之后才能触发填表，或者去记录网格手工逐条录入，两种方式都很笨重。

## Solution

在 Tasks tab 提供「初始化填表」入口：一个多行文本框 + 触发按钮。用户在新对话开始时，把剧情设定/角色设定等文本粘进文本框，点击按钮——插件把文本框内容作为填表任务的 msg 输入（与楼层填表任务相同的 `{{msg}}` 占位符语义与消息编排路径），连同活动 Agent 提示词预设的内容一起喂给表格填写 Agent，由 Agent 依据表格定义的填写意图生成初始记忆记录变更并自动落库。初始化是填表任务管线的一种输入形态，不是新管线：任务行加 kind 区分（初始化 / 楼层填表），初始化任务无楼层、无台账、单块执行，与楼层填表任务共享单空间单活动任务守卫。

## User Stories

1. 作为用户，我想在 Tasks tab 的文本框中输入初始化设定并点击「初始化填表」按钮，以便新对话一开始就能初始化记忆表格，而不必先发消息再触发填表任务。
2. 作为用户，我想初始化时自动带上活动 Agent 提示词预设的内容，以便初始化遵循我配置的填写规则与消息编排。
3. 作为用户，我想文本框内容按 `{{msg}}` 占位符语义展开（预设引用时内容只出现在展开处），以便与楼层填表任务完全同构的编排行为。
4. 作为用户，我想预设未引用 `{{msg}}` 时文本框内容作为用户消息自动追加（保持现有旧行为），以便任何现有预设无需修改即可用于初始化。
5. 作为用户，我想 `{{worldbook}}` 占位符的扫描输入是文本框内容，以便初始化时世界书条目能被展开进编排消息。
6. 作为用户，我想初始化输入也应用当前对话选择的清洗规则列表（与消息路径一致），以便保持两种输入形态行为对齐。
7. 作为用户，我想初始化的记忆记录证据以快照模式保存文本框原文（source_type `init`、source_id 为任务 runId），以便在记录详情中追溯每条记录来自哪次初始化的哪段文本。
8. 作为用户，我想初始化任务与楼层填表任务共享单空间单活动任务守卫，以便同一记忆空间不会并发跑两个任务造成写入冲突。
9. 作为用户，我想初始化任务在任务历史与活动任务区显示类型标签（初始化 / 填表），以便区分任务来源。
10. 作为用户，我想初始化任务失败或中断后可以重试且复用原文本框内容，以便不必重新输入一遍设定。
11. 作为用户，我想初始化任务运行中可以看到状态并可取消（与楼层填表任务相同的任务状态机），以便误触发时能停止。
12. 作为用户，我想非空记忆空间也能重复触发初始化，以便补充初始设定（Agent 按表格填写意图自行合并，不做状态干预）。
13. 作为用户，我想文本框内容允许为空（仅凭预设内容初始化），以便预设已包含完整设定时不需要重复输入。
14. 作为用户，我想未配置 LLM 时提交立即报可读错误（与楼层填表任务相同的预检行为），以便快速发现配置问题。
15. 作为用户，我想初始化任务也写入填表日志（运行记录，块范围为合成值），以便事后复盘 Agent 的初始化填写过程。
16. 作为用户，我想未绑定空间/未保存对话时初始化入口不可用（与现有触发填表表单一致），以便不会在无空间状态下误操作。

## Implementation Decisions

- **任务行扩展**：`FillTask` 增加 `kind: "floor" | "init"` 与 `initText: string | null`（init 任务必填，floor 任务为 null）；`from/to/blockSize/chatId` 字段保留（init 任务写入占位值，不参与语义）。Dexie 表结构随 schema 版本升级迁移。
- **提交入口**：`FillTaskService` 新增初始化提交路径（`submitInit`，与 `submit` 并列）：
  - 校验：不做楼层范围校验；活动任务守卫（`createIfIdle`）与 LLM 配置预检完全复用；initText 允许为空字符串（trim 后为空不拦截）。
  - 任务行：`kind: "init"`、`initText` 持久化（retry 依赖）；`chatId` 快照与对话切换安全点检查保留。
  - 单块执行：初始化任务退化为单块（不做分块循环），块处理时合成单条来源消息（内容 = 清洗后的 initText，名字为空，楼层为占位值）。
  - 证据：不走楼层 reference 证据，构建单条 snapshot 证据（`source_type: "init"`、`source_id: 任务 runId`、内容 = initText 原文）；重复初始化每次生成新证据行（对同源唯一不冲突）。
  - 台账：初始化任务不读写楼层台账（`markProcessed`/`markError`/`statuses` 全部跳过）。
  - 清洗规则：与消息路径一致，块处理时实时读取当前对话所选清洗规则列表并应用。
  - 编排：`{{msg}}` 展开输入 = 合成消息文本；未引用 `{{msg}}` 时自动追加块提示词（现有旧行为，两处均不去掉）；`{{worldbook}}` 扫描输入 = initText。
  - 运行记录：照常写入填表日志，块范围为合成值。
- **任务视图**：`FillTaskView` 对 init 任务 `totalCount = 1`，`processedCount` 不查台账（进度轮询对 init 任务退化为状态展示）。
- **重试**：`retry` 对 init 任务复用持久化的 `initText` 重新走初始化提交路径（活动任务守卫冲突语义不变）。
- **UI（Tasks tab）**：新增「初始化填表」输入区（多行文本框 + 按钮），与现有「触发填表」楼层表单并列；无空间状态（未绑定/未保存）时禁用并提示；提交错误内联展示（复用现有报错样式）；任务历史与活动任务区按 `kind` 显示类型标签。纯逻辑进 `task-panel-model`（可测），组件只做投影。
- **术语**：UI 与用户文档叫「初始化填表」；`core/CONTEXT.md` 不新增术语；`apps/st-extension/CONTEXT.md` 的「消息内容占位符（{{msg}}）」条目已补充"填表任务输入源可以是同步楼层消息或初始化文本"的说明（grilling 会话已写入）。
- **不做**：楼层填表任务"未引用 `{{msg}}` 自动追加块提示词"的既有行为不在本功能内改动（用户后续单独处理）；不引入横幅/自动触发。

## Testing Decisions

- **原则**：只测外部行为——提交/重试后的任务终态、落库的记录与证据（snapshot 模式、内容为原文）、台账行数（init 任务不产生任何台账行）、与楼层任务的互斥、编排消息内容（`{{msg}}` 展开与自动追加两分支）；不测循环内部实现细节。
- **主 seam：`FillTaskService`**（扩展 `fill-task-service.test.ts`）：已有先例——fake-indexeddb 真库 + `scriptedStreamFn` 脚本化假 LLM + 假聊天源，覆盖任务生命周期、证据、编排、失败/取消/重试。新增用例：
  - `submitInit` 创建 init 任务并单块跑完 → 记录落库、snapshot 证据（source_type/source_id/内容）正确；
  - init 任务不产生台账行（`ledgerStatuses` 空）；
  - 清洗规则应用于 initText（喂给 Agent 的是清洗后内容，证据存原文）；
  - `{{msg}}` 引用与未引用两个编排分支；
  - init 任务与楼层任务 `createIfIdle` 互斥（双向）；
  - `retry` 复用 initText（不重新输入）；
  - 取消/失败路径与对话切换安全点（init 任务保留 chatId 检查）。
- **次 seam：`task-panel-model`**（扩展 `task-panel-model.test.ts`）：初始化输入区状态（空文本允许、空间不可用禁用）、任务类型标签映射。先例为该文件现有表单校验与视图模型测试。
- **repository 迁移**：`fill-task-repository.test.ts` 覆盖 schema 升级后旧任务行读取（缺省 kind 视为 floor）与 init 任务行的读写。
- **不做**：UI 组件级测试（TasksTab 投影沿用现有风格，由 model 测试兜底）；core 层无改动，无需 core 测试。

## Out of Scope

- 聊天区横幅/自动触发初始化（grilling 已否决，只做 Tasks tab 按钮）。
- 楼层填表任务"未引用 `{{msg}}` 自动追加"行为的改动（用户后续自行处理）。
- 模板填充式初始化（无 LLM 的结构化填空）——初始化始终走表格填写 Agent。
- 表格/字段/显示策略/清洗规则的修改；证据展示 UI 的改动（记录详情已支持证据，无需变更）。
- core 领域模型变更（初始化不引入新领域概念，纯应用层输入形态扩展）。
- 交互式填写（问答面板）的改动。

## Further Notes

- 设计树来自 grilling 会话（2026-08）：输入构成 = 活动 Agent 提示词预设 + 文本框内容；执行 = 复用填表任务管线；状态限制"不做过多的干预"（非空空间可重复触发）；证据 snapshot；清洗规则走；`{{msg}}` 两处旧行为都保留。
- `apps/st-extension/CONTEXT.md` 已同步补充说明（`{{msg}}` 条目）。
- 实现参照：`fill-tasks/fill-task-service.ts`（块循环、证据构建、编排）、`fill-tasks/fill-task.ts`（任务行与端口）、`ui/tasks-tab.tsx` + `ui/task-panel-model.ts`（触发 UI）。
