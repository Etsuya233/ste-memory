# 语义 SQL 函数方案讨论记录

2026-10-26。主代理与原 Astra Medium 进行四轮方案质询，Sol 6.1 Medium 负责真实 WASM 技术验证。用户已给出缓存、Agent 复用和参数选择方向，本轮由代理作出具体建议，没有向用户追加问题。

## 决策过程

| 议题                 | 反例或约束                                          | 收敛结论                                                                   |
| -------------------- | --------------------------------------------------- | -------------------------------------------------------------------------- |
| 原生函数与异步请求   | SQLite 虚拟表回调同步返回，embedding 是异步请求     | 注册 eponymous-only 虚拟表，缺源中断、外层准备、原 SQL 重执行              |
| 用空源代替待准备状态 | COUNT、LEFT JOIN、EXISTS 会提前认定结果为空         | 用结构化需求配合明确的中断，只发布最终成功轮；真空源须经过准备确认         |
| 固定两遍执行         | 第二个源可能只有第一源准备成功后才被访问            | 逐轮新增供给，最多 16 源、17 轮，SQL 和总等待预算累计                      |
| 禁止所有行关联参数   | UNION CTE 的两个绑定值逐行传入后 frombind 仍为 1    | 撤销这项承诺，允许 SQLite 原生表达式和有界行关联，每 SQL 最多 4 种查询文本 |
| 提前截取评分         | LIMIT 影响源会改变 JOIN、聚合和最终排名             | 源保持完整评分，SQLite 负责最终条件和数量                                  |
| 单组参数与多组参数   | 多组 UNION 后需正确取得最高分对应的组，用户容易写错 | 采用 groups_json 数组，服务保留现有每记录最高组分与稳定同分规则            |
| 跨执行缓存           | 记录变化后沿用评分会读到旧结果                      | 仅短期缓存成功查询向量；评分仅在固定记录及向量输入内共享                   |
| 连接缓存键           | 当前 profile version 未包含凭据变更                 | 增加请求配置 revision，连接修改隔离缓存，记录索引 profile 保持自身职责     |
| Agent 取消共享请求   | 一个工具超时可能杀掉同 run 其他工具的请求           | 在途请求按有效等待者计数，最后等待者退出才取消；run 结束取消剩余请求       |
| Agent 读视图         | 填表工具原本可读暂存修改，改读 committed 会破坏预期 | 首版只挂查询 Agent 的独立工具，每次调用固定新 committed 快照               |
| 旧来源自动重写       | CTE 同名遮蔽、schema、别名和字符串需要区分名称绑定  | 保留旧格式兼容执行，用户显式创建内联副本或转换草稿；不做词法替换           |

## 已验证事实与待开发边界

终审还明确了普通 SQL 的启用状态：用 prepare-only authorizer 的读取依赖分类语义 SQL，处理 COUNT 的空列名，普通 SQL 保留原有规则。Sol 已补直接调用、COUNT、CTE、子查询、WHERE 0 和绑定分支的真实 WASM 观测；未使用的 CTE 无 READ，不能将这项分类说成识别所有词法调用。旧格式继续按原预算执行，不套用新的动态发现限额，也不开放旧 sources 与内联函数混用。

Sol 用当前真实 SQLite 3.54.1 WASM 验证原生模块、缺源返回后 reset／reprepare、LIMIT 对完整假评分关系的取数，以及报错前已产生部分行的风险；同时复现了参数来源标记不能可靠拒绝所有行关联的反例。详见 [探针记录](./native-vtab-probe.md)。

探针没有实现真实 embedding、Agent 接入、生产 Worker、L1／L2、等待者计数及动态源预算。上述内容是 [需求文档](./spec.md) 的待开发验收项。没有把这轮技术验证写成新功能已完成。
