# 原生语义 SQL 函数、查询向量缓存与 Agent 工具

状态：本轮宏函数与缓存已实现并完成验证；Agent 接入按用户最新要求延期。日期：2026-10-26。

本稿由主代理与 Astra Medium 讨论，Sol 6.1 Medium 使用当前真实 SQLite WASM 验证原生虚拟表及重执行机制。用户明确要求 SQL 内联调用、相同输入缓存、Agent 等入口复用，函数参数由本次讨论选定。实施前用户补充本轮先不接入 Agent，并要求减少其 API 调用；本轮真实 embedding 验收预算为全体代理合计最多 3 次已发 POST，包含索引、失败与取消请求，优先使用合成向量验证。

## 1. 目标与范围

用户可以在一份 SQL 中表达向量评分、业务条件、关联、排序与最终数量，新 SQL 宏无需单独填写 sources JSON。SQL、Query 宏及查询 Agent 共用语义评分能力，保留现有全量有效索引评分、记录指纹检查、只读授权及生成时求值。

本轮交付原生 `semantic_scores` 表值函数、两层查询向量缓存、执行内评分缓存与宏接入。第 5 节查询 Agent 工具、run 级跨工具等待者所有权及 S12 的验收留到后续；现有 Agent 工具和读写视图保持原状。手动 SQL 控制台和手动检索界面本轮不接入新函数；共享服务接受明确的空间快照、连接及取消上下文，供后续复用。

本稿调整 [表达式宏需求](../macro-expression-refactor/spec.md) 中“跨生成重新请求查询向量”的约定：新生成仍重新取得记忆快照、评估 SQL 和渲染宏，查询向量允许命中短期缓存。宏结果继续只在实际生成或显式测试时计算，不恢复后台预计算，也不恢复 memoryRecall。

## 2. SQL 调用契约

```sql
semantic_scores(table_key, groups_json, query_text)
```

| 参数        | 类型与含义                                                                  |
| ----------- | --------------------------------------------------------------------------- |
| table_key   | 非空 TEXT，当前授权空间中启用表的定义 Key                                   |
| groups_json | TEXT，内容为非空、无重复字符串的 JSON 数组；元素为该表向量组的稳定 Key      |
| query_text  | TEXT，实际检索文本；去除首尾空白后使用，不拼历史、不展开宏、不调用 LLM 改写 |

参数均必填。向量组参数不接受字段 Key、显示名称或实例 ID，不推测用户意图；缺表、缺组、停用字段、无效 JSON、空数组、重复组、NULL、错误类型及空查询直接报错。查询文本沿用 4,000 字符本地上限，有已存向量时再遵守捕获连接的输入上限。每个源的表、组及调用方读取权限在该源发起网络请求前核验，缓存命中同样不能跳过这些检查；此前其他合法源可能已有请求。

原生参数表达式按 SQLite 正常求值，可使用字面量、绑定参数、`json_array(...)` 等表达式，也允许外层行提供不同参数；以实际求值后的 TEXT 值生成评分源。不能声称已经通过 `frombind` 标记禁止所有行关联参数，技术探针已给出反例。动态输入受第 6 节资源上限约束。

输出列为 `record_id TEXT`、`score REAL`、`group_key TEXT`。每条有有效向量的记录输出一行；多个组选最高余弦分数，同分按组 Key 的稳定字典序选组，分数范围为 [-1, 1]。输出不隐含阈值、Top K、最终排序或投影。

```sql
SELECT e."summary", e."details", s.score
FROM "chronicle" AS e
JOIN semantic_scores(
  'chronicle',
  '["event_memory"]',
  :last_user_message
) AS s ON s.record_id = e."$record_id"
WHERE e."plot_summary" IS NULL AND s.score >= 0.3
ORDER BY s.score DESC, e."$record_id" ASC
LIMIT 10;
```

多组写法：`semantic_scores('chronicle', json_array('event_memory', 'summary'), :query)`，实际组 Key 由表配置决定，示例不代表所有表都有这些组。等价组集合归一为排序后的 Key 集合用于缓存，输入中的重复组仍报错。

宏继续自动绑定 `:last_user_message`，没有用户消息时为 NULL；将它传入函数会产生明确的输入错误。普通宏 SQL 可以继续将该 NULL 用于其他条件。Agent 工具不自动读取 ST 消息，必须显式提供绑定值。

无有效索引的源是合法空关系：INNER JOIN 无行，LEFT JOIN 可保留业务记录，COUNT 可返回零。缺失、过期和异常向量分别统计。不等待或触发索引补建；无记录或无存储向量可以免连接和请求，有存储向量而未配置 profile 则报错，沿用现有语义。

## 3. 原生扩展与异步准备

采用 SQLite eponymous-only virtual table，通过 `sqlite3_create_module` 注册；WASM 使用现有 JS 虚拟表接口。函数参数映射到隐藏列，`xBestIndex` 选择必需的等值参数约束，`xFilter` 接收参数，游标回调返回评分行。各游标独立持有行集和位置，支持同一语句中的多次调用、CTE、UNION 和关联。

查询 embedding 和全源评分保留在异步服务层，虚拟表同步读取已经准备好的完整评分关系。执行采用以下协议：

1. 固定记录快照、读取权限、连接配置和本次预算，注册只读模块，prepare 并绑定 SQL。
2. `xFilter` 校验实际参数。已有评分源则返回行集；遇到未准备源，记录该语句的结构化准备需求并返回明确的中断状态。
3. 外层核对结构化需求，丢弃本轮全部已产生结果、结束本轮 statement，再异步准备查询向量与完整评分。
4. 在同一输入快照和会话上重新 prepare 原 SQL、重新绑定，从头执行；多源可能需要多轮，成功后才发布结果。

“需要准备语义源”使用会话和语句局部的结构化状态，例如 `{status: "needs-semantic-source", requests: [...]}`。不能只凭错误文本或任意 SQLITE_ABORT 触发外部请求。真实 SQL 错误、参数错误、embedding 失败和取消直接结束；不自动重试网络请求。若已供给的同一源仍报告缺失，按实现错误结束。

缺输入时不能返回占位空表，否则 COUNT、LEFT JOIN、EXISTS 和短路条件会把尚未计算的结果当真。中断前可能已有部分结果，必须整轮丢弃。源无有效向量时经过准备后得到的真实空关系才可以参与 SQL。

首版不消费 LIMIT/OFFSET 约束，不声明 `orderByConsumed`，由 SQLite 决定最终取数；不能把作者的 LIMIT 提前用于评分源。SQLite 短路、空外表或结果上限可能使某些函数调用未实际执行，此时无需请求其评分，也不承诺预先发现 SQL 文本中的所有源。

原 SQL 可能从头执行多次。非确定表达式在各轮会重新求值，例如随机生成查询文本可能不断形成新源，最后触及资源上限；已经完成的少量请求可能计费。不能冻结首次随机值来改变 SQL 行为，也不保证表达式只求值一次。建议业务查询使用显式绑定的稳定文本。

模块职责分为三处：宏层绑定消息输入并渲染结果；共享语义查询服务负责快照约束、连接、缓存与源准备；SQLite 适配器负责模块、游标、授权及结构化执行状态。Agent 工具向共享服务提供参数、权限、committed 快照和取消上下文，不调用宏服务或检索页面状态服务。

## 4. 缓存与取消

### 4.1 执行范围

宏的一次生成批次共享记录快照和查询向量上下文；群聊批次及同次工具递归沿用已有批次定义。本轮在途请求由整个批次拥有，单个宏失败不取消其他宏的等待。后续 Agent 方案为一次 run 共享查询向量上下文、每次工具调用另取新的已提交快照，尚未接入。

Query 宏、SQL 函数和旧格式语义源均通过同一评分服务。显式测试拥有独立结果与评分会话，可以使用查询向量缓存，但不覆盖真实生成的结果。

### 4.2 两层查询向量缓存

| 层级 | 范围与内容                                        | 规则                                                                                   |
| ---- | ------------------------------------------------- | -------------------------------------------------------------------------------------- |
| L1   | 同一有效执行上下文内的在途 Promise 与成功查询向量 | 相同连接配置和实际文本共享一次请求，多个表、组、宏及重复扫描可以复用                   |
| L2   | 当前插件运行实例内的成功查询向量                  | 绝对 TTL 5 分钟、最多 64 项、向量与键的逻辑载荷最多 8 MiB；按 LRU 淘汰，读取不延长 TTL |

L2 只存成功、有限、维度合法的查询向量，不存记录、评分或 SQL 结果，不持久化、不备份、不镜像。单项超过载荷预算时跳过 L2，仍可用于当前执行。载荷按规范键的 UTF-8 字节数与向量数值每项 8 字节合计，不含运行时对象开销；8 MiB 不代表浏览器总内存峰值。跨执行上下文不共享在途请求，只共享已经成功的向量；两个独立上下文同时 miss 可以各发一次请求，同一 Agent run 内的工具共享其 L1。

键包含实际送往 embedding 的 trim 文本、捕获的连接身份及请求配置 revision、模型、向量语义 profile 与维度配置。凭据、端点、模型或维度变化必须隔离缓存；凭据变更无需因此重建记录索引。当前 `getProfile().version` 仅包含端点、模型和维度，实施时须补充独立的请求配置 revision，不能直接拿它充当完整缓存键。密钥不出现在诊断、导出或可打印的缓存键中。

缓存查询向量与缓存评分分开。评分只在相同记录快照、已捕获向量输入、profile、表、组集合和实际文本下复用；下一生成或新工具调用重新计算评分。SQL 输出和宏渲染结果不跨执行缓存。补建索引、编辑记录后，相同文本可以命中查询向量，评分仍反映本次有效数据。

### 4.3 取消的所有权

本轮宏实现由批次统一拥有和取消请求；以下 Agent run 级引用计数为后续要求，不作为本轮已实现能力。

同一 Agent run 的共享在途请求记录有效等待者。一个工具超时只结束自身等待与 SQL 会话，其他工具仍可等待共享请求；最后一个等待者退出时，从 L1 移除并取消底层请求。run 结束取消全部在途工作，宏批次也由自身信号拥有请求。

迟到回调按请求实例身份操作缓存，不能删除同 key 的新请求。L2 仅接收仍有有效等待者、所属上下文活跃且连接 revision 有效的成功结果。取消、超时、失败和无人等待的迟到成功不写入缓存；之后的新调用可以重新请求。“同输入一次”指有效在途共享与成功缓存，不把一次失败固定成整个 run 永久失败。

## 5. 查询 Agent 工具（后续）

工具名为 `query_semantic_sql`，首版挂载查询 Agent；调用格式如下：

```json
{
  "sql": "SELECT e.\"summary\", s.score FROM chronicle e JOIN semantic_scores('chronicle', :groups, :query) s ON s.record_id=e.\"$record_id\" WHERE s.score>=:minimum ORDER BY s.score DESC LIMIT 10",
  "params": {
    "groups": "[\"event_memory\"]",
    "query": "古桥事故中红色披风人物的线索",
    "minimum": 0.3
  }
}
```

`sql` 必填，`params` 可省略为空对象；值接受字符串、有限数字和 NULL。只开放 `:name` 命名绑定，键不带冒号；缺少或未使用的显式参数报错，位置参数、`@name`、`$name` 不开放。重复参数沿用 SQLite 同名绑定语义。表和字段标识符按 SQL 正常引用，参数不能替代 FROM 后的表标识符。

每次调用固定新 committed 快照、权限和连接，不读取 ST 当前输入或宏文本。摘要提供可用表 Key、字段 Key、启用向量组 Key 及所含字段，让模型能发现合法参数；缺少连接或索引时说明原因，不伪造结果。

返回列顺序、行、截断状态、各源索引覆盖和执行诊断。沿用现有 Agent 100 行展示上限并探测第 101 行，明确是工具返回上限；函数评分源仍完整。工具说明要求模型区分“SQL 没有命中”与“没有有效索引”，不能据零评分行断言记忆中没有相关事实。工具错误返回可读原因、实际发起请求数、L1 在途／成功命中、L2 命中和准备轮数，不返回部分 SQL 行；同一次共享请求的发起数只归属创建该请求的一方，命中方不重复累计。现有 `query_sql` 保持原有读视图，填表 Agent 不自动改成读取 committed 的语义工具。

共享服务不依赖 ST 宏注册或提示词 UI。填表 Agent 的 write 快照、未提交记录及有效索引规则需单独设计后再接入，不能声称所有 Agent 已经支持该工具。

## 6. 一致性、权限与资源

所有重执行轮次使用同一记录快照与权限。向量列表按表首次读取后固定并复用，用本批正文、引用显示、字段、组和 profile 核验指纹；跨库仍不承诺同瞬时事务。重执行时不能重新读取同一表的新向量版本。

| 限额         | 首版约定                                                                               |
| ------------ | -------------------------------------------------------------------------------------- |
| 总等待       | 宏沿用同批 10 秒共享截止；每次 Agent 工具调用最多 10 秒，且受 Agent run 的剩余时间限制 |
| SQL 执行     | 各轮 prepare／VM／游标工作的累计预算 1 秒，不在缺源重执行时重置                        |
| 不同评分源   | 每条逻辑 SQL 最多 16 个规范化的表／组集合／实际文本三元组，空源也计数                  |
| 不同查询文本 | 每条逻辑 SQL 最多 4 种 trim 文本，缓存命中同样计入逻辑种类                             |
| SQL 轮数     | 最多 17 轮；每次重执行必须至少供给一个新增评分源                                       |
| 最终行数     | 宏最多 10,000 行，超出报错；Agent 保持 100 行加 101 探测与截断说明                     |

上限先检查、后发起下一项 embedding。16 源和 4 文本作用于一条 SQL／一次工具调用；多个宏或多次 Agent 调用可能累计更多，不能将其宣传为整个 run 的收费上限。错误和超限不会返回部分 SQL 结果，已发生的 API 请求保留诊断；索引构建请求不计入“查询向量请求数”。

虚拟表只注册在显式支持语义查询的隔离会话。SQL authorizer 继续拒绝写入、事务、PRAGMA、内部表和越权列；函数参数中的表名需额外按调用方允许集合校验，authorizer 不会自动检查字符串所代表的业务表。`xBestIndex` 不启动网络。函数名和业务表 Key 的冲突应在会话准备时明确报错，不自动改名或覆盖用户表。

每条 statement 的 pending 状态、游标和评分缓存隔离。超时、取消、切对话和关闭时清理 statement、游标、会话与在途等待；关闭保持单次所有权，延迟创建和迟到响应不重开会话、不发布旧结果。

## 7. 宏编辑与旧格式

新 SQL 宏编辑器只要求 SQL 正文，提供内联函数示例、表／字段／向量组 Key 说明及输出设置。Query 宏保留当前 JSON 体验，语义评分走共享服务。新建、复制及导入的语义宏继续默认停用；保存后的 enabled 语义沿用既有规则，不因缓存自动启用。

语义 SQL 的识别采用 prepare-only 阶段按语句记录的 authorizer 读取依赖，包含 `semantic_scores` 的读取时标为语义宏，COUNT 场景的空列名同样处理；不做正则搜索，也不使用可能只在连接初始化时发生的 `xConnect` 判定单条 SQL。普通 Query／SQL 沿用原有启用及复制规则；新建、复制、导入的语义宏默认停用。未使用的 CTE 可能不触发 READ，这项分类不声称识别文本中每个词法调用；按实际编译依赖处理。生产 Worker 的分类准确性需覆盖 CTE、子查询、COUNT、WHERE 0 和绑定分支后验收。用户显式启用后，错误与停用的同名遮蔽规则不变。

保存、预设导入及应用使用 prepare-only 验证，不 step SQL，不查评分、不请求 embedding。可校验语法、只读权限、列名和参数名称等静态条件；`xFilter` 才能检查的实际值、动态源和输入类型在执行时校验，不能宣称保存成功就证明所有参数合法。

已有非空 `sources + sql` 定义保留原值、启用状态和兼容执行，原 SQL 继续引用受控临时评分表，评分改用共享服务与缓存。缺失 sources 或空数组可以无损归一为普通 SQL，无需进入旧格式编辑限制。旧定义完整只读展示来源及 SQL，允许改名、启停和调整输出；表达式迁移通过创建内联副本或显式转换草稿、测试后保存完成。转换失败保留旧定义，不能因升级丢弃或静默停用原宏；新复制或导入的旧语义定义仍遵守语义宏默认停用规则。

旧格式的评分源预先明确声明，沿用原有一次 SQL 执行、10 秒总等待、1 秒 SQL 和最终行数预算，不套用新增动态发现的 16 源／4 文本／17 轮限额。非空旧 sources 与新内联函数混用明确拒绝，转换后保存为单一内联格式。

不自动做标识符 token 替换。例如 `WITH episode_scores AS (...) SELECT ... FROM episode_scores` 中的名称可能绑定 CTE，简单替换会改变语义；schema 限定、别名及字符串同样需要处理。保留旧格式的执行不要求新增完整 SQL AST 解析器。

原有 ST 接入边界保持：主要提示词、角色卡及世界书在计算后展开；本轮用户消息保存前展开的宏无法使用随后结果。并发 quiet 的无身份结束事件、取消门禁加载顺序及群聊实际验收范围继续按 [既有实现记录](../macro-expression-refactor/implementation.md) 说明，不把新增 SQL 函数当成这些问题已解决。

## 8. 实现顺序与技术门禁

1. 在生产 Worker 的隔离会话接入原生虚拟表，确认 authorizer、结构化缺源状态、游标清理和参数绑定工作正常。
2. 从宏求值器抽取共享评分服务，固定 snapshot／向量输入和连接，落实重执行、累计预算及原子结果发布。
3. 加入 L1 等待者所有权与 L2 成功向量缓存，覆盖连接变更、失败、取消及迟到响应。
4. 本轮接入新 SQL 宏及旧格式兼容路径；查询 Agent 工具和向量组摘要扩展后续另做。
5. 本轮完成真实 ST 宏与缓存验收，控制实际 API 次数；真实 Agent 工具链验收留到后续。

已有 [真实 WASM 探针](./native-vtab-probe.md) 证明模块注册、来源标记反例、中断后 reset／reprepare、部分行风险和 prepare-only 读取依赖分类；它使用假评分，没有验证生产 Worker、Agent、资源限额、共享取消或真实 embedding。这些均是开发验收项，不能沿用上一轮宏验收结果替代。

## 10. 依据与讨论结论

本轮 S12，以及 S06／S07／S09／S10／S16 中的 Agent run、跨工具等待者和 Agent 工具调用条目均延期；宏侧采用批次统一取消。实际测试范围、API 计数和产物身份见 [实现与验收记录](./implementation.md)。

官方机制：[SQLite 虚拟表与表值函数](https://www.sqlite.org/vtab.html)、[WASM JS 虚拟表接口](https://www.sqlite.org/wasm/doc/trunk/vtab.md)、[规划期 RHS 取值](https://www.sqlite.org/c3ref/vtab_rhs_value.html)、[运行时值来源](https://www.sqlite.org/c3ref/value_blob.html)。本次本地反例和可复现脚本见 [探针记录](./native-vtab-probe.md)。

当前代码依据：[宏求值器](../../src/features/macros/macro-evaluation.ts)、[宏 SQLite 端口](../../src/features/macros/macro-evaluation-port.ts)、[SQLite 引擎](../../src/infrastructure/sqlite/engine.ts)、[现有 Agent SQL 工具](../../src/features/agent/tools/query/query-sql-tool.ts)、[查询 Agent](../../src/features/agent/query-agent.ts)、[向量连接适配器](../../src/infrastructure/sillytavern/embedding/openai-embedding.ts)。

讨论的主要取舍是：原生虚拟表避免执行期 SQL 改写；异步源缺失通过明确中断处理；来源标记的真实反例促使参数采用有界动态语义；查询向量可短期复用，评分保持快照约束；Agent 首版独立工具读取 committed，避免改变填表读写语义；旧定义保持兼容执行，不冒险自动改写。
