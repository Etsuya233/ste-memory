# 填表日志改为三级行流（任务 / 批 / 请求）

一次填表任务的日志按「任务 → 批 → 请求」拆成多行通用日志（key = 任务 runId），边跑边写：`fill-task` 在任务开始/结束各一条（kind、range、batchSize、状态、耗时）；`fill-run` 每批开始/结束各一条（批号、楼层区间、状态、耗时）；`fill-agent` 每次 LLM 请求一条，携带该轮**新增**消息与模型输出（思考、文本、停止原因、用量、工具调用参数；工具结果落在下一请求行的 messages）。批内首条携带系统提示词与预设消息快照，历史上下文批内不重复记录，批内拼接即该批完整 Prompt；载荷为 Pretty JSON 文本。

这修订 ADR 0008 的实现形态（快照原则不变）：完整 Prompt 仍是受控例外，但不再是"一条大记录嵌套全部轮次"，而是直接可作为查询结果展示的行流——单行可读、运行中每完成一轮即可查询可见、体积不随轮次重复携带上下文膨胀。

不选方案：单条大记录含 turns 数组（展示需解码、批结束前不可见）；每请求记录完整请求与历史（体积随轮次增长）；生命周期只记任务级（丢失每批成败的实时可见性）。
