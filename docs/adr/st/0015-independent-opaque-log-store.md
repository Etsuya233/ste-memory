# 日志模块：独立数据库 + 不透明文本 + 查询式刷新

日志从主库的 `memoryLogs` 表迁出，成为**独立数据库**中的行：每行只有 `{type, key, level, text, createdAt}`，`text` 是不透明文本（写入方自行组织，填表日志写 Pretty JSON），查询侧按类型/级别/key 过滤后原样展示、不做任何业务结构解析；刷新由用户点击「查询」触发，不引入推送、轮询或订阅。全局 1000 行上限与修剪保留。

独立性是刻意的：日志是审计数据而非记忆数据——不参与云同步、备份与对话文件镜像（ADR 0008 原有边界），且**不随记忆空间删除级联**（行内不再有 spaceId）；旧主库 `memoryLogs` 不迁移、不读取、不删除（原地留在旧库中）。

不选方案：主库新增表（日志 schema 仍牵动主库版本，级联语义纠缠）；保留结构化 data + 查看器按类型解码（正是被废弃的复杂度来源）；订阅/轮询实时刷新（手动查询已满足实时性要求，推送与业务耦合更重）。
