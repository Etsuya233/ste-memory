# 移动端优先的新前端入口

用户决定全量重写前端，首轮完成记忆记录的列表、详情、编辑保存和对话切换。
沿用 React、TypeScript、Tailwind 4、shadcn Base UI / Luma 与 esbuild。
所有宽度使用列表 → 详情 → 编辑这一套页面流程。桌面允许调整窗口尺寸、定位、留白和导航布局，
当前使用可移动缩放窗口与左侧紧凑导航；窄屏使用全屏面板与底栏。
持续维护的开发规则见 [前端开发规范](../../ui/frontend-development.md)。

## 入口与依赖

`src/frontend/index.ts` 为默认插件构建入口。`bootstrap` 启动原有 runtime 后调用
入口提供的挂载函数。新 App 通过记录工作区消费表格、字段和记录服务；ST 对话状态、
消息楼层与文件写回状态集中在 `frontend/host` 接线。SQLite、IndexedDB、镜像及任务服务沿用。

旧 `src/index.ts`、`src/ui/kit` 和旧页面源码继续保留，默认构建不引用旧面板。
新样式入口为 `frontend/theme.css`，不合并旧 kit 或页面 CSS。
这替代 ADR 0028 中逐页混合新旧 UI 的迁移策略。

通用组件仍位于 `ui/primitives`，新前端仅复用旧 UI 中无 React 的表单值转换逻辑。
不增加路由、全局状态库、表单配置引擎或通用组件适配层。

## 对话与编辑

`RecordsWorkspace` 维护本次页面生命周期内的记录状态。草稿按对话身份与空间配对保存，
外部 ST 对话切换立即使旧读取失效；返回原对话时恢复草稿并重新检查字段结构与记录修订。
上下文代次同时处理 A → B → A 与同空间不同对话，过期读取的成功和失败均不发布。

保存前检查真实宿主上下文，提交使用草稿的原空间、原记录及 `expectedRevisionId`。
已开始的保存可在切换对话后结束，结果仅归属原编辑会话。失败保留草稿；提交后的宏刷新错误
单独展示，避免误报提交失败。持久化错误通过原有镜像状态与重试入口显示。
提交后失败通过公开的 `MemoryRecordSaveError` 携带精确已提交记录；重试只执行快照缓存和文件写回，
不重放业务变更。原始修订冲突仍按未提交处理，数据库层的事务工具路径保持原有语义。

主动返回、取消或关闭时，未保存修改通过 shadcn AlertDialog 确认，初始焦点在“保留编辑”。
浏览器刷新使用 beforeunload 提示。保存期间禁用重复提交和主动离开，外部 ST 切换仍可发生。
草稿只在本次页面生命周期保留，未承诺跨刷新恢复。

## 宿主边界与验证

采用普通 DOM，保留 `ste:`、局部主题、important 工具类、生成 CSS 命名空间和原生 popover。
菜单、Tooltip 与 AlertDialog 共用面板内的 Portal 容器。
独立预览通过同一 esbuild 配置、样式编译与真实页面运行，仅注入内存服务。
浏览器验证覆盖草稿、异步切对话、失败重试、冲突、移动布局及键盘焦点。
独立预览不替代真实 ST 对话文件持久化验收。
