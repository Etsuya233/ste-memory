# ADR 0022 — 独立命名清洗规则，先排除后保留

## Status

Accepted（2026-10-25，用户确认）

## Context

ADR 0021 保留了“列表内多个规则”的结构和先保留后排除的顺序，界面仍有多余层级。
先提取会剥去外层排除标签，使思考区域中的正文片段混入结果。

## Decision

- 每份命名清洗规则直接包含 id、名称、启用状态、排除标签对数组、保留标签对数组。
- 全局可保存多份规则，对话选择其中一份，没有子规则数组、串联执行或排序。
- 固定先从原文删除排除区域，再从剩余文本提取保留内容，两组内均为 OR。
- 例：排除 `<think>`、保留 `<正文>` 时，`<think><正文>草稿</正文></think><正文>正式</正文>` 输出 `正式`。
- 保留组为空则输出排除后的全文，有配置但未命中则输出空文本；其余标签配对语义沿用 ADR 0021。
- 选择页点击规则即进入编辑；名称和标签同一草稿保存，可直接测试当前草稿，没有中间详情页。
- 清洗测试仅展示原文、结果和未保存状态，和填表共用单规则执行函数。
- 填表任务开始时冻结所选规则，后续批次沿用快照；未选择或停用时使用原文，证据保持原文。
- 独立清洗 schema 升到 v3，设置字段为 `cleaningRules`，直接丢弃 v1/v2 列表。
- 对话选择载荷改为 `{ version: 3, ruleId }`，沿用历史存储键以清除旧指针；其他设置与 metadata 不变。

## Consequences

旧版开发配置需要重新创建。去掉列表层后，UI、任务输入与测试工具都只处理一份规则。

## Validation

- 全量 Vitest：135 个文件、1475 项测试通过，覆盖单规则选择、先排除后保留、填表输入、草稿测试和 schema v3。
- Browser Use 验证新建直接编辑、保存直接返回选择页、已保存配置再次编辑、草稿清洗结果与 390px 窄屏布局。
- 生产构建仍经现有 Junction 提供给 ST；浏览器交互验收使用独立预览。
