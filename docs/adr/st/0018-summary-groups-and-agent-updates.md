# 总结归组校验与提案字段累计

剧情记忆预设的模拟运行暴露出查询值类型转换、连续更新丢字段和总结来源漏关联问题。此次修复保持统一 Agent 填表：Agent 查询来源、撰写总结、提交归属；程序检查可计算的一致性，不代写内容。

查询工具用 JSON Schema 联合 type 表达合法值类型，防止工具运行库按 anyOf 首分支改写 null、数字和布尔值。连续 update 累计字段，同字段后写覆盖，null 明确清空；create 和跨操作替换沿用原契约。

表格预设可携带 summaryRules，包含来源表 Key、总结表 Key、归属字段 Key、每组条数和保留条数。规则复制进记忆空间，随预设导入导出、空间备份和克隆保留。旧空间缺省无规则，不根据预设名称推断。修改表/字段 Key 时须同步调整规则；配置失配明确报错。

每次 Agent 开始时固定已提交来源快照。剧情记忆规则为每组 15 条、至少保留 5 条；只有快照中未归组来源达到 20 条才能新建总结。每轮最多一条，来源必须恰好等于按创建时间升序、ID 次序取出的前 15 条。本批新增来源不参与。预览和提交共用校验，遗漏、多选和引用错误均返回具体记录 ID。

规则可指定来源与总结的起止日期时间字段。总结开始取来源开始时间最小值，结束取来源结束时间最大值；单条来源未填结束时使用其开始时间，全部未知时对应边界留空。校验同时考虑本次提交对已保存来源的时间更正，错误时告知期望边界，由 Agent 修正。

增加显式 compact 读取宏：保留总结和未归组来源，已归组来源继续存储并可查询。呈现顺序为总结、未归组来源、其它表，减少字符上限截断前未读到总结的问题；上限仍可能截断后续内容。原有默认、full 和单表宏保持各自读取契约。短时场景过程集中于纪要，人物近况与关系字段仅保留持续状态、定性、转折和承诺。

填表运行提供可配置总超时，默认十分钟，保留硬中止和取消；已显式设置的时限保留。十二批实测中单批接近五分钟，故增加默认余量。修复后用相同模型、输入、20 条一批的十二批实验对照，逐请求留存日志，比较工具错误、归组一致性、重复、用量与耗时；单次生成差异不作为统计显著性结论。
