# 总结填写回归预设 Prompt，保留通用填表修复

状态：2026-10-21 修订。原方案中的专用总结配置、归组校验和 compact 宏已撤回。

十二批模拟曾暴露出查询值类型转换、连续更新丢字段和总结来源漏关联问题。初版增加 summaryRules 配置、固定来源快照与归组校验，但这进一步引出了界面配置、表和字段 Key 变更、删除依赖及导入导出的维护需求。用户确认保持表格预设和统一 Agent 填写的简单模型。

## 当前决定

删除 summaryRules 数据模型、传递和序列化声明，移除运行前的来源选择、总结专用预览/提交校验，以及依赖规则的 compact 宏和界面展示。无需为总结增加独立配置入口或依赖维护机制。

纪要与剧情总结表保留，纪要通过“所属总结”引用维护来源归属。总结时机、查询方法、来源选择、全部来源关联核对和时间边界写进预设 Prompt，由同一个填写 Agent 执行。每轮先查询已保存未总结纪要，满 20 条时取较早 15 条，每批最多一条，总结后至少保留 5 条；本批新建来源留待以后处理。起止时间沿用所选来源的最早开始与最晚结束，来源修订时同步修订总结。

程序沿用通用字段、格式、引用和提案校验。总结规则属于模型填写约定，执行可能存在偏差。默认及 full、单表、视图宏维持现有行为，已归组纪要继续保存；自动筛选注入内容暂不实现。修改 Key 后由用户同步维护相关 Prompt，更新内置预设不会改写已有空间。

## 保留的通用修复

查询工具用 JSON Schema 联合 type 表达合法值类型，防止工具运行库按 anyOf 首分支改写 null、数字和布尔值，并明确系统字段的查询用法。连续 update 累计不同字段，同字段后写覆盖，null 明确清空；create 和跨操作替换沿用原契约。

填表运行提供可配置总超时，默认十分钟，保留硬中止和取消，已有显式时限保留。人物近况、关系和纪要的 Prompt 继续明确职责与减少过程重复。

此前十二批实验及末批补跑验证的是撤回前的实现，不能直接作为当前纯 Prompt 方案的运行成绩。本次简化通过现有自动测试、类型检查与构建验证，不重新调用模型进行十二批模拟。
