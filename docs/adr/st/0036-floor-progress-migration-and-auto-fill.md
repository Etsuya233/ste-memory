# 旧楼层进度迁移与自动填表时机

日期：2026-11-03。状态：已实现。

## 问题

旧楼层进度保存在 IndexedDB 的 `floorFillLedger`，部分旧聊天快照没有台账。
数据库 v13 曾直接删除旧表，文件迁移又将缺失台账转换为空数组；自动调度把空数组解释为从 #0 待填。
启动、切聊及每秒轮询均可能创建任务，导致打开旧对话立即重填历史。

## 决策

对尚未执行删除的数据库，修正 v13 升级以保留旧表，v14 声明迁移表。
已运行旧 v13 的浏览器只能重建空表，无法从已删除表恢复数据。
旧空间正文仍不迁移，旧任务记录不用于推断成功范围。

加载聊天时，文件中非空台账完整保留。文件台账为空时，
仅对 v2 绑定的聊天身份精确匹配当前文件的情况读取对应空间旧台账。
移植文件、分支与缺少文件身份的 v1 绑定不自动借用本机台账。
旧台账经过现有完整性校验，与记忆正文组成同一个候选，沿用保存、回读核验与失败重试。
核验成功且原聊天仍活动、空间归属匹配后才清理对应旧台账。失败或切聊保留旧数据与待核验候选。

没有进度时使用空台账，从 #0 计算待填范围，不区分“未填写”和“旧进度缺失”。
不增加进度确认状态、人工确认流程或相应的持久化字段。

进入或刷新对话只恢复状态，符合间隔的范围先通知。
自动模式等待同一次有效生成的 MESSAGE_RECEIVED 与 GENERATION_ENDED 后，
按最新台账、间隔、延迟楼层与队列范围重新计算。每个有效回复只授权一次新增任务检查，
后续轮询和设置修改负责状态维护，不自行创建自动任务。
quiet、impersonate、dry-run、没有收到有效 AI 楼层的失败和停止生成不授权。
切聊清除授权，返回后重新等待；原中断任务经用户明确确认仍可恢复。
共享队列同时检查自动任务的启动许可，防止手动任务带动后续旧自动项提前执行。
自动任务按已入队范围执行，启动时不额外调整起点。

## 验证边界

回归覆盖旧数据库保留台账、已删除 v13 空表、原文件迁移、核验失败重试、切聊隔离、
空台账从 #0 计算范围、按已入队范围执行、启动通知和真实运行时事件桥授权。
不承诺恢复已删除的 IndexedDB 数据，不从任务申请范围自动重建进度。
