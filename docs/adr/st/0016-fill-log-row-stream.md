# 填表日志改为「任务 / 批 / 决策」三级：任务起止、批起止、上下文 + 逐轮决策行

一次填表任务的日志按「任务 → 批 → 轮次」拆成通用日志行（key = 任务 runId），边跑边写：

- `fill-task` 任务开始/结束各一条：kind、range、batchSize、状态、耗时；
- `fill-run` 每批开始/结束各一条：批号、楼层区间、状态、耗时；
- `fill-agent` 每批一条**上下文行**（kind: context——该批系统提示词、预设消息与本批消息
  分列，批开始即写），此后**每轮一条决策行**（kind: turn，round 从 1 递增——思考、输出文本、
  停止原因、用量、工具调用参数及结果，工具调用与结果同轮成对；失败轮 error 级并携带
  errorMessage）。

历史上下文与系统提示词不在轮次行重复；批内「上下文行 + 各轮次行」拼接即该批完整决策轨迹。
载荷为 Pretty JSON 文本。

**采集走 Agent 事件订阅**（runFillAgent 的 `onEvent` 通道，Agent 循环的 turn_end 事件）：
循环每轮结束必发 turn_end，携带该轮最终助手消息与工具结果（工具轮带结果，stop/error 轮为
空数组）——输出侧与工具结果在同一条事件里成对，无需请求快照、无需批内去重。
输入侧（系统提示词/预设/本批消息）由宿主组装时直接提供，不走 LLM 采集。

这修订 ADR 0008 的实现形态（快照原则不变）：完整 Prompt 仍是受控例外，但呈现为
「上下文行 + 逐轮决策行」的行流，单行可读、边跑边写（上下文行批开始即写、轮次行每轮完成
即写），体积不随轮次重复携带上下文膨胀。上一版「请求行流」（每请求一行、messages 增量、
output 原始投影）废弃：工具结果在请求行里要跨行拼接，本版用 turn_end 事件把工具调用与
结果同轮成对。

不选方案：单条大记录含 turns 数组（展示需解码、批结束前不可见）；每请求记录完整请求与
历史（体积随轮次增长）；生命周期只记任务级（丢失每批成败的实时可见性）。
