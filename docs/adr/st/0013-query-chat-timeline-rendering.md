# ADR 0013 — 问答面板：Agent 回复按片段时间线渲染

## Status

Accepted（spec：`.scratch/query-chat-timeline/spec.md`，tickets 01/02）

## Context

插件问答面板（ADR 0009）把一条 Agent 回复展示为「思考块（折叠）+ 工具调用卡（可展开）+ 回答文本」三段式结构。但 Agent 的真实工作流是「思考 → 输出 → 工具调用 → 拿结果 → 再思考 → 再输出…」的交错循环：一次回复里会多次调用工具、每次调用前都可能有一段独立思考。当前的扁平状态模型（thinking 单字符串累积 + text 单字符串累积 + toolCalls 数组）在事件应用时把顺序信息直接销毁，渲染时只能固定为「思考块 → 工具卡 → 文本」，用户看不出 Agent 在哪一步思考、哪一步调用。同时回答文本是纯文本渲染，无 Markdown 支持；折叠态 summary 行 44px 高，紧凑度差。

## Decision

1. **片段时间线数据模型**：assistant 消息的扁平字段替换为有序「片段序列」作为唯一事实来源。片段三种：思考片段（累积文本）、文本片段（累积文本）、工具调用卡（callId、名称、参数、结果/错误）。构建规则：`thinking_delta`/`message_delta` 追加进当前同类型片段，类型切换开新片段；`tool_start` 在时间线当前位置插入工具卡（不改变后续增量的归属）；`tool_result` 按 callId 回填卡片。聚合回答纯文本由文本片段推导（回传历史与复制按钮复用）。事件流无轮次边界（协议不变），分段完全由类型切换驱动。
2. **折叠语义**：流式中仅「当前进料片段」受控展开；已完成片段默认折叠、手动展开后不被自动收回（不受控 details）；工具卡执行中展开、出结果后折叠；进行中思考片段受控展开、流式中手动折叠不生效（与 ADR 0009 现状一致）。
3. **Markdown 选型：react-markdown + remark-gfm 打进 esbuild bundle**，只渲染文本片段。思考片段保持纯文本、工具参数/结果保持 `<pre>` JSON。样式用插件设计 token（--stm-*）新写容器样式。
4. **折叠态压缩**：思考块/工具卡 summary min-height 44px → 28px，卡片内距 6px 10px → 4px 8px，assistant 容器 gap 8px → 6px。
5. **本轮只改 st-extension，apps/web 不对齐**（web 存在同样问题，后置单独评估）。

## Rationale

### 为什么是片段时间线而不是「按轮次分组」

pi agent 会发 `turn_*` / `message_*` 事件，支持精确的轮次边界。但引入轮次边界需要改 SSE 协议 + 两个客户端，而「类型切换分段」已经能还原真实时序——思考块之间通常隔着文本或工具调用，双轮连续思考（无任何间隔）在实践中几乎不存在。纯客户端改动、协议不动、服务层与回传历史零变化，成本低一个量级。若未来需要轮次标签/按轮折叠，再补协议事件即可。

### 为什么不选 ST 全局 marked + DOMPurify

ST 运行时自带 marked 与 DOMPurify 全局，零新增依赖、观感与 ST 本体一致。但：逻辑耦合 ST 运行时（纯逻辑测试需注入桩）、XSS 防护要自己接 DOMPurify、且与 apps/web 已采用的 react-markdown 组件行为不一致。react-markdown 默认转义原始 HTML（自带防注入）、与 web 的 MarkdownContent 同语义（表格横向滚动包装、外链新标签）、组件可在两客户端间复用。代价是 bundle 增重几十 KB——对一个已经打进 React 全家桶的插件可接受。

### 问答 Tab 的面板渲染是会话数据不是记忆数据（继承 ADR 0009）

时间线只影响渲染层与页面内存状态，不落 Dexie、不进通用日志、不动云同步与备份——ADR 0009 的边界不变。

### web 暂不对齐的理由

两客户端本就刻意保持同语义（历史原因：web 先实现、插件后移植，注释互相引用）。但本轮插件是实际交付物，web 只是本地实验工具；同步意味着双倍修改 + 双倍测试面。先让插件落地验证时间线 UX，web 是否跟进、何时跟进单独评估，避免在实验工具上提前投资。

## Consequences

- 问答面板的事件应用函数语义改变：从「三字段累积」变为「片段构建」，所有消费该消息形状的代码随 ticket 01/02 迁移（范围已核实：仅问答面板自身，填表日志有独立渲染不受影响）。
- 多轮回传历史与「复制回答」的纯文本来源变为「文本片段拼接」，输出等价、行为不变。
- 折叠语义细化：完成片段手动展开后不被自动收回（现状是完成后必然折叠），需要用户手动展开的阅读模式成为可能。
- ST 全局 marked 未使用：若未来插件内其它区域需要 Markdown，可复用本特性打入的 react-markdown 依赖，不再评估 marked。
- web 端保持旧扁平模型，两客户端在该特性上暂时不同语义——后续跟进时以此 ADR 为基准对齐。
