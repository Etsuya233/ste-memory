# SQLite 内存运行数据库与指定聊天文件快照

日期：2026-10-24。状态：已实现核心路径；真实 ST/WebView 验收待完成。

## 决策

记忆在线读写迁入自有 Web Worker 中的 SQLite WASM 内存库，Worker 和 WASM 随插件发布，
不使用 OPFS、额外服务器或 CDN。按空间建立写连接和已提交读取连接；普通界面、宏、查询
Agent 与向量流程读取已提交版本，填表 Agent 通过任务连接查询自己的临时修改。

现有结构化查询契约编译为参数化 SQL，宏参数、配置和界面保持原样。Agent 增加只读
`query_sql`，支持 AND/OR、括号、JOIN、聚合与子查询，通过 SQLite authorizer、执行预算
与结果行数限制控制权限。运行时在执行 SQL 前按当前引用刷新 `$display_text` 派生列，
刷新不产生修订。记录修改通过实体业务端口执行领域校验、证据和修订流程，
未开放 Agent 原始 SQL 写入。

每个填表批次独立使用一个事务，手动、自动与初始化填表共用这一规则。变更工具即时执行，
每次调用有 SAVEPOINT，新建记录返回可直接引用的最终 ID。批次成功后立即提交并保存，
同条记录在本批内的多次修改归并为一个修订，只归档本批开始前的正式旧状态；本批内新建
后删除的记录不留下正式历史。失败、取消或运行阶段切换对话只回滚当前批次，已成功批次
保持已提交。任务输入与清洗配置在启动时冻结，每批提交前核对本批原消息范围。

2026-10-25 修订：事务边界由整项任务调整为单批次；后续批次可读取之前批次已提交的结果。

IndexedDB 继续保存任务、楼层进度、向量和日志。现有六类记忆表保留为本地快照缓存，
缓存采用差量保存，不在每次提交时清除向量；SQLite 承担在线查询和事务。

同步默认开启，初始化始终采用所选聊天文件的合法快照，即使本地缓存更新时间较新。
无镜像的旧对话可从本地迁移；损坏或未知文件拒绝导入和覆盖。关闭同步则使用本地快照。
分支文件在用户确认前只作预览和克隆输入，不覆盖原空间的 SQLite 或本地缓存。

每次 SQLite 提交后立即调用完整快照保存，包含历史。通过 ST 指定单聊/群聊文件接口
读最新文件，再只替换插件快照，必要时同次写绑定，保留正文及其他 metadata。
切换时导出旧空间已提交快照并发起原文件保存，再释放旧数据库和加载新对话。
重新加载文件会等待本实例已经排队的保存，避免快速返回对话时重新导入旧文件。

## 保证与限制

保证 SQLite 事务内修改一起成功或回滚，以及有效完整快照、明确目标身份和保存错误
展示。文件保存、缓存和任务进度按序调用，不构成共同事务；不建立提交日志、回执、
跨引擎对账、跨标签页锁或崩溃恢复，接受最近修改丢失、进度不同步及并发保存覆盖。

当前实现尚未完成 snapshotId 与楼层台账集合的归属检查、所有计划中的会话代次协议、
迁移前性能对照与峰值内存测量。真实 ST/Edge 已通过初始化、事务、保存、群聊和备份导入
验收，其他 WebView 仍待验证。结果见 [浏览器验收记录](../../sqlite-browser-e2e.md)。
详细完成/待完成范围记录在 [迁移方案](../../sqlite-migration-plan.md)。
