# 统一记忆空间快照迁移

> 2026-11-01：本地快照缓存及旧空间迁移条款由 [ADR 0033](./0033-chat-file-only-memory.md) 取代，文件与 SQLite 事务边界按新决策执行。
> 后续必要楼层进度进入领域快照，保存与核验按 [ADR 0034](./0034-host-managed-memory-save.md)
> 执行；下文 schemaVersion 1 描述该决策最初落地的版本。

日期：2026-11-01。状态：已实现。

备份文件、对话文件镜像和 IndexedDB 本地缓存共用一个完整空间快照契约。
`features/memory-snapshot` 负责旧结构校验、纯数据迁移及当前结构/完整性校验；
它聚合 Memory 的公开领域类型和可选任务集合，Memory 内部保持对其他功能的单向依赖边界。

文件外壳版本升级为 v3，空间快照独立携带 `schemaVersion: 1`。
旧外壳 v1 映射含旧视图的历史形状，v2 映射表达式宏形状；旧文件不得已有领域版本标记。
外壳解码后统一迁移初始化来源、宏、表格位置、废弃 kind 和向量分组 Key，
仅清除当前记录中指向不存在字段且值为空数组的证据键。非空引用仍拒绝，历史字段状态原样保留。
当前版本只校验，不根据缺字段猜测旧版本，也不在保存时补字段。

Dexie v11 的升级事务将旧领域行组合为快照并调用相同入口，取代 v5/v7/v8 的分散领域升级。
旧版本建表、索引及助手会话等独立数据升级保留。表格旧本地顺序按创建时间与 ID，
旧文件顺序按数组；两种适配只确定输入顺序，赋位置规则仍只有一份。
本地空间行的 `snapshotSchemaVersion` 保存领域快照版本，读取时移除存储元数据。
后续读取必须携带明确版本，新数据缺字段会暴露错误，不会再次被当旧数据修补。

迁移保留身份并早于克隆和 SQLite 导入；SQLite 继续保存完整实体 JSON。
保存导出当前快照并校验，经既有差量缓存和指定聊天文件保存链路写回。
新建空间在领域创建入口明确初始化宏集合。当前备份/镜像创建同时校验结构和完整性，
不生成无法重新加载的文件。

本决策细化 [备份格式 ADR 0021](../0021-backup-file-format.md) 与
[对话镜像 ADR 0023](../0023-chat-metadata-mirror.md) 的数据版本边界，保持
[SQLite 运行 ADR 0019](./0019-sqlite-runtime.md) 的加载、提交及保存顺序。
绑定冲突、绑定原子保存和字段删除业务不属于本次变更范围。
