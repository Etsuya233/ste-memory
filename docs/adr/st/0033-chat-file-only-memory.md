# 聊天文件作为空间内容唯一持久化来源

> 宿主保存、必要楼层进度及关键操作核验现按 [ADR 0034](./0034-host-managed-memory-save.md)
> 执行；[ADR 0037](./0037-compressed-memory-history.md) 增加本机历史集合。本文保留此前重构的决策记录。

日期：2026-11-01。状态：已实现。

## 决策

空间、表、字段、记录、历史与证据统一由 SQLite 在线管理，对话文件保存完整快照。
IndexedDB 只管理独立的任务、楼层台账、向量、助手会话和日志；v12 直接废弃六类旧空间表。
旧本地空间不扫描、不校验、不迁移、不导出、不用于存在检测。旧文件 v1/v2 仍走统一快照迁移。

`SqliteMemoryStore` 管 SQL 事务归属与已提交事件；保存与编辑门控为必需构造端口。
提交并导出后，同步把独立快照交给 `ChatSnapshotPersistence`，SQL writer 随即释放。
宏、向量和公共只读接口通过已提交事件失效，异步刷新失败不能改变提交结果或阻断文件保存。

`ChatSnapshotPersistence` 按文件目标持有最新有效快照、绑定及任务阶段。
普通更新是 write → complete，complete 确认已保存填表批次；候选替换是 write → activate。
文件已成功时，重试只继续确认或激活；同目标旧结果不发布到新 metadata。
离开已保存聊天释放完整内存快照，未完成任务保留；返回未保存聊天优先恢复待保存输入。

每个聊天只激活当前空间。导入或分支副本在纯快照函数中重映射 ID，经 SQLite 独立验证，
再同次保存 binding 与 snapshot；成功前不发布新绑定、不清原辅助数据。候选保存期间停止旧写入，
异步校验归属在排队前集中核对。保存成功后才清旧辅助并激活，分支副本不删除源聊天数据。
退休/卸载持有原文件目标，防止迟到保存误清相同空间 ID 的其他活动文件。

卸载仅释放 SQLite。向量只执行当前空间队列，离开只中断 running 并保留 queued。
真正的替换、清除和预设重建由对应业务顺序调用辅助模块清理，不用空间删除钩子模拟生命周期。
本地空间目录、全库备份/恢复、同步开关、Dexie 空间仓库及轮询式镜像架构全部移除。

## 版本与边界

保留 [ADR 0032](./0032-unified-memory-snapshot-migration.md) 的文件领域迁移、当前校验及版本边界，
取代其本地缓存迁移条款；取代 [ADR 0019](./0019-sqlite-runtime.md) 的 IndexedDB 双写缓存。
备份文件外壳读取兼容历史集合，但当前聊天导入只接受一个空间，当前导出不携辅助数据。

不引入 identityKey、跨聊天空间目录、多存储后端或服务端协议变更。
正常字段删除的孤立证据业务不在本次范围。SQLite 提交、文件写入与辅助台账没有共同事务，
保存失败由明确内存待办表示；关闭页面仍可能失去未完成内容，不建立跨刷新确认协议。

## 实现维护入口

`ChatSpaceManager` 按待保存恢复、首次初始化、已绑定加载和候选替换组织聊天入口；
选择对象与候选请求对象共同拒绝迟到结果。候选来源使用具名 origin，发布空间状态由激活方法返回。
绑定契约及文件身份规则位于 `chat-space-context.ts`，角色索引变化但同文件名的移植兼容约定保留；
同 ID 的跨文件退休安全由 `MemorySpaceLifecycle` 的 owner 检查保证。

`ChatSnapshotPersistence` 管每文件队列、当前已提交快照及保留策略；
`ChatSnapshotSaveTask` 管固定输入、write/complete/activate 阶段、批次回调与调用者结算。
write 阶段被新提交覆盖时，旧调用者与批次回调迁入最新任务；已经开始 complete 的调用独立结算。
文件成功后先发布活动 metadata，再确认业务；确认失败重试保留落盘阶段。

`SqliteMemoryStore.commitTask` / `rollbackTask` 明确任务事务的结束语义；
独立写入和任务提交共用 commit/export/同步交接规则，工具调用只创建保存点。
仓库按空间级操作、表字段结构和记录修订提交组织，共享 `SqliteRepositoryView` 的读视图与 writer 身份。
`MemorySpaceLifecycle` 统一文件归属、停止写入、卸载、退休及切聊队列；
`PresetSpaceUpdater` 集中预设比较、替换、锁外保存及带聊天代次校验的派生数据刷新。

全量预设重建由 `MemorySpaceLifecycle.rebuildStructure` 捕获文件 owner 并持有待确认请求。
重建未保存或辅助清理失败期间，同文件的新编辑、填表提交、业务重试与手动台账修改被明确拒绝；
旧填表批次的文件确认仍按 runId/batch 独立完成，不套用这项门控。
SQLite 替换失败撤销请求，文件保存失败保留请求供重试，成功清理或失去归属而跳过清理都会解除门控。
确认只处理仍为当前的重建请求；重复或过期回调不会清理资源，也不会解除较新请求的门控。
owner 表示运行期最后文件归属，卸载时保留，同文件重激活复用凭据，另一文件接管会使旧请求永久失效；
它不证明 SQLite 已加载，也不参与空间枚举和加载判断。
