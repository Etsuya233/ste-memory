# 记忆宏注入：用户手动放置，而非 setExtensionPrompt 自动注入

记忆上下文通过**记忆宏**注入：插件注册宏（新宏引擎 `context.macros.register`），**用户自行把宏放进提示词预设**（角色卡、系统提示、作者注释等）；宏名由用户配置，不写死（后续可能多个宏）。ST 宏引擎要求 handler 同步，故宏返回**预计算快照**——每次数据变更（同步、填表、手动编辑）后重建「组装好的记忆上下文文本」，宏展开时同步返回。

选择宏而非自动注入的原因：用户完全控制注入位置与频率（与预设绑定、可移植、可关停）；宏在每次生成时展开，天然拿到最新快照；ST 的 `setExtensionPrompt` 是自动注入机制，需要插件自行决定位置/深度/刷新时机，与「用户手动放置」的心智不符，也让预设失去可移植性。

组装规则（Phase 4 细化）：按启用表分组（表名 + 记录显示文本，复用显示策略），上限可配置；宏名约束遵循 ST 标识符规则（字母开头、字母数字连字符、大小写不敏感）。

不选方案：`setExtensionPrompt` 自动注入（用户失去控制、事件驱动刷新、预设不可移植）；异步宏展开（ST 宏引擎不支持 Promise）；每次展开现算（组装开销 + 同步约束，快照更稳）。
