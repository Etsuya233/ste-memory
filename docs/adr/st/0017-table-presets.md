# ADR 0017 — 表格预设：统一表格规则与预设驱动的空间初始化

## Status

Accepted（spec `.scratch/table-presets/spec.md` 已实现：预设模型与库操作、预设实例化、原子重建、设置分组、系统表身份废弃）

## Context

在此之前，记忆空间首次创建时由 `SystemMemoryTableInstaller` 安装固定的 8 张「系统表」，设置里的「重置空间」也恢复这套结构；表格带 `kind: system | custom` 身份，界面据此限制系统表的编辑。由此产生三个问题：

1. 用户无法保存与复用自己调整过的表结构（首建与重置都回到出厂定义）；
2. 系统表身份带来一套「只读/专用」的行为分支，与「所有表格遵循同一领域规则」矛盾；
3. 重置入口与「清除记录」共用危险操作区，语义与文案含糊。

## Decision

1. **引入表格预设**：一整套可复用的表结构（表、字段、填写规则、引用关系、显示策略），不含记录。系统自带预设（系统默认）由插件模板在运行时计算、不落库；用户预设存全局插件设置（`PluginSettings.tablePresets`），默认选择一并存全局设置。
2. **引用按 Key 表达**：预设内引用目标写表 Key、显示策略占位符写字段 Key；实例化时生成全新实体 ID 并转换引用，预设不保存来源空间的身份。
3. **首建与应用预设共用一条实例化 + 原子重建路径**：`TablePresetApplyService.installDefaultStructure` / `applyPreset` → `SpaceStructureRebuild.rebuild`（单事务清空结构/数据/任务/进度并写入新结构与初始化来源）。
4. **初始化来源存空间行**（`MemorySpace.initializationSource`）：随空间单元序列化，天然随备份、克隆、对话文件镜像保留；旧库用 Dexie v5 迁移补 `null`，旧备份文件解码时归一化。
5. **废弃系统表身份**：移除 `MemoryTable.kind`，表格顺序改为显式 `position`；所有表格统一支持编辑、删除、增删字段、启停与显示策略修改；「重置空间」入口移除，统一为「应用预设」（危险操作区只保留「清除空间记录」）。
6. **一次确认流程**：点击应用后先停止目标空间的进行中填表写入，再弹出确认框（取消 / 备份并应用 / 直接清空并应用）；备份未完成不清空，重建失败保留原持久化内容，重建成功后的宏或镜像同步失败单独回报。
7. **备份覆盖删除范围**：空间备份单元在结构/记录/修订历史/证据之外补齐填表任务、楼层进度与对话级宏快照（spec 6.3），使「备份并应用」能恢复本次将被删除的持久化内容；三项为可选集合，缺省表示不涉及（对话文件镜像不带，恢复不触碰本地任务/进度/宏）。

## Rationale

- **内容随版本走**：系统预设计算而非落库，插件升级改模板只影响之后初始化的空间（spec 4.1）。
- **无迁移负担**：预设不含记录，应用预设是「清空 + 重建」，不做字段映射与数据迁移；引用与显示策略在实例化时按 Key 重映射，避免跨空间身份泄漏。
- **原子性**：结构、记录、任务与进度在同一 Dexie 事务内替换，失败整体回滚，绝不产生半初始化空间。
- **旧任务隔离**：填表任务的批次提交在**同一事务内复检任务行**（`running` 才写入），重建事务删除任务行且替换表/字段身份——两份写入在任务表上互斥，重建后旧任务不可能再写入（AC-12）；取消（`stopSpaceWrites`）先于备份，保证备份之后不会再有旧写入。
- **统一规则**：删除 `kind` 后，界面与领域层不再有系统表/自定义表分支，表格顺序由 `position` 表达（取消身份排序）。

## Consequences

- 备份文件与对话文件镜像的行形状变化（表格去 `kind`、加 `position`；空间加 `initializationSource`；备份单元新增可选的任务/进度/宏集合）：解码侧对旧文件归一化，新导出总是写全；不迁移历史空间记录（不做数据迁移，符合 spec 3.2）。
- 单空间导出因此变大（含任务、进度与该对话的宏快照）；全库导出同样携带任务与进度，全库导入会一并恢复。
- IndexedDB 需要一次 Dexie v5 升级（同一事务内补字段与顺序），对用户表现为一次性迁移。
- 「重置空间」不再是独立入口；用户从「表格预设」分组选择目标预设（含系统默认）后应用，确认流程与备份提醒统一在该入口。
- 应用预设会清除当前对话的对话级宏并覆盖对话文件镜像；全局记忆视图、Agent 配置、预设库与其他对话不受影响（全局视图对新结构不满足时沿用既有配置错误展示语义）。
