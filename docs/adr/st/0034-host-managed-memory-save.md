# 宿主统一保存记忆快照与关键操作核验

日期：2026-11-01。状态：已实现。

## 决策

SQLite 继续承担记忆空间在线查询与事务，对话文件继续承担空间内容持久化。
插件停止独立执行聊天文件的读取、修改、整文件上传，统一更新活动聊天的宿主内存
metadata，再请求 ST 原生保存。保存入口同时发布 `steMemory` 与 `steMemoryMirror`，
不修改其他 metadata 或聊天正文，不传递绕过 ST 完整性检查的 `force` 参数。

普通业务提交按以下顺序执行：

```text
SQLite 同事务更新记忆及必要楼层进度
  → 导出完整快照
  → 同步发布活动聊天的绑定与快照
  → 释放 SQL writer
  → 请求 ST 原生即时保存
```

字符输入属于表单草稿。点击保存、结构修改、每个填表批次提交才请求一次宿主保存，
插件不再增加时间防抖。普通提交不回读服务器，不保留全部聊天的待保存完整快照。
ST 原生保存可能内部捕获错误，因此返回只表示宿主调用结束，界面不能据此声称
服务器已保存。必要楼层进度随同记录一起恢复，不以 IndexedDB 任务历史推断已处理范围。

## 关键操作与强制同步

导入、空间替换和预设重建涉及旧辅助数据删除时，先在内存中激活候选并发布 metadata，
同时暂停该空间后续编辑、填表和再次替换。保存后对捕获的原聊天文件做只读回读，
按结构比较完整的绑定与 Memory 快照；核验一致且原操作仍有清理权限时才清旧辅助数据。
核验失败保留候选和旧辅助，重试只执行保存及核验，不重复导入、模型请求或结构重建，
不根据超时、网络失败自动回滚 metadata。失败可能发生在服务器已经写入之后。

“强制同步”共用同一保存入口，以当前 SQLite 已提交内容立即请求宿主保存并回读核验。
未提交的表单草稿不进入快照；核验通过才显示远端已核验。重复点击与并发 Memory 写入
由明确的操作归属和写入门控协调，不能让较旧内容的回读结果替较新提交报告成功。
当前有关键操作待确认时，强制同步继续同一任务，包括尚未完成的辅助清理。
临时同步门控在第一个异步等待前按文件归属建立，已持有 writer 的批次可以收口；
运行中的填表任务在下一批开始前等待同步结束，不能把临时门控当成填表业务失败。

## 聊天切换与生命周期

写入只针对活动聊天。插件不向非活动聊天后台补写；已进入宿主的请求由宿主完成。
切换后的迟到结果不能发布旧 metadata、操作新聊天状态或清除另一聊天同空间 ID 的数据。
关键操作可以继续只读核验原文件，写入重试必须等原聊天重新活动。

普通聊天返回时从宿主已加载 metadata 恢复 SQLite。当前页面仍持有某聊天关键候选时，
返回该聊天先恢复这一候选及待确认门控，不能用旧文件悄悄替换候选后放开编辑。
此例外只保留未完成关键操作所需的内存状态，不恢复空间缓存或本地空间目录。
刷新后内存候选消失，按聊天文件恢复；未经确认的旧辅助数据保留。

## 版本与边界

必要楼层进度进入领域快照，沿用统一快照版本迁移入口。旧文件没有提供的进度视为未知，
不从旧 Dexie 空间内容或本机独立台账补齐。文件外壳与领域 schema 的职责继续分离，
加载、备份、导入与克隆共用迁移和当前结构校验。

核验只证明回读时两个 metadata 键与本次提交一致，不提供之后的覆盖保护。
ST 仍可能上传整份聊天；该方案减少插件的额外下载和独立写入者，不构成局部上传协议。
不提供跨设备并发编辑协调、宿主服务端扩展、跨存储事务或关闭页面后的崩溃恢复。
切聊或关闭页面前尚未落盘的普通修改可能丢失。

本决策取代 [ADR 0033](./0033-chat-file-only-memory.md) 中固定目标后台写入、普通批次
保存后确认及候选文件成功后激活的条款；保留其 SQLite 在线运行、废弃 Dexie 空间内容、
每聊天一个当前空间及同空间 ID 的跨文件清理归属规则。

## 维护入口

- `infrastructure/sillytavern/chat-snapshot-file-store.ts` 原子发布宿主 metadata 与请求保存，
  只有核验方法读取固定文件；正文、完整性检查和上传协议仍由 ST 管理。
- `features/chat-mirror/chat-snapshot-persistence.ts` 统一普通提交、关键候选与强制同步；
  `memory-runtime/memory-space-lifecycle.ts` 管写入门控、批次等待和清理归属。
- `features/memory-snapshot/snapshot-migration.ts` 集中领域快照升级；
  `memory-runtime/sqlite-floor-ledger.ts` 管 SQLite 权威进度。
- `frontend/pages/settings/snapshot-sync-control.tsx` 提供设置页单按钮和简短结果，
  不持有独立保存队列，也不提交其他页面草稿。
