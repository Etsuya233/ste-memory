# 填表任务共用持久化队列

自动填表原先在聊天元数据中管理暂存列表与运行快照，手动填表和初始化填表直接提交运行。两条路径共用执行名额，手动提交遇到运行任务会报冲突，等待顺序与恢复行为分散在两个模块中。

## 决策

所有填表任务经 `FillTaskService` 入队，任务表保存 `queued` 状态、空间内递增的 `queuePosition` 与自动重试参数。仓库在事务中分配序号、检查队首并启动任务；执行器等待当前循环退出后再处理下一项。当前对话的任务串行执行，其他空间保留自己的队列。关闭自动填表或切为仅提醒时，取消队列中的自动任务，手动任务继续保留。

最终失败的任务保持 `failed`，并以 `blocksQueue` 保留在原位置阻塞后续执行。用户重试会生成新任务、原子替换阻塞项的位置；取消失败项只释放阻塞，保留失败历史。取消等待项只移除该项。自动任务恢复时跳过已完成的楼层。

页面重开后，运行项转为 `interrupted` 并阻塞队列，等待项保留；切换对话时暂停调度并中断运行项，返回后可继续或取消。宿主生成期间暂停启动后续任务。空间清理与应用预设前原子取消全部待处理项，避免取消运行项后启动等待项。备份导入中的未结束任务转为阻塞的中断项，需用户显式继续。

`AutoFillService` 负责计算触发范围、避免重复入队、提醒与通知。旧聊天元数据中的暂存项首次检查时转入任务表，随后删除旧运行快照与暂存状态。任务面板统一展示运行、等待和阻塞项，运行期间仍可提交手动或初始化任务。

## 快照时机

本决策修订 ADR 0006、0007 中的提交时快照规则：LLM 配置、活动预设及世界书扫描在任务实际开始时读取一次，分批执行沿用该次快照。楼层范围、每批楼层数和自动重试参数在入队时确定。连接或提示词构建失败也会成为可见的失败任务并暂停队列。

## API 请求重试（2026-10-27）

重试粒度从自动任务的整批重跑调整为每轮模型请求。手动和初始化任务默认额外重试两次，首次等待十秒；自动任务沿用持久化的次数和首次等待参数。复用 Pi 的 `retryAssistantCall` 分类、指数退避及重试回调，每轮独立预算，等待可取消且计入批次总超时。

执行器通过 Pi 底层循环的 `shouldStopAfterTurn` 完成一轮和工具执行后暂停，再处理下一轮。成功轮次及其工具结果进入有效上下文，失败尝试保留原生流式和轮次事件供日志查看，不进入重试上下文。各次尝试共用当前批事务，保留已经成功执行的工具；最终失败或取消才回滚当前批，成功批次保持提交状态。配置、提示词、工具和保存错误不进行整批自动重试。

所有填表类型在统一活动任务区显示重试原因、次数和倒计时。问答 Agent 不启用此策略。
