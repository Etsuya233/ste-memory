# 统一记忆助手与持久化会话

将原查询与交互填写入口合并为记忆助手，复用提案工具及普通、语义 SQL 查询能力。后台填表保持独立的事务模式。助手会话归属真实 ST 对话身份与记忆空间，同一归属可创建多个会话，共享已提交记忆，独立保留消息、输入、工具上下文和提案。

旧实现每轮新建 ProposalState，并只回传文本历史，与跨轮等待用户确认的流程冲突。会话现在保存提案操作、计数器及完整工具消息；每次运行重建短期 Agent，通过外部 State 接续草稿。会话由运行时唯一 store 管理，在 IndexedDB 持久保存，不随聊天文件或备份同步，避免把交互日志扩大为记忆领域数据。此决策取代旧问答的双模式及页面内无状态历史约定，并调整 ADR 0024 中交互用途的每 run 新建 State 约束；后台填表仍保持该约束。

提交确认由界面发起，绑定当前预览身份；模型的 submit_proposal 只准备确认。新一轮交互使旧确认失效，实际提交继续执行领域校验和修订检查。提交失败保留草稿，成功后清空提案；提交已完成但快照保存失败按已提交展示。刷新中断普通请求时保留草稿、补齐未完成工具结果且不重放工具；提交过程中刷新则阻止直接重提，先核对结果并放弃旧提案，避免重复写入。

同一会话的运行、确认和放弃操作使用浏览器 Web Locks 串行执行，并在获得锁后读取持久化的最新提案。持有锁的页面完成最终检查点保存后才释放；其他页面订阅 IndexedDB 变化，等待锁释放后判断是否需要恢复遗留请求。会话快照另以 storageRevision 在 IndexedDB 事务内执行版本校验，拒绝旧快照覆盖或复活已删除会话。数据库 v10 为旧会话补齐版本。会话未保存及保存失败的刷新保护归工作台宿主，切页或收起面板后继续生效。单条修改的 MemoryRecordSaveError 与批量修改的 MemoryCommitPersistenceError 都按已提交处理。
