# 记忆视图：记忆宏表达式化（筛选/条数/投影）+ core 记忆查询

记忆宏（ticket 15 / ADR 0004）把「全部启用表」的预计算快照注入提示词文本，但无法按需选取——用户要「只展示未完成的伏笔」「最后几条剧情条目」这种带表达式的注入。ST 1.18.0 宏引擎已支持位置参数（`{{name::arg}}`，参数内任意字符、handler 同步），且 WI 条目内容在激活时无条件展开自定义宏（事实调研见 `docs/research/st-macros-args-and-worldinfo.md`）。设计过程中发现：视图需要的选取能力（投影/筛选/排序/条数）与 core 既有的**查询契约**（`memory-record-query-contract`，查询 Agent 工具与 apps HTTP 查询共用）高度重叠，因此**不新建第二套读侧语言**——视图的选取翻译成记忆查询（既有契约，补 in/not_in 算子）执行。决策：**单宏 + 视图名参数**（宏名沿用用户配置，无参 = 现有默认行为），视图为**插件级命名配置**；语法与配置在 st-extension，求值经 core 记忆查询。

## 决策

1. **单宏 + 视图名参数**：沿用用户可配置宏名（默认 `{{memoryContext}}`），注册为带一个可选位置参数（`unnamedArgs`）的宏。无参 → 现有默认快照（全部启用表分组、updatedAt 倒序、字符上限截断，行为不变）；带参 → 该命名视图的快照；未知视图名/空参数 → 空串 + 日志，不阻断生成。两个以上参数 → ST 参数校验失败（文档说明）。视图名受 ST 宏参数语法约束：不含空白、`::`、`|`、`}}`（中文可用）。
2. **记忆视图 = 插件级命名配置**：存插件设置（与清洗规则列表同层），全局生效。字段：名称、表 Key、筛选条件（v1 单条件：字段 Key + 值集合，single_select/short_text 字段）、条数上限（可选）、显示字段投影（可选）。视图缺失、表/字段缺失（含字段 Key 被改名）→ 展开空串 + 日志（翻译层错误可在面板显示）。
3. **求值 = 记忆查询（既有查询契约）**：视图的选取翻译成 `QueryRecordsInput`（`fieldIds` = 投影、`conditions` = 筛选（多值 = `in` 算子）、`order` = `$updated_at` desc、`paging.pageSize` = 条数上限），经 `MemorySpaceReader` 端口执行——查询 Agent 工具、apps HTTP 查询与记忆视图共享同一契约与实现（api SQLite / st-extension Dexie 双实现），**不新建独立求值器**。契约补 `in`/`not_in` 算子（`value` 为数组，`MemoryFieldValue` 已支持），`query_records` 工具参数 schema 与描述同步更新（LLM 面受益：多值查询无需拆多次 equals）。视图无条数上限时用 pageSize 100（契约上限；全局字符上限兜底截断使其实际影响不可见，文档说明）。
4. **投影**：视图可选显示字段；渲染 = 「字段名：值」按视图字段顺序拼接（空值省略，引用字段显示为目标记录显示文本，需渲染层解析引用）；无投影 → 沿用查询结果的显示文本（displayText）。输出不含分组标题（视图是单表语义）。**输出文本不含 `{{...}}`**（整条 prompt 还会过一次 substituteParams，避免二次展开）。
5. **世界书零插件改动**：用户把宏放进 WI 条目内容即可（ST 激活时展开，含自定义宏；预算按展开后内容计 token）；插件不自动维护 WI 条目（`loadWorldInfo/createWorldInfoEntry/saveWorldInfo` 能力存在但不采用）、不改写 ST 预设文件（`getPresetManager` 能力存在但不采用）。交付物 = 文档 + 视图能力。
6. **快照架构不变**：每视图一个预计算快照 + 默认快照；重建 = 视图翻译成记忆查询**异步**执行（`MemorySpaceReader.queryRecords`）→ 渲染 → 缓存文本，宏 handler 仍同步返回（无冲突）；指纹轮询重建；视图 CRUD（设置变化）kick 立即评估。**默认快照维持 ticket 15 现状**（`listTables` + `listRecords` + `assembleMemoryContextSnapshot`），不迁移到记忆查询（已验收行为不动）。

## 边界

- ST 宏参数是**位置参数**（`namedArgs` 预留未实现）；「key=value」需插件自解析——本设计不采用内联语法，视图名是唯一参数。
- 管道过滤器（`{{x|filter}}`）在 1.18.0 未实现——表达式能力全走宏参数。
- 新宏引擎默认开启（`experimental_macro_engine`）；用户关闭后自定义宏不展开（既有风险，文档提示，本决策不处理）。
- v1 视图面板 = 单条件行；**契约本身已支持多条件 AND 与 10 个算子**（相等/包含/有序比较/in/not_in）——多条件与字段运算（contains/gt/lt）后续只需放开视图 UI，无需 core 改动。
- v1 视图不含：OR/嵌套条件、行模板、每空间视图、投影字段运算。

## 不选方案

- **独立统一表达式求值器**：与既有查询契约重叠，core 出现两套读侧语言，算子演进两边都要长；视图翻译进查询契约后免费获得类型校验、系统字段、多条件 AND。
- **内联表达式参数**（`{{memoryContext::plots::status=埋设中,已触发::5}}`）：位置参数难记、同筛选多处复制、语法错误到生成时才暴露。
- **每视图注册一个宏**：宏名受 ST 标识符规则（`[a-zA-Z][\w-_]*$`）限制，中文名不可用；视图数膨胀注册。
- **插件自动写入 ST 预设 / 自动维护 WI 条目**：写服务器文件、侵入用户配置、与用户手动编辑冲突；`setExtensionPrompt` 运行时注入留作自动注入方案的备选。
- **筛选求值全部放 st-extension**：选取语义在 core，查询契约让 api/web 与查询 Agent 共享同一实现。
- **默认快照迁移到记忆查询**：动 ticket 15 已验收行为，无收益。
- **管道过滤器路线**：ST 1.18.0 未实现。

## 现状与后续

初版按本决策落地；后续演进：OR/嵌套条件、行模板、每空间视图、投影字段运算；多条件与字段运算仅差视图 UI 暴露。事实调研：`docs/research/st-macros-args-and-worldinfo.md`。
