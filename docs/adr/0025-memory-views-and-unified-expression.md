# 记忆视图：记忆宏表达式化（筛选/条数/投影）+ core 统一表达式

记忆宏（ticket 15 / ADR 0004）把「全部启用表」的预计算快照注入提示词文本，但无法按需选取——用户要「只展示未完成的伏笔」「最后几条剧情条目」这种带表达式的注入。ST 1.18.0 宏引擎已支持位置参数（`{{name::arg}}`，参数内任意字符、handler 同步），且 WI 条目内容在激活时无条件展开自定义宏（事实调研见 `docs/research/st-macros-args-and-worldinfo.md`）。决策：**单宏 + 视图名参数**（宏名沿用用户配置，无参 = 现有默认行为），视图为**插件级命名配置**；视图语法与配置在 st-extension，翻译成 **core 统一表达式**求值。

## 决策

1. **单宏 + 视图名参数**：沿用用户可配置宏名（默认 `{{memoryContext}}`），注册为带一个可选位置参数（`unnamedArgs`）的宏。无参 → 现有默认快照（全部启用表分组、updatedAt 倒序、字符上限截断，行为不变）；带参 → 该命名视图的快照；未知视图名/空参数 → 空串 + 日志，不阻断生成。两个以上参数 → ST 参数校验失败（文档说明）。视图名受 ST 宏参数语法约束：不含空白、`::`、`|`、`}}`（中文可用）。
2. **记忆视图 = 插件级命名配置**：存插件设置（与清洗规则列表同层），全局生效。字段：名称、表 Key、筛选条件（v1 单条件：字段 Key + 值集合，single_select 多值 + short_text 精确）、条数上限（可选）、显示字段投影（可选）。视图缺失、表/字段缺失（含字段 Key 被改名）→ 展开空串 + 日志。
3. **统一表达式在 core**：结构化 JSON 描述 `{ conditions: [{ fieldKey, operator: 'in'|'eq', values: string[] }], sort: { by: 'updatedAt', direction: 'desc' }（v1 固定）, limit? }`，多条件 AND 语义；core 纯函数求值（筛选 → 排序 → 取条数，返回记录子集），apps（api/web）可复用。语法层（视图配置、宏参数）留在 st-extension，翻译成统一表达式后交 core 求值。
4. **投影**：视图可选显示字段；渲染 = 「字段名：值」按视图字段顺序拼接（空值省略，引用字段显示为目标记录显示文本）；无投影 → 沿用显示策略的显示文本（displayText）。输出不含分组标题（视图是单表语义）。**输出文本不含 `{{...}}`**（整条 prompt 还会过一次 substituteParams，避免二次展开）。
5. **世界书零插件改动**：用户把宏放进 WI 条目内容即可（ST 激活时展开，含自定义宏；预算按展开后内容计 token）；插件不自动维护 WI 条目（`loadWorldInfo/createWorldInfoEntry/saveWorldInfo` 能力存在但不采用）、不改写 ST 预设文件（`getPresetManager` 能力存在但不采用）。交付物 = 文档 + 视图能力。
6. **快照架构不变**：每视图一个预计算快照 + 默认快照；指纹轮询重建；视图 CRUD（设置变化）kick 立即评估。视图名/表/筛选/条数/投影都参与重建判定（设置变化不反映在指纹上）。

## 边界

- ST 宏参数是**位置参数**（`namedArgs` 预留未实现）；「key=value」需插件自解析——本设计不采用内联语法，视图名是唯一参数。
- 管道过滤器（`{{x|filter}}`）在 1.18.0 未实现——表达式能力全走宏参数。
- 新宏引擎默认开启（`experimental_macro_engine`）；用户关闭后自定义宏不展开（既有风险，文档提示，本决策不处理）。
- v1 表达式不含：嵌套条件、排序自由度（如剧情时间排序）、字段运算、long_text 包含、引用字段筛选、行模板、每空间视图、投影运算——均为后续演进。

## 不选方案

- **内联表达式参数**（`{{memoryContext::plots::status=埋设中,已触发::5}}`）：位置参数难记、同筛选多处复制、语法错误到生成时才暴露、handler 需从「预计算文本」改为「缓存记录集 + 同步求值」的架构改动。
- **每视图注册一个宏**：宏名受 ST 标识符规则（`[a-zA-Z][\w-_]*$`）限制，中文名不可用；视图数膨胀注册。
- **插件自动写入 ST 预设 / 自动维护 WI 条目**：写服务器文件、侵入用户配置、与用户手动编辑冲突；`setExtensionPrompt` 运行时注入留作自动注入方案的备选。
- **筛选求值全部放 st-extension**：筛选是对记忆记录的领域选择语义，core 统一表达式让 api/web 可复用同一求值。
- **管道过滤器路线**：ST 1.18.0 未实现。

## 现状与后续

初版按本决策落地；后续演进：嵌套条件、排序（剧情时间等）、字段运算、long_text 包含、引用筛选、行模板、每空间视图。事实调研：`docs/research/st-macros-args-and-worldinfo.md`。
