# 系统表提供完整的实验模板

人物、人际关系、地点、物品、剧情、伏笔和待办系统表在首个实验阶段提供内容完整的默认字段与填写意图。模板由 API 持有，创建记忆空间时通过 Core 的通用表格与字段用例安装；Core 不包含具体系统表清单或系统 Key 类型。伏笔与待办虽然都涉及未闭环事项，但因叙事暗线和行动事项的状态语义不同而分表；它们仍使用统一表格模型，并在创建记忆空间后可局部修改。

## 2026-08-06 修订（v4 世界状态表）

新增第 8 张系统表 `story_state`（世界状态）：承载剧情时钟的当前值，全表单条覆盖式记录。

- 动机：时间/地点/天气/着装是随剧情推进的瞬态状态，原模板无处归位，导致时间坐标各表自行推导、不一致（v2/v3 实验实证：time_hint 填「当天午后」等相对词、地点被塞进时间字段）；
- 形态：`name`（固定「世界状态」，正则校验）+ `current_time` / `current_location` / `weather` / `clothing`，单条记录、更新时覆盖旧值；
- 时间坐标双轨（2026-08-07）：有明确具体日期（如场记头「2025年5月14日 17:35」）填绝对年月日时分，否则用「第 N 天·时段」稳定相对坐标兜底；两类格式由字段 value_pattern 硬校验；
- 字段级格式校验（value_pattern + 回喂消息）：非空值必须匹配正则，空值跳过，校验失败经提交拒绝链路回喂 Agent 自愈（见 ADR-0009 的单一管线）；
- 其余模板要点：plots.details 为追加式摘要（保留旧事实+追加新进展，maxChars 800，是未来 RAG/搜索语料）；items.current_status 改状态枚举；事件唯一归位 plots。
