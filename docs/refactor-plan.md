# ST 插件单包收敛与可维护性改造计划

状态：待执行。本文记录已确认的方向及执行步骤，不代表重构已经完成。

## 1. 任务与授权范围

将当前仓库收敛为一个 SillyTavern 记忆插件，删除失去用途的宿主、功能和工程边界，提升代码可读性，减少修改时的额外影响面。

已确定的范围：

- 删除 `core`、`apps` 的工程划分，将 Core 与 ST 插件合并到根级单一 `src`。
- 停止维护并移除 `apps/api`、`apps/web` 及其专属代码、测试、配置和运行命令。
- 删除 R2 Sync 功能，保留本地备份、导入导出、克隆、聊天文件镜像及恢复。
- 保留共享领域模型、共同业务规则和必要的外部依赖隔离。
- 功能按目录组织，允许直接调用，不建立独立业务上下文或强制模块 Contract。
- 不引入事件总线、DI 容器、微服务、CQRS 或通用业务框架。
- 本次不新增产品功能，不重新设计界面，不改变已保留功能的用户行为。

用户将本文交给执行者后，可在以上范围直接推进。遇到影响数据兼容性或明显超出范围的关键歧义，再说明具体问题。

## 2. 执行约束

1. 先读根 `README.md`、`AGENTS.md`，遵守用户补充的规则；全部文本以 UTF-8 读写。
2. 不主动使用用户禁止的 Skills；不因本计划引入新的架构流程。
3. 检查 Git 工作区，不覆盖用户已有修改。不主动提交、推送或发布。
4. 不删除本机数据库、ST 安装目录、用户配置文件、`tmp` 中的参考资料及其他运行数据。版本控制中的废弃源码可按计划移除。
5. 不增加防御性分支、静默吞错、默认成功或替代执行路径。保留实际业务校验、并发约束和数据兼容行为。
6. 新方法按业务含义命名，避免新增泛化的 `parseXxx`、`resolveXxx` 命名。必要注释说明规则、事务或宿主限制。
7. 保留当前工具链版本约定，以 `mise.toml` 和项目配置为准，不顺带升级依赖。
8. 通过本地检查后即可交付，不自行调用会部署到 ST 或发布远端的命令。

这是职责示意，不是创建空文件、空目录的清单。已有实现优先迁移和整理，必要时保留清楚且准确的原文件名。无需为每个功能套 `domain/application/ports/adapters`。

根目录保留 `scripts`、`tests/architecture`、`tests/integration`、`docs`、`manifest.json`、单一 `package.json`、锁文件及检查配置。构建产物仍为 `dist/index.js`、`dist/manifest.json`、`dist/style.css`，不纳入手工维护的源码。

### 3.2 公共模型与业务调用

- `features/memory/domain` 是记忆模型与共同规则的唯一来源，包含空间、表格、字段、记录、证据、修订、提案等。
- 任务、清洗规则、预设、UI 草稿等类型各归所属功能或界面；不要全部搬进公共 Domain。
- Domain 不依赖 React、Dexie、ST、LLM SDK。
- 普通功能通过函数、具体服务直接协作。输入、结果类型与其操作放在一起，不复制 DTO。
- 无须为每个具体服务增加同形接口。删除无实际价值的 `*UseCases` 等重复抽象前，先确认所有消费者。
- 保留必要的仓库、LLM、聊天来源、事务等外部端口；接口归使用它的业务，实现在 `infrastructure`。
- Agent SDK 相关执行细节集中在 Agent 执行与工具代码中，厂商请求及 ST 协议集中在基础设施中；不为消除所有第三方类型而重建整套 SDK 协议。

建议调用方向：

```text
UI → 功能流程
填表 → Agent → Memory 查询/预览
填表 → Memory 提交 + 台账更新
问答 → Agent / Memory
手动编辑 → Memory
```

Agent 生成提案；调用方负责提交前的取消、聊天身份及交互确认等流程检查。Memory 统一执行记录校验、引用检查、修订、历史、证据及显示文本处理。

禁止形成业务运行时循环依赖。需要结果的步骤直接 `await`；不把同步业务流程改造成事件链。现有必要的状态订阅和宿主事件桥可以保留。

### 3.3 Memory 入口约束

- 其他功能及 UI 只通过 `features/memory/index.ts` 使用 Memory。
- 入口只导出必要的完整操作、公共领域类型和持久化接口。
- 其他功能不得调用 Memory 的内部写历史、生成修订等步骤。
- `infrastructure/indexeddb` 可以从此入口导入仓库接口及领域类型。
- `runtime.ts` 的装配若确实需要内部构造器，可增加精确例外，不把整个工程列为例外。
- Memory 内部允许按文件直接引用。
- 通过 ESLint 和/或架构测试约束实际导入路径，涵盖 `import`、重导出及项目采用的动态导入形式；相对路径和别名不能绕过约束。
- 不要求其他每个小目录都创建公开入口或 Contract。

### 3.4 事务与数据约束

- 填表的记录提交与台账标记继续使用同一个 IndexedDB 事务；任一步失败，两者均回滚。
- 保留现有无提案批次的台账处理、取消安全点、聊天切换和活动任务并发约束。
- 保留手动编辑与 Agent 提交共用的记录修改实现，禁止在两个入口复制规则。
- 重构不改变数据库名、数据 ID、ST 元数据键、备份格式和镜像格式。
- 保留 IndexedDB 版本历史。遗留表的声明可能承担兼容作用，不得因“没有运行时引用”直接删除。
- 通用日志继续使用独立数据库，不进入备份和镜像，不随空间删除级联。

## 5. 分阶段执行

### 阶段 A：建立基线与迁移清单

1. 检查工作区、包依赖、构建入口、测试配置、开发同步与发布脚本。
2. 执行当前类型检查、lint、格式检查、测试与构建，记录已有失败及环境限制；不要把历史失败记为重构引入。
3. 识别仍有插件消费者的代码，特别是 R2 共用能力、旧 Agent 装配、系统表模板及仓库接口。
4. 将基线与后续阶段结果记录到 `docs/refactor-progress.md`，使用完成、未完成及阻塞原因描述真实状态。

完成标准：明确迁移来源、基线状态和所有删除项的依赖关系。

### 阶段 B：拆除 R2 Sync

先迁移仍被使用的共用能力：

- `SpaceFingerprint`、`SyncChangeSource` 及比较逻辑归 Memory 的变更检测能力。
- `DexieSyncChangeSource` 归 IndexedDB，去掉云同步专属命名。
- `SyncTimerPort`、轮询骨架迁到 `common`；不在此阶段重写为新的事件系统。
- `resolveCloudLww` 被聊天镜像使用的部分，归聊天镜像的更新时间比较逻辑。

然后删除：R2 Adapter、S3 签名、云同步协调器、云空间/索引文件协议、配置与配置判断、状态展示、立即同步按钮、启动拉取、防抖上传和重试。

同步调整设置折叠组、状态文案、样式、测试、运行时和验收脚本。设置读取不再保留 R2 字段，下一次保存移除旧凭证，保留其他设置。先核查宿主设置写回方式，确保没有通过浅合并继续残留 `r2`。

完成标准：保留功能无 R2 代码依赖；镜像、记忆宏、Agent 宏仍可工作；相关测试通过。明确废弃的历史 ADR 可保留并标记被取代。

### 阶段 C：收敛单包与路径迁移

1. 按目标归属迁移源码、测试和静态资源，更新全部导入。
2. 合并根依赖、版本号及命令，取消 `workspace:*` 和递归包命令。
3. 删除 API、Web 和其专属依赖、测试、SQLite 迁移及 seed 命令；故事种子资产若已无用途再删除，不迁建新种子功能。
4. 删除完成迁移后的 `core`、`apps`、`packages`。检查工作区配置是否仍有实际必要，单包无需保留包列表。
5. 更新浏览器侧与构建脚本侧 TypeScript 配置、Vitest、ESLint、Prettier、忽略项及锁文件。
6. 更新构建入口、静态资源路径、watch 范围、ST 目标目录读取、发布版本来源和产物路径。
7. 根包沿用插件当前版本，不因路径迁移任意升级版本。运行时版本和发布产物 manifest 版本继续同源。

根命令至少提供 `dev`、`build`、`typecheck`、`lint`、`format:check`、`test`、`release:st`；若保留 `sync`/`deploy:st`，文档明确其会写入 ST 安装目录。

完成标准：仅一个源码包；全项目检查使用根命令；本地构建产物形状正确；无活动配置继续引用旧工作区包。

### 阶段 D：业务归位与入口收敛

1. 取消全局 `core/application`；业务流程放回对应功能目录。
2. 保留并整理现有共享记录修改实现。提供查询、预览、手动修改及提案提交等实际需要的完整操作。
3. 将时间、ID、显示文本计算等提交细节收进 Memory 装配或内部实现，减少填表、问答暴露的底层上下文。
4. 事务由完整流程组织，收窄接口时保留记录与台账原子性。
5. 合并重复 Agent 装配。API 删除后，核查 `ProposalAgent` 的生产消费者；确实无消费者时移除，将有价值的运行契约测试迁到保留实现。
6. 删除无实际用途的重复接口、类型转换和导出中转；端口是否保留依据实际依赖与测试用途判断。
7. 实施 Memory 导入约束；Domain 无外层依赖，业务无具体基础设施或 UI 依赖。

完成标准：业务直接协作；共同规则单一实现；入口约束生效；测试仍验证保留实现的行为。

### 阶段 E：拆分 UI 热点与整理运行时

1. 拆分原 `panel-shell.tsx`，外壳仅处理窗口、导航、Tab 和公共上下文。
2. 表格字段编辑、记录、任务、问答、日志、设置分组各归对应 UI 目录。
3. 将备份导入、克隆、设置保存后的联动等业务编排移到对应功能；组件管理草稿、选择、弹窗、加载和错误展示。
4. 用局部依赖参数取代组件对整份 Runtime 的依赖，不新增与服务完全重复的接口层。
5. 将 Runtime 中的提示词准备、宏内容聚合等具体逻辑移到所属功能；Runtime 保留装配、订阅接线和生命周期。
6. 样式按界面职责拆分，继续生成一个 `dist/style.css`；开发 watch 同时覆盖样式和静态资源。
7. 保留 DOM 类名、`data-action`、`data-stm-field` 及交互；必须变化时同步更新验收脚本。

完成标准：面板外壳不再承载各功能具体操作；组件不操作数据库表或 Memory 内部步骤；构建与界面行为保持一致。

### 阶段 F：文档、验证与交付

1. 重写 README：ST 插件用途、根开发命令、配置位置、构建产物、验证与发布。
2. 更新 `AGENTS.md` 中失效的多上下文说明、`CONTEXT-MAP.md`、领域词汇和文档引用。保留原决策历史，将过时 ADR 标记为被新结构取代。
3. 将插件 ADR、备份/镜像说明和浏览器验收文档迁到根 `docs`，更新脚本路径。
4. 扫描旧包名、旧源码路径、R2、SQLite 和 API/Web 命令；检查命中项，区分活动代码与明确标记的历史说明。
5. 运行最终检查，更新进度记录，交付改动摘要、验证结果及未解决问题。

## 6. 验证要求

迁移与清理分步完成，每个稳定阶段执行针对性验证；最后完整执行：

```bash
pnpm typecheck
pnpm lint
pnpm format:check
pnpm test
pnpm build
```

沿用已有有价值的测试，路径变化不应成为删除测试的理由。只给关键缺口补充有意义的行为测试，不为简单搬文件新增镜像实现的测试。

重点验证：

- 字段类型、引用、显示策略与记录合法性。
- 修订冲突、历史与证据关联。
- 手动修改和 Agent 修改遵守相同规则。
- 填表记录写入及台账更新同事务，台账失败时记录也回滚。
- 无提案批次、取消、失败重试、聊天切换和启动中断。
- 系统表安装和空间清除/重置。
- 备份导入导出、空间克隆、镜像写回和本地缺失恢复。
- 旧设置可读取，保存后不再包含 R2 凭证，其他字段保留。
- 记忆宏、Agent 宏和预设展开。
- 构建、版本注入、开发 watch、发布脚本路径及静态资源输出。
- Memory 公开入口和架构依赖限制。

真实 ST 验收应使用隔离测试环境或已获授权的现有环境，不使用用户实际数据做清空/重置验收。检查插件加载、空间绑定、编辑、填表、取消、问答、宏、备份和镜像。无可用环境时，明确记录未验证，不将单元测试当作真机验收。

发布脚本优先通过已有测试及路径审查验证；先确认 `--dry-run` 的实际副作用，不把参数名称当作无副作用保证。不运行发布推送或向用户 ST 安装目录同步。
