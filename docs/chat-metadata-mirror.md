# 对话文件镜像（ticket 16）

把当前对话的记忆快照（表格结构 + 记录 + 修订历史 + 证据）写进聊天文件的
`chat_metadata.steMemoryMirror`，随聊天文件走：文件同步到哪，记忆就跟到哪。
独立通道——**不做跨服务协调**，镜像只解决一件事：换设备/本地库被清时，
能从聊天文件本身恢复记忆。

## 工作机制

- **写回**：当前对话的记忆数据变化后，防抖（3s）把该空间完整快照写进
  `chatMetadata.steMemoryMirror` 并触发 ST 保存（随聊天文件落盘，重命名自动跟随）。
  写回前与文件里已有镜像比较（LWW）：本地较新才写，绝不覆盖更新的镜像。
- **恢复**：打开对话时发现「绑定在、空间不在本地库」（新设备/存储被清），
  若文件里有有效镜像且 spaceId 与绑定一致 → 自动恢复该空间（含记录与修订历史），
  面板头部显示「已从文件镜像恢复」。恢复只影响该对话的空间，不碰其他对话数据。
- **跨设备与分支**：空间缺失时，先校验并恢复镜像，再判断对话身份。单聊文件名保持
  相同、仅角色索引变化时，自动更新绑定为本机身份并接续原空间；角色索引属于设备
  本地编号，不能单独作为跨设备分支依据。文件名变化（复制、分支或重命名）仍进入
  分支确认，可克隆刚恢复的空间或创建空空间。本地空间已经存在时，身份差异仍需
  分支确认，镜像不会覆盖本地数据。群聊保留原有身份检查。
  现有 v2 绑定无法区分「同名文件跨设备导入」与「改角色编号后复制且保留同名文件」；
  空库恢复时两者均按导入处理。
- **守卫**：临时/未保存对话不写；文件里已有无法识别的镜像（来自更新版本插件）
  原样保留不覆盖；防抖期间切换对话不会把旧对话镜像写进新对话文件。

## 设置

设置面板 →「对话文件镜像」组：

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 随对话文件同步记忆镜像 | 开 | 跟随插件总开关；关闭后不写不恢复 |
| 镜像包含修订历史 | 开 | 关闭后镜像不含修订记录，体积更小 |
| 镜像状态 | — | 上次写回时间 + 镜像体积（KB） |

## 已知限制

- 本地删除不传播：另一台设备打开该对话时，文件里的旧镜像会把已删记录恢复回来
  （与「另一设备打开同文件后复活」同源）。
- 无失败信号：ST 保存聊天文件失败时插件无法感知，状态只展示「上次写回时间」。
- 文件镜像比本地数据新（另一台设备的更新未落地到本机数据库）时只提示不动作。
- 镜像体积不设上限：长对话 + 频繁修订时文件会变大；可用「包含修订历史」开关控制。

## 手动验收步骤（真实 ST，双端）

已自动化：`docs/playwright-st-extension/verify-chat-metadata-mirror.mjs`（17 项断言，2026-08-10 真机 headless 全绿）覆盖步骤 1/3/4/5/6/7；步骤 2（修订历史开关）当前只能验证开关存在与写回正常——无记录时 history 恒为空数组，深度验证待记录 CRUD（ticket 11）就绪后补充。

1. **写入**：打开对话（自动建空间）→ 面板手动新建一条记录 → 等待约 5s →
   打开聊天文件 JSONL，第一行 `chat_metadata.steMemoryMirror` 存在且
   `spaceId` 与绑定一致、`data` 含新记录；设置面板镜像状态显示「上次写回 … · N KB」。
2. **修订历史开关**：设置关掉「镜像包含修订历史」→ 再改一条记录 → 文件里镜像
   `data.history` 为空数组（records 仍在）；重新打开开关后恢复包含。
3. **恢复**：清空浏览器 IndexedDB（或换设备）→ 重新打开同一对话 →
   面板头部出现「已从文件镜像恢复」，表格/记录列表完整（含修订历史）；其他对话
   的记忆不受影响。
4. **重命名跟随**：重命名对话文件 → 镜像随文件走，恢复仍指向同一空间。
5. **LWW 不覆盖**：手工把文件里镜像的 `updatedAt` 改成未来时间 → 改本地记录 →
   等待 → 文件镜像未被覆盖（日志 warn「比本地数据新，未覆盖」）。
6. **无法识别镜像不覆盖**：把文件里镜像的 `version` 改成 99 → 改本地记录 →
   镜像原样保留（日志 warn「无法识别…已原样保留」）。
