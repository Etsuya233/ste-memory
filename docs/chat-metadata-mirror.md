# 对话文件记忆快照

聊天文件的 `chat_metadata.steMemoryMirror` 保存当前空间的完整内容：空间、表、字段、
记录、修订历史、证据和必要楼层进度，对话宏属于空间。`steMemory` 保存空间绑定。
对话文件是空间内容唯一持久化来源，原始聊天消息及实际文件写入由 ST 管理。

## 加载与版本

初始化消费 ST 已载入的当前聊天 metadata，校验文件外壳、领域版本、空间身份与完整性，
再导入 SQLite；插件不为普通加载额外下载完整聊天。旧文件与备份仍经
`features/memory-snapshot/snapshot-migration.ts` 统一迁移，之后校验当前格式。
文件外壳版本与 `data.schemaVersion` 分别管理外层协议和领域数据结构。
当前文件外壳为 v3，领域快照为 schemaVersion 3，`floorLedger`、`space.stableId`、当前记录与历史的 `stableId` 为必填。领域 v1/v2 明确迁移：空间取原空间 ID，当前及已删除记录的历史取原记录 ID；新格式缺失稳定身份拒绝加载和写回。

旧快照未提供的楼层进度视为未知，不从本机 Dexie 的旧空间内容或独立台账猜测。
当前快照导入、导出和克隆同时携带记忆内容及必要进度，不恢复旧辅助任务、向量或助手会话。
当前格式缺必填字段、未知版本或损坏内容直接拒绝，不把损坏数据当成空空间。

有绑定却无快照、快照与绑定不符、绑定损坏，都会明确停止加载。已有快照却缺绑定也会
停止初始化并保留原内容。只有快照与绑定都不存在的新聊天才创建默认空间。
正常启动不读取旧 Dexie 空间数据，不进行旧空间存在检测、迁移或恢复。

## 普通提交

```text
SQLite 同事务提交记忆修改与必要楼层进度
  → 导出完整快照并发布已提交事件
  → 同步更新当前 ST 内存中的快照与绑定
  → 释放 SQL writer
  → 请求 ST 原生即时保存
```

一次记录保存、结构修改或一个填表批次触发一次宿主保存，输入框逐字输入仍是草稿。
插件不额外增加时间防抖，不读取聊天文件后自行上传，不把网络等待放进 SQL writer。
公共只读接口、宏和向量消费已提交事件，刷新失败独立报告，不能跳过宿主保存。

普通提交不回读服务器，宿主调用返回只表示该调用结束。ST 可能在内部捕获网络错误，
因此界面只报告已交给 ST 保存，不能据此声称远端已确认。填表执行进度与记录一起提交，
不再依赖文件成功回调去补写另一份权威台账；保存重试也不重新调用模型。

## 强制同步

设置页的“强制同步”保存当前 SQLite 已提交内容，不包含未提交的表单草稿。
它等待已有 Memory 提交结束，捕获当前聊天身份、绑定和完整快照，再使用同一宿主保存入口。
期间协调 Memory 写入与重复点击，保存后只读回读捕获的目标文件，按结构比较两个 Memory 键。
仅匹配时显示远端已核验；失败报告原因并释放本次同步门控，下一次重新捕获最新内容。
已运行填表在批次边界等待临时同步结束，已持有事务的批次可以完成提交；新手动编辑被阻止。

强制同步不传 ST 的 `force=true`，不跳过完整性检查，不把本地旧聊天内容写入新聊天。
当前存在关键候选待确认时，按钮继续同一个候选保存和核验任务，不重新导入或重建。
核验只证明回读时内容一致，不阻止之后其他客户端或宿主旧请求再次覆盖文件。

## 候选替换与辅助清理

导入、分支和预设重建先验证候选，随后在当前内存中激活并发布其快照与绑定。
涉及旧辅助数据删除的关键操作在核验完成前暂停后续 Memory 写入、填表和再次替换。
原生保存后回读固定目标，只有两个 Memory 键与本次候选一致，且原操作仍有清理权限，
才清除旧空间对应的任务、向量和助手会话等辅助数据。分支不删除源聊天辅助数据。

失败保留候选、旧辅助与待确认门控；重试只保存及核验，不重新生成另一份候选，
也不自动把 metadata 回滚到旧内容。网络失败或超时并不能证明服务器没有完成写入。
候选仅在当前页面内保留，刷新后重新按文件加载；未经确认的辅助数据保留。

## 切换聊天

离开聊天停止旧聊天在途工作，等待 SQL 操作结束并卸载 SQLite；不主动向旧文件后台补写。
已进入 ST 的保存由宿主完成。向量 queued 任务保留，已发出请求中断，只有活动空间可以领取任务。
卸载不清辅助数据，也不建立所有聊天的完整空间缓存。

普通聊天返回时从宿主已加载的文件内容恢复。当前页面仍持有该聊天的关键候选时，
优先恢复候选与待确认门控，不能悄悄加载旧文件后放开编辑。候选可继续只读核验原文件，
但写入重试必须等原聊天活动；迟到结果不能发布到新聊天或清理其同空间 ID 的数据。

## 保证范围

该方案减少额外聊天下载和独立写入者，ST 原生保存仍可能上传整份聊天。
SQLite、聊天文件与 IndexedDB 辅助数据没有共同事务；未落盘的普通修改在切聊或关闭页面时
仍可能丢失，不提供跨设备并发编辑协调、崩溃恢复、服务端局部更新或强制覆盖。
决策与维护边界见 [ADR 0034](./adr/st/0034-host-managed-memory-save.md)。
