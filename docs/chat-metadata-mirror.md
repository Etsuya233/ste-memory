# 对话文件记忆快照

聊天文件的 `chat_metadata.steMemoryMirror` 保存当前空间完整快照：表格定义、字段、
记录、修订历史与证据。快照信封使用 `ste-memory-chat-mirror` version 3，`data.schemaVersion` 为 1，
与备份文件共用空间快照契约。原始聊天消息仍由 ST 管理，不导入 SQLite。

## 快照版本与迁移

备份与镜像的外壳版本描述文件格式，空间快照的 `schemaVersion` 描述领域数据形状，二者独立维护。
旧外壳 v1/v2 明确映射旧快照形状，通过 `features/memory-snapshot/snapshot-migration.ts` 统一转换，
补齐初始化来源、对话宏、表格顺序和向量分组 Key。v1 的独立旧视图集合先转成空间中的表达式宏；
旧当前记录中已删除字段留下的空证据键可以清除，非空证据不会丢弃，历史字段键保留。

IndexedDB v11 在版本升级事务中组合旧空间快照并调用同一入口，升级后在空间行持久化
`snapshotSchemaVersion`，读回时显式移除这个存储元数据。新建、克隆和缓存写入也保存当前标记。
文件旧表格按数组顺序赋位，本地旧表格保留创建时间与 ID 的顺序，已有显式位置始终保留。

当前外壳必须携带完整当前快照；缺必填字段、未知版本或内容损坏时直接拒绝，不在保存时补字段。
迁移在克隆改 ID 与 SQLite 导入之前完成。保存仅校验当前快照，SQLite 提交、差量缓存与文件写回的
既有顺序保持不变。对话绑定与镜像空间 ID 冲突仍由加载流程明确拒绝，迁移不改写身份。

## 初始化来源

“随对话文件同步记忆镜像”默认开启。每次进入对话，按捕获的文件身份读取聊天文件，
校验镜像格式、版本、空间身份和内容完整性，再初始化 SQLite 内存数据库。
本地缓存即使较新，也不替代合法文件快照，不再按更新时间进行 LWW 裁决。

已有绑定且文件没有镜像时，可以从已有本地数据迁移并写入文件；新对话按默认预设
建立空间。文件读取失败、文件格式异常、镜像损坏或绑定不符会停止初始化，保留原文件。
关闭同步时从本地 IndexedDB 快照加载，不用文件覆盖本地。

分支仍经过对话身份检查和确认。启用同步时先校验所选分支文件快照，以独立预览保存，
确认克隆后才复制其内容及引用身份，不覆盖原空间的 SQLite 或本地缓存。单聊同名文件
跨设备导入的既有绑定迁移规则继续保留。

## 保存与切换

每次手动保存或整次填表任务成功后执行：

```text
SQLite 提交并发布已提交读取快照
  → 差量更新 IndexedDB 本地快照缓存
  → 立即尝试保存捕获的原对话文件
  → 填表任务更新 IndexedDB 任务及楼层台账
```

本地缓存仍使用现有六类记忆表，不作为第二套在线查询引擎。差量缓存保存不清除
记录向量；明确恢复备份、删除等操作继续使用各自的派生数据清理规则。

单聊通过角色 avatar 与聊天文件名定位，群聊通过聊天文件 ID 定位。保存前读取目标
文件最新完整内容，只替换插件快照键；新建或分支时可同次写入对应绑定。保留正文、
头部、其他插件 metadata 和 ST integrity 标识。不存在的文件、空对象响应、未知格式、
损坏镜像均不会被空数据覆盖；不强制绕过 ST integrity 检查。

收到 `CHAT_CHANGED` 后，先中断旧对话仍在运行的填表任务并回滚，导出旧空间最近已提交
快照，立即发起指定旧文件的保存尝试，然后释放旧 SQLite 并初始化新对话。保存请求持有
独立数据和目标身份，完成回调只有在该文件仍活动时才更新页内 metadata。
无需等待“切换前”事件，也不会将旧空间写入新对话。
快速返回旧对话时，文件加载先等待本实例已排队的保存，避免读取保存前的旧快照。

## 设置和状态

| 项目                   | 当前行为                                                |
| ---------------------- | ------------------------------------------------------- |
| 随对话文件同步记忆镜像 | 默认开启；关闭后保存本地快照，不读写文件镜像            |
| 镜像包含修订历史       | 旧设置保留兼容；SQLite 保存路径始终包含完整历史，不裁剪 |
| 镜像状态               | 显示保存中、最近成功时间或具体失败原因                  |

SQLite 提交成功与文件保存成功分开处理。文件请求只有收到宿主 `{ ok: true }` 才标记
成功；它不构成跨引擎原子提交，也不承诺宿主文件系统级持久性。失败后当前内存结果保留，
再次保存导出当前完整快照，不重新运行 Agent，不持久化待重试结果。

## 接受的限制与验证状态

不实现跨标签页锁、版本合并、提交日志、回执对账、崩溃恢复或自动重放。
保存失败后立即关页可能丢失最近修改；文件与任务进度偶尔不同步属于接受范围。
全量聊天文件的读改写仍可能与宿主或另一页面并发保存竞争，不保证冲突合并。

Node 集成测试已覆盖真实 SQLite 初始化、较旧文件优先、保存失败后的切换重试、旧文件
目标身份和新对话隔离；文件适配器测试覆盖读取异常不覆盖及正文、其他 metadata 保留。
Worker/WASM 已加入打包，真实 ST/Edge 的单聊群聊、手动保存、文件优先重开、保存失败后
切换重试和真实备份导入已完成验收，见 [浏览器验收记录](./sqlite-browser-e2e.md)。
其他 WebView 尚未验证。
此前基于轮询、防抖和 LWW 的浏览器验收脚本只证明旧版行为，不能作为本次迁移验收结论。
