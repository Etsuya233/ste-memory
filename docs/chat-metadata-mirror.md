# 对话文件记忆快照

聊天文件的 `chat_metadata.steMemoryMirror` 保存当前空间的完整内容：空间、表、字段、
记录、修订历史与证据，对话宏属于空间。文件外壳为 v3，`data.schemaVersion` 为 1。
对话文件是空间内容唯一持久化来源，原始聊天消息继续由 ST 管理。

## 加载与版本

初始化读取指定聊天文件并校验格式、领域版本、空间身份与完整性，再导入 SQLite。
旧外壳 v1/v2 继续走 `features/memory-snapshot/snapshot-migration.ts`，规则集中维护；
当前格式缺必填字段、未知版本或损坏内容直接拒绝。旧备份携带的辅助任务/台账只用于
历史文件读取兼容，当前空间导入不恢复这些辅助数据，导出只包含完整空间内容。

有绑定却无快照、快照与绑定不符、绑定损坏，都会明确停止加载。文件已有快照却缺绑定
也会停止初始化，保留原内容。只有确认文件没有快照且没有绑定的新聊天才创建默认空间。
正常启动不读取旧 Dexie 空间数据，也不进行旧空间存在检测、迁移或恢复。

## 普通提交与文件保存

普通修改按以下顺序执行：

```text
SQLite 提交 → 发布已提交事件 → 导出完整快照并同步交给保存组件 → 释放 SQL writer
  → 指定聊天文件保存 → 确认该快照对应的填表批次进度
```

已提交事件通知公共只读接口、宏与向量刷新，刷新错误独立报告，不能跳过文件保存。
SQLite 提交成功而文件失败时，界面显示“已提交、未保存”。重试保存组件所持有的最新
有效快照，不重新执行记录修改或模型请求。文件成功但批次台账确认失败时，仅重试确认。

保存组件按固定文件目标持有快照、绑定及明确的写文件/批次确认/候选激活阶段。
同聊天较旧保存结果不能发布到较新的 metadata。插件总开关不丢弃尚未完成的保存任务。
页面刷新保护检查所有聊天的待保存状态，切换到其他聊天不会使失败快照失去归属。

## 候选空间替换

导入与分支先从已迁移快照产生独立副本，并验证 SQLite 约束。候选空间保留在保存组件，
先停止原空间写入，再把新绑定和对应完整快照同次写入捕获的目标文件。成功后发布新绑定、
装载新空间并清理旧空间任务、楼层台账、向量和助手会话；分支克隆不清理源聊天辅助数据。
保存失败时不提前修改 `chatMetadata` 中的绑定，也不清除原空间辅助数据。

旧空间编辑和新填表在候选未完成时被阻止，避免覆盖候选。排队前过期的校验请求取消，
已交给保存组件的任务可以跨聊天完成。若文件成功而激活失败，重试激活已保存候选，
不会重新导入另一份副本或重新写文件。

## 切换与辅助数据

离开聊天先停止旧聊天在途工作，等待 SQL 操作结束并卸载 SQLite。向量 queued 任务保留，
只中断已发出的请求；只有当前已加载空间可以领取向量任务。卸载不触碰辅助数据。
返回有未保存内容的聊天，优先使用保存组件持有的快照，磁盘旧内容不能覆盖它。
成功保存的非活动聊天释放完整内存快照，只保留必要保存状态。

退休与卸载都持有原文件归属；同一领域空间 ID 已由另一聊天激活时，迟到任务不能卸载
或清理该聊天。这里不建立跨聊天目录、身份修复、跨引擎原子提交或跨标签页协调。

## 宿主文件协议

单聊通过角色 avatar 与聊天文件名定位，群聊通过聊天文件 ID 定位。保存前读取目标文件
最新完整内容，只替换本插件的快照及绑定键，保留正文、头部、其他 metadata 与 ST integrity。
不存在的文件、空对象响应、未知格式和损坏镜像会明确拒绝覆盖。宿主确认 `{ ok: true }`
后，保存组件还会检查该任务是否仍为最新，随后才发布活动页内存 metadata。

文件、辅助台账和 SQLite 不组成共同事务；刷新仍会丢失尚未落盘的内存任务，不提供崩溃恢复。
当前实现与验收说明见 [ADR 0033](./adr/st/0033-chat-file-only-memory.md)。
