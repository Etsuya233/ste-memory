# 表格预设

实现说明（需求文档：`.scratch/table-presets/spec.md`；决策记录：[ADR 0017](./adr/st/0017-table-presets.md)）。
本文描述插件当前的表格预设行为与实现位置，供后续维护参考；系统自带预设的八张表内容见
[`docs/system-memory-tables.md`](./system-memory-tables.md)。

> 术语提示：`docs/system-memory-tables.md` 写作时表格还带系统表身份（`kind: system`），
> 该身份已废弃（见下）；该文描述的八张表内容即当前「系统默认」预设的内容。文中提到的
> `SystemMemoryTableInstaller` 也已由表格预设的实例化路径取代。

## 概念

| 术语 | 说明 |
| --- | --- |
| 表格预设 | 可复用的表结构、字段、填写规则、引用关系与显示策略，不含记忆记录 |
| 系统自带预设 | 「系统默认」与「剧情记忆」：随插件提供，不落库；不可删除、重命名或覆盖，可复制、导出 |
| 用户预设 | 新建、从空间另存、复制或导入得到；可编辑结构、重命名、覆盖、删除、设为默认、导出 |
| 默认预设 | 创建全新记忆空间时采用的全局预设，初始为「系统默认」 |
| 应用预设 | 清空当前空间的结构与记忆数据，随后按选定预设重新初始化（保留空间身份与绑定） |
| 初始化来源 | 最近一次创建或应用时使用的预设来源快照（ID / 名称 / 时间），仅说明用途 |

核心规则：设置默认只影响以后创建的全新空间；应用到当前空间不会改默认选择；编辑或删除预设
不改变已有空间；编辑空间中的表格不会反向更新预设；每个空间拥有自己的表格与字段 ID。

## 实现结构

```text
src/features/table-presets/
├── preset-model.ts              # 预设结构类型、设置合并、名称与解析规则
├── table-preset-library.ts      # 预设库操作（另存/重命名/覆盖/删除/复制/设默认）
├── system-preset.ts             # 原系统默认预设（由 SYSTEM_TABLE_TEMPLATES 计算）
├── story-memory-preset.ts       # 剧情记忆：8 张表、44 字段与通用填写规则
├── preset-transfer.ts           # 版本化 JSON 导入导出与结构校验
├── preset-instantiation.ts      # 预设结构 → 空间表/字段行（新 ID + 引用/策略按 Key 映射）
├── space-structure-capture.ts   # 空间表/字段 → 预设结构（ID 引用改写为 Key 引用）
└── table-preset-apply-service.ts# 停止写入 + 原子重建 + 重建后同步
src/features/space-maintenance/
└── space-structure-rebuild.ts   # 原子重建端口（单事务：结构/数据/任务/进度/来源）
src/infrastructure/indexeddb/space/
└── space-structure-rebuild-repository.ts  # Dexie 实现（八张表同一读写事务）
```

设置持久化：`PluginSettings.tablePresets = { userPresets, defaultPresetId }`（全局插件设置，
不随对话切换）。设置页分组「表格预设」由 `src/ui/settings/table-preset-manager.tsx` 渲染，
纯逻辑模型在 `table-preset-manager-model.ts`。

## 编辑预设

设置 → 表格预设 → 预设管理提供「新建空白预设」和用户预设的「编辑」。编辑页沿用表格页的表格、字段表单，可维护名称、说明、通用填写规则、表格与字段定义、顺序、启用状态、显示策略及字段约束，无需活动聊天或记忆空间。预设不包含记录，字段类型允许修改，切换后清除旧类型专属配置。

界面复用表格页的可折叠表格卡片、表格及字段启停开关和「管理字段」模式，首张表默认展开；表格、字段和显示策略编辑器在所属卡片内打开。预设信息与通用填写规则放在顶部折叠区，字段约束在对应字段的管理区展开。显示策略依赖字段会显示标记，并禁用停用和删除操作。

表格及字段表单先完成局部编辑，最后点击「保存预设」统一保存到全局预设库。保存保留用户预设 ID、创建时间和默认选择，不修改已有空间。新建与「复制并编辑」在保存前只产生页面草稿。内置预设可只读查看，也可从列表复制并编辑。

修改表 Key 自动更新字段引用目标；修改字段 Key 自动更新本表显示策略及模板占位符。填写规则中的文字引用需自行核对。删除被其他表引用的表格时，会明确显示依赖并阻止删除。保存与导入共用完整校验，拒绝重复 Key、无效引用、显示策略或字段配置。

离开编辑页、切换页签、收起预设分组及关闭面板时，有未保存修改会提示确认放弃；浏览器关闭或刷新采用原生离开提示。尚未完成的表格、字段表单输入也参与离开检查。

## 升级与内置预设

升级后预设列表自动出现「剧情记忆」（`storyMemory`），原「系统默认」（`systemDefault`）和用户预设继续保留，默认选择不变。新预设包含人物、人际关系、地点、物品、纪要、重要事件、世界状态、剧情总结，共 44 个字段；7 个独立时间字段采用 `datetime`。

剧情总结通过纪要的可选单条引用 `plot_summary` 表达来源。预设初始规则为：已保存且未总结的纪要达到 20 条时，取创建时间最早的 15 条生成总结，每批最多一条，并同批更新来源纪要归属。触发与内容同步由统一填写 Agent 遵循 Prompt 执行，尚无强制分组约束或自动失效检测。新增预设不会自动改变宏注入范围，已总结纪要的自动排除仍待实现。

旧空间的字段与记录不自动改写。项目已有 Dexie v1–v5 数据库升级；从旧表结构到新预设的内容迁移仍未提供。新增内置预设由运行时列出，无需批量写设置或迁移旧空间。

## 通用填写规则

预设可携带 `prompt`，创建或明确应用时复制到 `MemorySpace.prompt`；旧空间、旧用户预设缺省表示无共用规则，无需 IndexedDB schema 升级。规则随备份、对话镜像、空间克隆与预设另存保留。覆盖或重新应用不带规则的预设会清除原空间的共用规则。

填写 Agent 的摘要包含空间共用规则、启用表的 Prompt 和启用字段的 Prompt。默认提示词与自定义预设中的 `{{tablesDigest}}` / `{{systemDefaultPrompt}}` 共用此摘要；自定义预设应选择其中一个占位符，避免重复。只读查询 Agent 只接收结构，不携带填写指令。

## 导入导出

设置 → 表格预设 → 预设管理提供「导入表格预设」，每条预设提供「导出」，内置预设也可导出。文件是 UTF-8 JSON，信封使用 `format: ste-memory-table-preset`、`version: 1`、`exportedAt` 与 `preset`。预设内容含名称、说明、共用规则和表字段定义，不含记录、空间身份、预设 ID 或默认选择。

导入先完整校验版本、字段类型、表/字段 Key 唯一性、引用与显示策略，再新建用户预设。重名追加 ` (2)`、` (3)` 等编号，重新生成身份和创建时间，不覆盖库中预设、不切换默认、不应用到当前空间。未知版本或损坏内容整体报错，不静默丢弃字段或部分导入。后续文件格式变更需新增显式版本转换。

纪要未填写的引用可能以字段省略或显式 `null` 存储，查询时两者都按空引用处理：`equals null` 选未总结纪要，`not_equals null` 选已归属纪要；按总结 ID 的 `equals` 查询可反查来源。

## 初始化与应用的时序

首次创建记忆空间（`ChatSpaceManager` 首次打开对话）：

1. 创建空间行（`initializationSource: null`）；
2. `TablePresetApplyService.installDefaultStructure`：解析**当时**的默认预设 → 实例化结构 →
   原子重建写入结构并记录初始化来源；
3. 最后写绑定指针（绑定存在 ⇔ 空间与结构已就绪）；失败回收空间并上抛，下次打开重试。

应用到当前空间（设置页「表格预设」→「应用到当前空间」）：

1. **一次确认**：固定空间、对话身份和预设内容；打开或取消确认框不停止填表任务。
   确认框给出删除范围、聊天正文保留说明与备份提醒，提供取消 / 备份并应用 / 直接清空并应用；
2. **停止写入与备份**：用户确认执行后取消该空间进行中的填表任务（interrupted，安全点停止）。
   备份并应用先打开文件保存器，选择文件后停止任务并生成完整备份，文件写入且关闭成功才重建；
   取消保存不生成备份、不停止任务、不清空数据。浏览器不支持文件保存器时明确报错，不触发清空；
3. **原子重建**（`SpaceStructureRebuild.rebuild`）：同一 Dexie 事务内删除该空间的表格
   （级联字段/记录/历史）、证据、填表任务与楼层进度台账，写入新结构与新的初始化来源；
   任一步失败整体回滚，原持久化内容保留；
4. **重建后同步**：清除本次操作所属对话的对话级宏（对话已切换则跳过并回报）、重建宏快照、
   立即写回并等待对话文件镜像元数据更新（`flushRebuiltSpace`，不经过防抖排队）；页面内存的问答历史按空间清空。同步失败单独回报为
   `applied-with-sync-issue`，不重做重建、不再清空空间。

## 旧任务隔离

- 填表任务的批次提交（提交提案 + 台账标记）在**同一事务内复检任务行**：只有任务仍为
  `running` 才写入（`FillTaskService` 的安全点 3）。
- 重建事务删除任务行并替换表/字段身份，两份写入在任务表上互斥——重建提交后，旧任务的提交
  事务要么已经完成（数据在重建前落库），要么看到任务行不存在而放弃写入。
- `stopSpaceWrites` 先于备份，「备份并应用」因此不会丢掉最后一次旧写入，也不会在备份后写入。

## 数据处理范围

| 数据 | 处理 |
| --- | --- |
| 空间身份与对话绑定 | 保留 |
| 表格、字段、显示策略 | 删除后按目标预设重建（含用户新增与改过的结构） |
| 记录、修订历史、证据 | 清空 |
| 填表任务、楼层进度台账 | 停止进行中写入后清空 |
| 页面内存问答历史 | 清空（按空间） |
| 当前对话级宏 | 清除（仅当仍是本次操作所属对话） |
| 对话文件镜像 | 重建成功后立即更新；显式重建允许覆盖旧镜像，不受旧 LWW 时间阻挡 |
| 初始化来源 | 更新为本次预设的 ID、名称快照与时间 |
| 聊天正文、角色卡、世界书 | 保留 |
| 全局设置、全局记忆视图、预设库、Agent 配置 | 保留 |
| 其他对话与记忆空间、通用日志 | 保留 |

## 备份覆盖的内容

「备份并应用」导出的单空间备份必须能恢复本次将被删除的持久化内容，因此备份单元在
结构 / 记录 / 全部修订历史 / 证据之外，还携带（不受镜像历史裁剪设置影响）：

- **填表任务与楼层进度台账**（`fillTasks` / `floorLedger`）：单元带这些键 = 恢复时替换
  目标空间的对应行；缺省（对话文件镜像、旧备份文件）= 不涉及，保持目标原有值。
- **对话级宏快照**（`chatScopeMacros`）：导出时写入当前对话的对话级宏；导入到当前对话时
  若文件带该键则写回（缺省 = 保持当前对话的宏）。页面内存的问答历史不纳入持久化备份。

克隆和导入会将备份中的运行中任务转换为 `interrupted`，保留任务历史，避免无执行器的活动任务阻挡新填表。

对话文件镜像刻意不带这三项：任务、进度与宏在对话文件里各有自己的键，镜像恢复只恢复
记忆内容，不触碰它们（与既有行为一致）。

## 兼容与迁移

- **IndexedDB**（Dexie v5）：旧空间补 `initializationSource: null`（界面显示「初始化来源未记录」），
  旧表格按创建顺序补 `position` 并删除废弃的 `kind` 字段。
- **备份文件与对话文件镜像**：表格不再有 `kind`、新增 `position`，空间新增可选
  `initializationSource`；解码时对旧文件归一化（来源补 `null`、顺序按单元内数组顺序补齐），
  新导出总是写全。恢复、克隆与分支新建按实际内容处理，不套用当前默认预设。
- **预设库**：设置合并会丢弃损坏的预设项；默认选择指向不存在的预设时回退「系统默认」。

应用目标已被删除时，选择器显示待选择状态并禁用应用；按 ID 查找不存在的预设会明确报错，不静默切换到系统默认。

## 剧情总结填写

剧情记忆使用纪要的 `plot_summary` 指向剧情总结，来源通过引用反查，原始纪要保留。总结约定全部写在表级和字段级 Prompt 中，由统一填写 Agent 查询和处理。

Agent 在本批新增纪要前查询已保存且所属总结为空的纪要。满 20 条时，按创建时间升序取最早 15 条，每批最多生成一条总结，保留至少 5 条；同批更新全部来源的所属总结，并在提交前检查来源完整性。总结开始取来源最早的已知开始时间，结束取来源最晚的已知结束时间，单条未填结束时用其开始时间，全部未知时留空。来源纠错或补漏时同步修订对应总结。

程序保留通用字段、引用及提案校验；总结门槛、来源选择、数量和时间覆盖由 Agent 按 Prompt 核对，不作专用硬校验。用户调整表或字段 Key 时，需要同步修改引用这些 Key 的 Prompt。更新内置预设不会改写已有空间的结构或 Prompt。

读取继续使用无参宏、`full`、单表宏和已有视图，没有专用 `compact` 宏，也不自动省略已总结纪要；输出仍受全局字符上限限制。

填写 Agent 连续更新同一记录时累计不同字段，同字段后写覆盖，显式 `null` 清空；重写 create 与跨操作替换仍沿用旧语义。设置中的「每批填写时限」控制每批硬中止时间，默认 600 秒，可设 30–1800 秒；已有自定义值保留，取消、超时或提交失败均不提交当前批次。
