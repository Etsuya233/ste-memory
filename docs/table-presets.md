# 表格预设

实现说明（需求文档：`.scratch/table-presets/spec.md`；决策记录：[ADR 0017](./adr/st/0017-table-presets.md)）。
本文描述插件当前的表格预设行为与实现位置，供后续维护参考；系统自带预设的八张表内容见
[`docs/system-memory-tables.md`](./system-memory-tables.md)。

> 术语提示：`docs/system-memory-tables.md` 写作时表格还带系统表身份（`kind: system`），
> 该身份已废弃（见下）；该文描述的八张表内容即当前「系统默认」预设的内容。文中提到的
> `SystemMemoryTableInstaller` 也已由表格预设的实例化路径取代。

## 概念

| 术语 | 说明 |
| --- | --- |
| 表格预设 | 可复用的表结构、字段、填写规则、引用关系与显示策略，不含记忆记录 |
| 系统自带预设 | 「系统默认」：由插件模板计算，不落库；不可删除、重命名或覆盖，可复制 |
| 用户预设 | 从当前空间另存或覆盖得到；可重命名、覆盖、删除、设为默认 |
| 默认预设 | 创建全新记忆空间时采用的全局预设，初始为「系统默认」 |
| 应用预设 | 清空当前空间的结构与记忆数据，随后按选定预设重新初始化（保留空间身份与绑定） |
| 初始化来源 | 最近一次创建或应用时使用的预设来源快照（ID / 名称 / 时间），仅说明用途 |

核心规则：设置默认只影响以后创建的全新空间；应用到当前空间不会改默认选择；编辑或删除预设
不改变已有空间；编辑空间中的表格不会反向更新预设；每个空间拥有自己的表格与字段 ID。

## 实现结构

```text
src/features/table-presets/
├── preset-model.ts              # 预设结构类型、设置合并、名称与解析规则
├── table-preset-library.ts      # 预设库操作（另存/重命名/覆盖/删除/复制/设默认）
├── system-preset.ts             # 系统自带预设（由 SYSTEM_TABLE_TEMPLATES 计算）
├── preset-instantiation.ts      # 预设结构 → 空间表/字段行（新 ID + 引用/策略按 Key 映射）
├── space-structure-capture.ts   # 空间表/字段 → 预设结构（ID 引用改写为 Key 引用）
└── table-preset-apply-service.ts# 停止写入 + 原子重建 + 重建后同步
src/features/space-maintenance/
└── space-structure-rebuild.ts   # 原子重建端口（单事务：结构/数据/任务/进度/来源）
src/infrastructure/indexeddb/space/
└── space-structure-rebuild-repository.ts  # Dexie 实现（八张表同一读写事务）
```

设置持久化：`PluginSettings.tablePresets = { userPresets, defaultPresetId }`（全局插件设置，
不随对话切换）。设置页分组「表格预设」由 `src/ui/settings/table-preset-manager.tsx` 渲染，
纯逻辑模型在 `table-preset-manager-model.ts`。

## 初始化与应用的时序

首次创建记忆空间（`ChatSpaceManager` 首次打开对话）：

1. 创建空间行（`initializationSource: null`）；
2. `TablePresetApplyService.installDefaultStructure`：解析**当时**的默认预设 → 实例化结构 →
   原子重建写入结构并记录初始化来源；
3. 最后写绑定指针（绑定存在 ⇔ 空间与结构已就绪）；失败回收空间并上抛，下次打开重试。

应用到当前空间（设置页「表格预设」→「应用到当前空间」）：

1. **停止写入**（`stopSpaceWrites`）：取消该空间进行中的填表任务（interrupted，安全点停止）。
   这一步在备份之前——备份之后不会再有旧任务写入（spec 6.3）；
2. **一次确认**：确认框给出空间名、目标预设名、删除范围、聊天正文保留说明与备份提醒；
   三个动作：取消 / 备份并应用（先导出当前空间备份，成功后才重建）/ 直接清空并应用；
3. **原子重建**（`SpaceStructureRebuild.rebuild`）：同一 Dexie 事务内删除该空间的表格
   （级联字段/记录/历史）、证据、填表任务与楼层进度台账，写入新结构与新的初始化来源；
   任一步失败整体回滚，原持久化内容保留；
4. **重建后同步**：清除本次操作所属对话的对话级宏（对话已切换则跳过并回报）、重建宏快照、
   kick 对话文件镜像；页面内存的问答历史按空间清空。同步失败单独回报为
   `applied-with-sync-issue`，不重做重建、不再清空空间。

## 旧任务隔离

- 填表任务的批次提交（提交提案 + 台账标记）在**同一事务内复检任务行**：只有任务仍为
  `running` 才写入（`FillTaskService` 的安全点 3）。
- 重建事务删除任务行并替换表/字段身份，两份写入在任务表上互斥——重建提交后，旧任务的提交
  事务要么已经完成（数据在重建前落库），要么看到任务行不存在而放弃写入。
- `stopSpaceWrites` 先于备份，「备份并应用」因此不会丢掉最后一次旧写入，也不会在备份后写入。

## 数据处理范围

| 数据 | 处理 |
| --- | --- |
| 空间身份与对话绑定 | 保留 |
| 表格、字段、显示策略 | 删除后按目标预设重建（含用户新增与改过的结构） |
| 记录、修订历史、证据 | 清空 |
| 填表任务、楼层进度台账 | 停止进行中写入后清空 |
| 页面内存问答历史 | 清空（按空间） |
| 当前对话级宏 | 清除（仅当仍是本次操作所属对话） |
| 对话文件镜像 | 重建成功后按既有机制覆盖写回 |
| 初始化来源 | 更新为本次预设的 ID、名称快照与时间 |
| 聊天正文、角色卡、世界书 | 保留 |
| 全局设置、全局记忆视图、预设库、Agent 配置 | 保留 |
| 其他对话与记忆空间、通用日志 | 保留 |

## 备份覆盖的内容

「备份并应用」导出的单空间备份必须能恢复本次将被删除的持久化内容，因此备份单元在
结构 / 记录 / 修订历史 / 证据之外，还携带：

- **填表任务与楼层进度台账**（`fillTasks` / `floorLedger`）：单元带这些键 = 恢复时替换
  目标空间的对应行；缺省（对话文件镜像、旧备份文件）= 不涉及，保持目标原有值。
- **对话级宏快照**（`chatScopeMacros`）：导出时写入当前对话的对话级宏；导入到当前对话时
  若文件带该键则写回（缺省 = 保持当前对话的宏）。页面内存的问答历史不纳入持久化备份。

对话文件镜像刻意不带这三项：任务、进度与宏在对话文件里各有自己的键，镜像恢复只恢复
记忆内容，不触碰它们（与既有行为一致）。

## 兼容与迁移

- **IndexedDB**（Dexie v5）：旧空间补 `initializationSource: null`（界面显示「初始化来源未记录」），
  旧表格按创建顺序补 `position` 并删除废弃的 `kind` 字段。
- **备份文件与对话文件镜像**：表格不再有 `kind`、新增 `position`，空间新增可选
  `initializationSource`；解码时对旧文件归一化（来源补 `null`、顺序按单元内数组顺序补齐），
  新导出总是写全。恢复、克隆与分支新建按实际内容处理，不套用当前默认预设。
- **预设库**：设置合并会丢弃损坏的预设项；默认选择指向不存在的预设时回退「系统默认」。
