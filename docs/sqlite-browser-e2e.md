# SQLite 浏览器验收记录

日期：2026-10-24。环境：Windows、Edge、真实 SillyTavern `http://localhost:8000/`。

ST 的扩展目录通过 Junction 连接本开发 Worktree 的 `dist`，刷新后使用发布形态的
`index.js`、`sqlite-worker.js`、`sqlite3.wasm` 和样式。测试使用 Seraphina 的独立
`STE-SQLite-E2E-*` 对话及专用群聊，保留测试结果供复查。

## 验收方法

通过 Browser Use 操作实际界面；开发调试接口负责提交可控任务、检查 SQLite 读取结果、
制造文件保存失败和比对完整快照。保存与恢复始终经过真实 ST 文件接口和磁盘聊天文件。

填表和查询 Agent 仅在模型 HTTP 响应边界使用可控 SSE 流，Agent 循环、工具校验、SQLite
Worker、事务、任务台账及文件保存均使用生产实现。本次结论不包含远端模型质量或兼容性。
测试结束后已移除响应替换和网络阻断，并恢复默认开启的镜像设置。

本机 Edge 扩展未开启文件 URL 访问，文件选择器的 `setFiles` 被拒绝。真实文件导入采用
用户指定文件的 UTF-8 内容构建浏览器 `File`，交给界面原有 input/change 处理器，保留
原有备份解码、校验、原生确认、导入和成功提示流程。常规文件选择器传文件仍待该权限
开启后单独验证。未修改扩展权限，也未改写网站确认逻辑。

2026-10-25 事务粒度已调整为每批独立事务。下表为 2026-10-24 的历史验收结果，其中整任务提交、回滚相关条目不再代表当前行为；本次批次隔离通过自动化测试验证，尚未重跑真实 ST 的对应场景。

## 验收发现与修复

浏览器暴露了文件适配器的原生 `fetch` 调用绑定错误：保存为对象属性后调用会触发
`Illegal invocation`。默认请求现已绑定全局对象，并增加调用绑定回归测试；修复后
重新构建、加载并完成上述验收。

自动检查：131 个测试文件、1458 项测试通过；类型、Lint、格式检查和构建通过。
尚未覆盖其他浏览器/WebView、峰值内存、全部维护与删除入口，以及方案中明确列为
未实现的会话代次协议和楼层台账快照标识。
