# STR-MEMORY

SillyTavern 长对话记忆插件的源码仓库：在对话文件之外维护可修订的「记忆表格」，
供角色卡与提示词预设通过宏注入当前认知，并支持手动编辑、Agent 填表、问答与
本地备份/镜像恢复。记忆在线读写运行在 SQLite WASM Worker 的内存数据库中；
默认从对话文件加载完整记忆快照，每次提交后立即尝试写回原对话文件。
IndexedDB 保留本地快照缓存、任务与向量数据，不依赖额外数据库服务。

## Prerequisites

- [mise](https://mise.jdx.dev/)

项目通过 [`mise.toml`](./mise.toml) 固定 Node.js 与 pnpm 版本，不使用 Corepack。

## 开始

```bash
mise install
pnpm install
```

## 开发命令

```bash
pnpm watch        # esbuild watch 增量构建；配了 .env 就同步到 ST，Junction 模式自动跳过拷贝
pnpm build        # dist/：index.js / sqlite-worker.js / sqlite3.wasm / manifest.json / style.css
pnpm st:link      # 把 ST 扩展目录做成指向 dist/ 的链接（开发直连，见下）
pnpm st:unlink    # 解除该链接（只删链接，不动 dist）
pnpm typecheck    # tsc -p tsconfig.json
pnpm lint         # eslint .
pnpm format:check # prettier --check .
pnpm test         # vitest run
pnpm preview:frontend # 新前端独立预览，默认 http://127.0.0.1:18825/
```

当前构建入口为 `src/frontend/index.ts`，采用移动端优先的记录列表 → 详情 → 编辑流程；
桌面沿用同一套交互。旧入口、面板、页面和样式已移除，共用模型位于 `src/frontend/models/`，
`style.css` 仅包含新前端的 Tailwind / shadcn 样式。记录、表格、任务、Agent 和设置共用导航，
窄屏显示在底部，桌面显示在左侧，按钮按原尺寸从顶部排列。桌面窗口可拖动页头移动、拖动四边或四角缩放，
双击页头还原；关闭重开保留本次页面内的位置和大小。页头获得焦点后也可用方向键移动、Shift 加方向键缩放、Home 还原。
表格页支持表与字段管理、显示策略和向量配置；任务页支持填表提交、队列与历史、向量任务操作。
设置页支持连接、Embedding、重排、自动填表、预设、清洗与宏的编辑；
Agent 从主导航直接进入；向量搜索、运行日志、备份与空间维护、SQL 控制台从设置的工具区进入。
表格列表、详情和编辑分别管理滚动位置，进入子页从顶部开始，返回列表或详情恢复之前的位置。
记录编辑按对话身份和记忆空间保留内存草稿，切换对话后返回可继续编辑；刷新页面前会提示未保存修改。
保存沿用现有记录服务、修订冲突校验和对话文件写回，不另建数据存储。
架构边界、公共组件复用、移动端交互与 ST 样式隔离见 [前端开发规范](./docs/ui/frontend-development.md)；
预览与页面验收命令见 [新前端说明](./docs/ui/frontend-preview.md)。

真实 SillyTavern 验收脚本在 [`docs/playwright-st-extension`](./docs/playwright-st-extension)，
通过 `window.__STE_MEMORY_RUNTIME__`（调试入口）驱动面板与数据流。

## 记录排序

记录页支持「列表 / 表格」切换，默认使用列表。表格按字段顺序展示当前页记录，
单元格最多预览三行，表头与行号固定，横纵滚动限制在表格区域内。
视图切换使用表格选择旁的图标，表格右侧固定铅笔编辑列，单元格 hover 与点击区域填满整格。
点击单元格、行号或行尾「编辑」直接进入现有记录编辑页；列表仍先进入详情。
返回时恢复视图、搜索、排序、页码、横纵滚动位置与点击位置的焦点；
视图选择按对话与记忆空间保留到本次工作台生命周期结束，刷新后恢复默认列表。

记录页默认按创建时间升序排列，同一时间按记录 ID 升序保持稳定顺序。
搜索框旁的排序按钮可选择创建时间、更新时间或当前表的可排序字段；
再次点击当前选项切换升降序，箭头表示当前方向。记录列表和搜索结果共用排序，
先排序再分页，切换排序回到第一页。空值始终置后；列表、多选和引用字段不提供排序。
排序偏好按记忆空间和表格保存在当前浏览器，刷新后恢复；字段删除或改为不可排序类型后恢复默认。
同批 Agent 记录可能共享创建时间，此时 ID 顺序不表示剧情先后。

表格详情与向量编辑页提供「逐记录预览」：分页查找记录后查看各分组最终输入、字符数和配置错误。
编辑页按未保存草稿生成预览，返回后保留草稿和滚动位置；预览不保存配置、不提交索引任务，也不请求 Embedding。
修改连接或输入字符上限后返回预览、关闭后重开工作台，都会重新计算当前记录的状态。

## 聊天 API 连接

在设置的「Agent 连接」中为后台填表 Agent、记忆助手 选择独立连接。每个连接可配置
自己的请求头，支持键值行新增、删除和值隐藏；「测试连接」使用当前编辑草稿，模型列表
和实际生成共用请求头。修改地址、API Key 或请求头后，旧测试结果与模型列表清空。

API Key 默认生成 Bearer 鉴权，自定义 `Authorization` 可覆盖它；无 Key 且未配置
Authorization 时发送空鉴权值。`Content-Type` 固定为 `application/json`。请求头名称
不区分大小写，不允许重复，值允许为空但不能包含换行。API Key 和请求头值明文保存在
插件设置中；请求通过 ST 服务端的 Custom 代理转发。任务开始后沿用连接快照。

手动填表和初始化填表遇到临时 API 错误时，默认额外重试 2 次，分别等待 10 秒、20 秒；
自动填表使用其配置的重试次数和首次等待时间，后续等待翻倍。每轮模型请求独立计算次数，
成功工具及批次不会重放；失败尝试的部分输出保留在日志中，重试上下文跳过这些内容。
任务面板显示错误原因和重试倒计时，等待可取消，并计入当前批次的 Agent 总超时。
鉴权、额度等确定性错误直接结束；耗尽重试后回滚当前批次并暂停队列。记忆助手保持交互请求行为。

自动填表支持「延迟填写楼层数」，默认 1，允许为 0。以最新完成的 AI 楼层下标减去延迟层数作为可填终点，
用户和 AI 消息均计数；符合条件的待填楼层达到触发间隔后才入队，仅提醒也沿用此范围。
全局与当前对话覆盖均支持；对话留空继承全局。旧版包含当前 AI 楼层转换为延迟 0 层，不包含转换为 1 层。
修改配置只影响后续入队范围，已入队任务及已写入记忆保留；手动填表仍可自由选择楼层。

自动填表可开启「成功后自动隐藏楼层」，默认关闭，默认保留最近 10 层；全局设置与当前对话覆盖共用此配置。
整次自动楼层填表成功并保存后，调用 ST 原生 hide，隐藏从 #0 到
`min(当前楼层 − 保留最近楼层数, 台账中最大已填楼层)` 的闭区间。
当前楼层取执行时聊天最后一条消息的下标，用户和 AI 消息均计数；保留数允许为 0，终点小于 0 时跳过。
台账仅取 processed 状态的最大楼层，沿用现有填表进度语义，不检查更早的空洞。
手动填表、初始化、失败和取消均不触发；失败任务重试成功后可触发。
隐藏失败单独提示并保留填表成功结果。关闭开关只停止后续隐藏，已隐藏内容可用 ST unhide 恢复。

## Agent 会话

主导航提供统一的「Agent」，支持记录查询、普通 SQL 和语义 SQL，以及准备记录增删改。
每个 ST 对话和记忆空间可新建多个会话，支持切换、重命名和删除；各会话的历史、输入草稿、工具上下文与未提交提案独立保存。
会话在当前浏览器 IndexedDB 中持久保存，刷新后恢复，不进入聊天文件镜像或备份，也不跨设备同步。
切换会话时回答继续，删除正在回答的会话会中止请求；刷新会把在途请求标为已中断，后续可以继续交流。

修改先准备为提案，界面展示实际字段差异，点击「确认提交」后才写入记忆；聊天中的同意不会自动提交。
确认绑定具体提案版本，继续交流后需查看更新后的提案再确认；提交时沿用领域校验及记录修订冲突检查。
提交失败保留草稿，提交成功清空当前提案；快照写回失败会明确提示已提交，避免重复写入。
提交过程中刷新会提示核对结果，需放弃旧提案后再准备新的修改。

## 清洗规则

在设置中建立命名的清洗规则，为当前对话选择一份后应用于填表输入中的 AI 输出消息。
用户消息、系统消息和初始化文本保持原文；原始消息和证据也始终保留原文。
每份规则直接配置排除和保留标签对，两组内为 OR；固定先排除后保留，没有子规则或执行排序。
排除会从原文删除标签及内部内容，再从剩余文本提取保留标签内的内容并剥去边界，
多个非空片段按原文顺序用换行连接。保留组为空时使用排除后的全文，有配置但未命中时输出空文本。
标签按普通文本区分大小写匹配，支持跨行；缺少结束标签不匹配，不支持同名嵌套。
清洗测试支持手动输入、载入当前对话及未保存草稿；原始消息和证据始终保留原文。

清洗配置 schema 为 v3：升级后直接清空旧版规则列表，旧对话选择在打开时清除。
需要重新创建并选择规则；其他插件设置不受影响。

## 向量索引

在设置中保存独立的 OpenAI 兼容 embedding 连接，然后从表格的「向量索引」配置字段分组。
配置来源支持自动、预设和自定义；更新方式单独选择手动或自动。自动配置将启用字段合成一组，
每条记录的每个分组生成一个向量。分组有独立的可编辑 Key，同表内唯一；预设复制 Key，空间生成新 ID。表格预设保存当前分组快照，空间备份保留配置来源，均不导出向量或连接密钥。

任务页可按空间、表、状态、来源筛选向量任务，并逐项或勾选取消。队列优先手动任务，
同来源中优先当前对话；每次请求结束后重新排序。向量可补建、强制重算或单独清除，不改变记忆正文。

连接由浏览器直接请求服务的 `/embeddings` 接口，服务需允许当前 ST 站点跨域访问。
输入字符上限是本地限制，模型的 token 限制仍由服务校验；接口格式见
[embedding API 文档](https://developers.openai.com/api/reference/resources/embeddings/methods/create)。
设置工具区的「向量搜索」按当前对话绑定空间选择表和分组，默认 Top K 为 10（可调 1–50），最低分默认关闭。
每次提交只为查询原文请求一次 embedding，在本地按余弦相似度排序，同一记录取最高组分并去重。
只搜索已有有效索引，不等待或触发补建；缺失、过期、异常及空输入目标会单独显示，部分索引仍可搜索。
查询与索引请求独立并发、分别取消和处理错误；查询失败不改变索引任务状态。

结果展示实际参数、检查时点、索引覆盖、各阶段耗时、命中组和输入来源，可打开原记录查看证据与修订。
查询、选区和结果只存在页面内，切对话或刷新清空；正文、结构、profile 或所选索引删除后标为过期，
纯向量新增与同指纹替换保留当前快照并提示重新搜索。手动搜索不注入提示词；表达式宏通过独立批次读取索引。
查询长度上限为连接限制与 4000 字符中的较小值，超长需自行缩短，分数仅表示相似程度。
端点、模型及维度变化需重建；换密钥无需重建。同名远端模型更换权重无法自动识别，需强制重算。

可在设置的「重排连接」配置独立的 Cohere 兼容 rerank 服务。语义 SQL 与宏 Query 默认跟随全局开关，
SQL 可用第四参数 `'{"rerank":false}'` 单次关闭，`candidateLimit` 控制向量前 K 条重排候选。
`score` 保持余弦含义；使用 `WHERE s.rank IS NOT NULL ORDER BY s.rank` 跟随当前排序，再由 SQL `LIMIT` 决定最终数量。
业务范围通过 `scopeRecordIds` 在候选截取前限定，重排文本默认使用所选组字段，可由 `textFields` 覆盖。
实际生成中的宏完成重排后再渲染注入；手动向量检索页保持原有向量排序。详见[共享语义 SQL](./docs/semantic-sql.md)。

## SQL 控制台

设置工具区分别提供「向量搜索」和「SQL 控制台」。SQL 页可浏览实际表结构、插入名称与示例，
用 Ctrl / ⌘ + Enter 执行 SQL，并查看多个结果集、列信息、变更行数与耗时，支持复制 JSON。
允许 DDL、DML、PRAGMA、事务与多语句，不限制行数或执行时间。它直接操作当前空间的运行库，
不自动保存快照；修改不保证保留，直接改业务表也不生成修订或证据。Agent 的 SQL 权限保持只读。
同一个编辑器可以直接调用 `semantic_scores`，无需切换模式；右侧向量组可生成示例。
记忆助手 也通过同一个 `query_sql` 工具执行普通与语义查询，在 SQL 中填写查询文本即可。
手动查询需在 SQL 中填写查询文本，不自动读取对话消息。
SQLite 按语句识别语义依赖，自动准备评分后执行该查询，再继续后续语句；已经执行的普通写入不会重跑。
含语义依赖的语句仅允许只读查询，每条最多返回 10000 行、总等待 10 秒；结果展示索引覆盖与缓存命中。
普通 SQL 的 DDL、DML、PRAGMA、事务及多语句能力保持原样，支持取消语义准备。
详见 [手动 SQL 控制台决策](./docs/adr/st/0020-manual-sql-console.md)与[共享语义 SQL](./docs/semantic-sql.md)。

## 表达式宏

在设置的「记忆宏」中创建对话宏或全局宏，默认编辑 Query JSON，也可使用 SQL。
对话宏随当前绑定记忆空间保存，表格预设可自带宏；同名优先级为对话、全局、内置，
停用的高优先级宏仍遮蔽低层定义。用 `{{ste::宏名}}` 自行放入角色卡、提示词预设或世界书内容。

Query 的条件、fields、orderBy 和 limit 决定最终结果；增加 semantic 后可使用
`$similarity` 筛选、投影及排序。SQL 直接 JOIN `semantic_scores(表Key, 组Key的JSON数组, 查询文本)`，
由 SELECT、WHERE、ORDER BY 和 LIMIT 完整决定返回内容。评分源不提前取 Top K，
支持空评分源的 LEFT JOIN，也支持聚合和跨表查询。

宏在真实生成时统一计算，保存配置、编辑记录和切对话不预先查询。重生成与续写重新计算，
同次生成和群聊批次共享结果；同批相同文本与连接配置共用一次查询向量。
成功查询向量保留 5 分钟短期缓存，宏、记忆助手 和控制台语义查询共享缓存，记录评分和 SQL 输出仍按新快照计算。
测试按钮独立执行，最近结果只读；界面展示实际表达式、来源覆盖、耗时、输出和错误，可跳过未完成计算。
新副本中的语义宏默认停用，启用后每次适用生成都会计算，即使提示词中没有放置它。

旧自动召回整块移除，`{{memoryRecall}}` 不再注册；原引用需自行换成表达式宏。
手动向量检索、SQL 控制台与索引功能保留。详见 [表达式宏说明](./docs/memory-views.md)。

## ST 安装与同步

开发用两种方式，二选一。

### 方式一：Junction 直连（推荐）

```bash
pnpm build     # 先产出一份 dist/
pnpm st:link   # 把 ST 扩展目录链接到 dist/（Windows Junction，无需管理员）
```

之后 `pnpm watch`（或 `pnpm build`）产出的文件 ST 直接可见，**不再拷贝**：

- 链接目标必须是构建产物 `dist/`，不是 TS 源码——ST 只加载 `index.js` /
  `manifest.json` / `style.css`，TS 必须先经 esbuild 打包；
- 改动生效仍需刷新 ST 页面（扩展以 module script 加载，无 HMR）；
- `pnpm st:unlink` 解除链接（只删链接，dist 内容不受影响）；目标已存在真实目录
  时会拒绝建立/删除，不会动用户数据。

### 方式二：拷贝

`pnpm sync` / `pnpm deploy:st` 会把 `dist/` 拷进 SillyTavern 的
`public/scripts/extensions/third-party/ste-memory`（**会写入 ST 安装目录**）。
目标位置从仓库根 `.env` 读取，二选一（参考 [`.env.example`](./.env.example)）：

- `STE_ST_EXTENSION_DIR`：直接指向扩展目标目录；
- `STE_ST_INSTALL`：SillyTavern 安装根目录，自动推导扩展子路径。

`pnpm watch` 不配 `.env` 时只构建到 `dist/`（配合方式一的 Junction 正好）；
配置了但目标已是 dist 链接时，同一步骤会自动跳过拷贝。

## 发布

`pnpm release:st` 重新生成 `release/sillytavern-plugin` 分支（构建产物分支，
SillyTavern 通过该分支安装/更新）。默认只更新本地分支，`--push` 才推送远端。

```text
├── features/                              # 业务功能（直接函数/服务调用，无事件总线）
│   ├── memory/                            # 共享记忆模型与写入规则（唯一来源）+ 公开入口
│   ├── agent/                             # 提案/记忆助手 运行与工具
│   ├── fill-tasks/  query-chat/  macros/  # 填表任务、问答面板、宏
│   ├── table-presets/                     # 表格预设：预设库、实例化、应用（原子重建）
│   ├── backup/  chat-mirror/              # 备份文件格式、镜像格式与导出辅助
│   └── settings/ cleaning/ chat-binding/ space-maintenance/ logging/ agent-presets/
├── infrastructure/                        # 具体实现：IndexedDB（Dexie）、SillyTavern 适配器、浏览器
├── ui/                                    # 面板 React 组件与纯逻辑模型（shell/memory/tasks/…）
└── common/                                # 跨功能的小工具（定时器端口、轮询骨架）
```

约束：

- 其他功能与 UI 只能通过 `src/features/memory/index.ts` 使用 Memory（领域类型、
  完整操作与持久化接口都在入口导出）；内部步骤（校验、修订、历史写入、显示文本
  计算）不对外暴露。
- 功能层不依赖 `infrastructure/` 与 `ui/`；具体实现由 `runtime.ts` 装配注入。
- `tests/architecture/` 与 ESLint `no-restricted-imports` 同时强制以上方向。
- 填表与问答通过记录服务的 `commitProposal` 提交，仓库、ID、时钟和显示计算由
  Memory 内部管理；填表任务每个批次独立使用 SQLite 事务，批内工具即时写入并返回
  真实记录 ID。每批成功后保存文件和 IndexedDB 台账；失败或取消仅回滚当前批次。
  普通读取只看已提交快照，后续批次可读取之前批次的成果。
- 记忆结构、记录、历史与证据的旧 IndexedDB 表仅保存序列化快照缓存；差量更新缓存
  不清除向量。任务、台账、向量和独立日志继续使用 IndexedDB。
- SQLite 资源随包发布；结构化记忆查询与表达式宏 Query 编译为参数化 SQL。
  Agent 另有只读 `query_sql`，支持 AND/OR、括号、JOIN、聚合与子查询，写入仍经业务工具。
  真实 ST 的 Edge 浏览器已完成 Worker/WASM、保存、事务与备份导入验收，
  结果见 [浏览器验收记录](./docs/sqlite-browser-e2e.md)；其他 WebView 仍待验证。
  实施状态见 [SQLite 迁移方案](./docs/sqlite-migration-plan.md)。
- 设置保存后的宏注册、镜像与聊天同步由 `SettingsService` 负责；设置页和表格页只接收
  实际使用的服务，UI 负责草稿与错误展示。
- 首次创建对话与设置页「应用预设」共用 `features/table-presets` 的实例化与原子重建路径。
  「从预设更新空间」另按表、字段与向量分组 Key 展示树形差异，勾选新增、更新或删除；
  匹配对象保留 ID，字段类型保持原值，最终结构与引用统一校验后通过 SQLite 事务发布。
  初始化来源、未删除的记录、任务历史与同步进度保留；提交后的文件保存或索引处理失败可单独重试。
